# 每日复盘 Harness 编排层 V1.4.0

> **核心理念：Agent = Model + Harness。把"厨房"和"菜"分开。**

## 三种执行模式

### 早盘模式（盘前 8:00-9:15）

触发：用户说"执行早盘分析"或"早盘报告"

**流程：**
1. 读取 `harness/staging/今日-早盘分析.md`（完整可执行 prompt，由昨日复盘已填充日期特定内容）
2. 调用 `a-stock-data` 按四步并行取数（隔夜外盘 → 板块催化 → 资金面 → 事件日历）
3. 执行宏观研判 → 非持仓板块七维评分（第五节）→ 持仓板块评分+做T建议（第六节）→ 操作清单
4. 产出 `reports/{today}/早盘报告.md`
5. **生成每日信号**：从持仓映射分析和操作清单中提取结构化信号，按 `harness/prompts/早盘分析-模板.md` 第九节每日信号生成的规则，输出 `reports/{today}/每日信号.md`
   - 信号必须可量化、可验证、有时效
   - P0信号 ≤ 3条（风险控制信号精而不多）
   - 总信号 5-10 条
   - 信号总表按"优先级→标的→触发条件"排序（重要信息前置），信号ID在末尾便于盘中追加
6. 若执行交易操作，更新 `harness/config/持仓.md`

### 盘中模式（交易时段 9:30-15:00）

触发：用户说"执行盘中分析""盘中检查""午盘检查""intraday"

> 盘中分析**无需 staging**——市场状态随时变化，执行时直接读取永久模板 `harness/prompts/盘中分析-模板.md`，配合实时数据运行。可在交易时段内多次执行。

**流程：**
1. 读取 `harness/prompts/盘中分析-模板.md`（永久模板，无需预填充）
2. 调用 `a-stock-data` 按三步并行取数（大盘快照 → 板块扫描 → 资金面）
3. **验证早盘信号触发条件**：读取 `reports/{today}/每日信号.md`，逐条检查"待执行"信号的触发条件是否满足
   - 有效时段内+条件满足 → 更新状态为"已触发"
   - 有效时段已过+未触发 → 更新状态为"已过期"
   - 已执行/已过期信号 → 跳过，不修改
4. **盘中追加信号生成**（三级阈值）：扫描当前市场是否有早盘未覆盖的新机会
   - Tier 1（强信号→P1）：北向剧烈逆转、板块级涨停潮、持仓触及止损/止盈位、突发重大催化、V反三信号齐备
   - Tier 2（观察信号→P2）：需 ≥3/5 条件满足（板块跃升+量比异常+资金流入+新催化+联动走势）
   - Tier 3（默认）：明确声明"当前无新增信号机会"
5. **原地更新 `每日信号.md`**：修改信号状态 + 追加盘中验证记录 + 追加盘中信号
6. **输出聊天摘要**：信号变更汇总 + 市场快照 + 新信号/无新信号

**关键约束：**
- 仅修改"待执行"状态信号；已执行/已过期/已取消不触碰
- 多次执行累计单调更新，追加验证记录不覆盖
- 无新机会时强制输出"当前无新增信号机会"
- 非交易时段执行时警告并重定向

### 复盘模式（收盘后）

触发：用户说"执行复盘分析"或"收盘复盘"

**流程：**
1. 读取 `harness/staging/今日-复盘分析.md`（完整可执行 prompt）
2. 调用 `a-stock-data` 获取收盘数据
3. 大市表现复盘 → 逐只持仓复盘 → 早盘预判逐条对比
4. 产出 `reports/{today}/复盘报告.md`
5. **信号执行复盘**：读取 `reports/{today}/每日信号.md`，逐条评价决策质量和执行质量，更新信号评价表。盘中验证记录和追加信号一并纳入评价
6. **报告审阅**：参照 `harness/experience/报告审阅经验.md` 进行 2-3 轮审阅
7. **经验沉淀**（见下文协议）
8. **生成次日 staging prompts**（见下文协议）
9. **归档当日 staging** → `harness/archive/{today}/`
10. **自动同步持仓配置**：读取 `每日调仓.md` "当前持仓"表 → 覆写 `harness/config/持仓.md`。比对上一日持仓，在复盘报告中列出变更

## Generator-Monitor-Evaluator 分离（核心 Harness 模式）

这是本 Harness 最重要的质量机制——将完整的交易日生命周期分为三个角色，严格分离：

- **早盘分析 = Generator（生成者）**：产生预测、操作建议、交易信号
- **盘中分析 = Monitor（监控者）**：验证信号触发条件、发现盘中新机会、实时更新信号状态
- **复盘分析 = Evaluator（评估者）**：逐条对比预测 vs 实际，对失误归因，评价信号决策质量和执行质量
- **关键纪律**：同一 Agent 不能既写早盘报告又评估早盘报告。复盘时必须带着"找茬"心态审视早盘预判，而非"自圆其说"。盘中分析是中立的——不修正早盘预判（那是复盘的任务），只验证触发条件和发现新机会。

复盘时检查：
- 早盘预测中哪些对了？是蒙对的还是逻辑正确？
- 哪些错了？根因是数据缺失、框架缺陷还是认知偏差？
- 操作建议的触发条件是否合理？是否过于宽松/严格？
- 盘中验证记录的触发判断是否准确？
- 盘中追加信号的决策质量和执行质量如何？

复盘时新增检查（板块机会+做T）：
- 非持仓板块扫描：预判的 3-5 个非持仓板块中，有几个实际走出行情？入场时机判断准确率如何？
- 做T建议：每只标的的做T方向预判 vs 实际日内走势，方向正确率统计
- 做T预估胜率 vs 实际胜率：是否存在系统性偏差（如一贯高估正T胜率）？
- 遗漏检测：今日表现最好的板块中，哪些在早盘的非持仓扫描中被遗漏？为什么？

复盘时新增检查（每日信号）：
- **每日信号 = 可验证承诺**：早盘发出的每条信号都是一个可验证的"承诺"——触发条件是否合理？执行后盈亏如何？复盘时必须逐条对账，不能选择性遗忘未执行的信号。
- P0信号执行率：必须100%——如果有P0未执行，复盘重点检讨原因
- 信号决策质量：信号方向是否正确？触发条件设计是否精准？
- 信号执行偏差：哪些信号用户应该执行但未执行？为什么？
- **盘中追加信号质量**：盘中追加的信号是否真的有价值？是否存在"为了有输出而输出"的信号？

## 经验更新协议

### 写入时机
- 复盘中发现可复用的市场规律 → 追加到 `harness/experience/投资经验.md`
- 复盘中发现做T/短线技巧 → 追加到 `harness/experience/短线机会经验.md`
- 复盘中发现板块扫描方法论 → 追加到 `harness/experience/投资经验.md` 的"板块机会扫描"相关章节
- 复盘中发现做T胜率校准经验 → 追加到 `harness/experience/短线机会经验.md` 的"做T胜率校准"相关章节
- 复盘中发现信号设计/执行偏差的经验 → 追加到 `harness/experience/投资经验.md` 的"信号设计"相关章节
- 复盘中发现盘中信号生成质量偏差的经验 → 追加到 `harness/experience/投资经验.md` 的"信号设计"相关章节

### 写入规则
1. **无日期标签**：经验不带日期标记，只写规律本身
2. **与原有经验融合**：新经验合并入已有条目，不重复记录
3. **冲突处理**：若新经验与旧经验逻辑冲突 → 说明原经验需要修正（不是简单追加，而是改写修正）
4. **简洁优先**：每条经验 3-5 句话，去掉冗余
5. **可操作**：每条经验应能直接指导交易决策，而非抽象哲理

### 示例
```
好：外部冲击（熔断级）>内部催化。日韩SIDECAR级别事件会覆盖A股内部所有利好利空。
差：今天日韩跌了很多导致A股也跌，以后要注意外部风险。
```

## Staging Prompt 生成协议（复盘任务 6）

这是 Harness 层的核心产出——用今日复盘结果生成次日完整可执行 prompt。

### 输入
- 模板框架：`harness/prompts/早盘分析-模板.md`、`harness/prompts/复盘分析-模板.md`
- 当前持仓：`harness/config/持仓.md`
- 今日数据：`reports/{today}/复盘报告.md` + `reports/{today}/早盘报告.md` + `reports/{today}/每日信号.md`
- 近期经验：`harness/experience/投资经验.md`、`harness/experience/短线机会经验.md`
- 次日事件：通过 `a-stock-data` + WebSearch 研究

### 输出
- `harness/staging/今日-早盘分析.md`（次日早盘完整 prompt）
- `harness/staging/今日-复盘分析.md`（次日复盘完整 prompt）

### 早盘 staging 必须包含
1. 当日持仓表（从 config/持仓.md 填入，含代码+数量+成本价）
2. 次日事件日历（具体事件+时间+影响标的）
3. 今日核心矛盾分析（根据复盘结果提炼多空矛盾）
4. **非持仓板块机会扫描行**（根据模板第五节七维评分表，从当日市场数据中挑选 3-5 个有潜力的非持仓板块，含入场时机和预估胜率）
5. **逐只持仓板块评分行**（根据模板 6.1 节七维评分表，含持仓建议）
6. **逐只持仓做T建议行**（根据模板 6.2 节，含做T方向、触发条件、T仓位、预估胜率、适用纪律）
7. **做T纪律规则勾选**（根据模板 6.3 节，勾选当日适用的纪律规则，可补充当日特有约束）
8. 操作清单（优先级+触发条件+时段+仓位）
9. **每日信号生成指令**（根据模板第九节，提示早盘执行时产出 `每日信号.md`）
10. 核心关注时间表
11. 跨品种约束检查
12. **上期预判回顾**（今日预判 vs 今日实际，含纠偏）
13. **上期信号回顾**（从上期 `每日信号.md` 提取关键信号的决策质量和核心教训）

### 复盘 staging 必须包含
1. 当日持仓表+今日操作列
2. 特别关注项（根据今日市场核心变量）
3. **非持仓板块扫描验证区域**（模板 3b 节：预留板块预判 vs 实际对比表）
4. **做T验证区域**（模板 2b+3c 节：预留做T预判 vs 实际对比表）
5. **信号执行复盘区域**（模板 2c 节：预留信号评价表 + 盘中验证记录复盘 + 盘中追加信号评价）
6. 上交易日核心回顾（今日的核心特征+核心教训+次日核心变量）

### 关键要求
- Staging prompt 必须是**完整可执行的**，不含 `[占位符]`
- 执行时直接读 staging 即可，无需再查模板
- 路径全部使用新 harness 结构（`harness/experience/`、`reports/` 等）

### 自动化与手动的切换

- 自动化执行时，手动触发（用户说"执行早盘分析"等）仍然有效
- task_state.json 的幂等检查防止重复执行
- 如果自动化未执行（如 Claude Code 未运行），手动触发不受影响
- 自动化复盘生成的 staging 与手动复盘完全相同
