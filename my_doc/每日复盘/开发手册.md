## 1. 项目概览

每日复盘系统是一个基于 **Harness Engineering** 架构的 A 股每日市场分析 + 复盘 + 经验沉淀工具。

**核心架构：厨房与菜分离**

```
my_doc/每日复盘/
├── harness/                          # "厨房" — 模板/经验/配置/工具
│   ├── prompts/                      #   永久模板（不含日期特定内容）
│   │   ├── 早盘分析-模板.md           #     早盘分析框架
│   │   ├── 盘中分析-模板.md           #     盘中监控框架
│   │   └── 复盘分析-模板.md           #     收盘复盘框架
│   ├── experience/                   #   经验沉淀（复盘后追加，持续积累）
│   │   ├── 投资经验.md                #     市场判断/跨市映射/超跌反弹/信号设计
│   │   ├── 短线机会经验.md            #     做T/跷跷板/事件套利纪律
│   │   └── 报告审阅经验.md            #     质量审阅清单
│   ├── config/                       #   日度配置
│   │   └── 持仓.md                    #     当前持仓快照（复盘自动同步）
│   ├── staging/                      #   当日可执行 Prompt（每日覆盖，仅2个文件）
│   │   ├── 今日-早盘分析.md           #     次日早盘的完整指令
│   │   └── 今日-复盘分析.md           #     当日复盘的完整指令
│   ├── archive/                      #   历史 Staging 归档
│   │   └── 20260721/                 #     按日期组织
│   └── automation/                   #   自动化编排层
│       ├── prompts/                  #     5个自动化执行 Prompt
│       ├── config/                   #     交易日历 + 跨任务状态
│       ├── steering/                 #     优化需求管理
│       └── logs/                     #     执行日志
├── reports/                          # "菜" — 每日报告产出（按日期组织）
│   └── 20260721/
│       ├── 早盘报告.md
│       ├── 复盘报告.md
│       └── 每日信号.md
└── 每日调仓.md                        # 调仓历史日志 + 当前持仓权威来源
```

**三大核心原则**：

1. **Generator-Evaluator 分离**：早盘生成预测，复盘逐条评估，不允许自产自评
2. **厨房与菜分离**：模板/经验/配置只在 `harness/` 中维护，`reports/` 只有报告产出
3. **经验持续积累**：每次复盘后追加经验，无日期标签，冲突时修正而非追加

**编排入口**：在 Claude Code 中说"执行早盘分析"或"执行复盘分析"，由 `daily-review-harness` skill 协调执行。

## 2. 快速上手：如何执行复盘

### 2.1 执行早盘分析

**触发方式**：在 Claude Code 中说：

```
执行早盘分析
```

**执行内容**（由 `daily-review-harness` skill 自动编排）：
1. 读取 `harness/staging/今日-早盘分析.md`（由上一日复盘自动生成）
2. 四路并行取数：隔夜外盘、A股板块催化、资金面、事件日历
3. 七维评分体系评估非持仓板块
4. 持仓映射与操作判断（加仓/持有/减仓/清仓）
5. 生成 P0/P1/P2 三级信号（含触发条件 + 有效时段 + 仓位）
6. 产出早盘报告到 `reports/{日期}/早盘报告.md`

### 2.2 执行盘中分析

**触发方式**：

```
执行盘中分析
```

可在盘中多次执行（10:30、13:30、14:45 是推荐时间点）。

**执行内容**：
1. 大盘快照 + 板块扫描 + 资金面
2. 逐条验证早盘信号是否触发
3. 扫描新增信号
4. 产出盘中更新

### 2.3 执行收盘复盘

**触发方式**：

```
执行复盘分析
```

**执行内容**：
1. 盘面复盘：各大指数、板块、资金面
2. 逐仓评估：每只持仓的操作回顾与评价
3. **Generator-Evaluator 核心**：逐条对比早盘预测 vs 实际表现，标记 8 类预测误差
4. 信号执行评级（S/A/B/C/D/F 六级）
5. 经验沉淀：写入 3 个经验文件
6. **生成次日 Staging**：产出下一个交易日的 `今日-早盘分析.md` 和 `今日-复盘分析.md`
7. 同步持仓配置：更新 `config/持仓.md`
8. 归档当日 Staging

### 2.4 直接手动查看 Staging

如果想自己手动分析（不使用 skill）：

```bash
# 查看次日早盘的完整指令
cat my_doc/每日复盘/harness/staging/今日-早盘分析.md

# 查看当日复盘的完整指令
cat my_doc/每日复盘/harness/staging/今日-复盘分析.md
```

### 2.5 查看历史报告

```bash
# 按日期浏览
ls my_doc/每日复盘/reports/20260721/
cat my_doc/每日复盘/reports/20260721/早盘报告.md
cat my_doc/每日复盘/reports/20260721/复盘报告.md
cat my_doc/每日复盘/reports/20260721/每日信号.md
```

## 3. 自动化迭代：如何让项目自动运转

每日复盘系统配置了 7 个定时任务，覆盖从早盘到周度的完整周期。

### 3.1 当前定时任务一览

| 任务 | 频率 | Prompt | 用途 |
|------|------|--------|------|
| 早盘分析 | 交易日 07:07 | `auto_morning_analysis.md` | 取数→研判→信号→产出早盘报告 |
| 盘中检查#1 | 交易日 10:37 | `auto_intraday_check.md` | 验证早盘信号触发→扫描新信号 |
| 盘中检查#2 | 交易日 13:37 | `auto_intraday_check.md` | 午盘更新 |
| 收盘前检查 | 交易日 14:52 | `auto_intraday_check.md` | 尾盘扫描 |
| 收盘复盘 | 交易日 15:52 | `auto_evening_review.md` | 复盘→预测对比→经验沉淀→次日Staging |
| 周度回顾 | 周六 10:07 | `auto_weekly_portfolio.md` | 周P&L+预测准确率+量化vs实际 |
| 经验健康 | 周日 09:07 | `auto_experience_health.md` | 大小/重复/矛盾/过时检测 |

### 3.2 注册/刷新定时任务

每次启动 Claude Code 时，`SessionStart` hook 会提示你执行注册。输入：

```
执行 .claude/prompts/setup_automation_cron.md
```

这会注册所有 12 个定时任务（含 7 个每日复盘 + 5 个 ETF 策略）。

### 3.3 查看当前定时任务

在 Claude Code 中说：

```
列出所有 cron 任务
```

### 3.4 自动化工作流全景

```
交易日流程:
  07:07  auto_morning_analysis  →  早盘报告 + 每日信号
  10:37  auto_intraday_check    →  盘中更新 + 信号验证
  13:37  auto_intraday_check    →  午盘更新
  14:52  auto_intraday_check    →  尾盘扫描
  15:52  auto_evening_review    →  复盘报告 + 经验沉淀 + 次日Staging

周末流程:
  周六 10:07  auto_weekly_portfolio   →  周度P&L + 预测准确率 + 量化vs实际
  周日 09:07  auto_experience_health  →  经验库健康检查 + 自动维护
```

**流水线协调**：`harness/automation/config/task_state.json` 是跨任务协调中枢：
- 确保**幂等**：同一天重复触发自动退出
- **流水线感知**：早盘→盘中→复盘共享状态，复盘检查早盘是否完成
- **失败透明**：连续失败超阈值时告警

### 3.5 交易日历

**文件**：`my_doc/每日复盘/harness/automation/config/trading_calendar.py`

包含 2026 年节假日/调休/交易周末。所有自动化任务执行前检查是否为交易日。

```bash
# 检查今天是否交易日
python my_doc/每日复盘/harness/automation/config/trading_calendar.py --status

# 检查当前是否交易时段
python my_doc/每日复盘/harness/automation/config/trading_calendar.py --market-open
```

### 3.6 查看自动化执行日志

```bash
ls my_doc/每日复盘/harness/automation/logs/
```

日志文件按日期命名，记录每次自动化任务的执行状态。

## 4. 需求与建议：如何提

### 4.1 提优化需求（Steering 系统）

**适用场景**：
- 希望早盘分析增加新的数据源（如港股通资金流）
- 希望复盘增加新的评估维度
- 希望优化经验库管理策略
- 希望盘中检查增加新的信号类型
- 任何对自动化分析/复盘流程的改进建议

**步骤**：

1. 在 `my_doc/每日复盘/harness/automation/steering/open/` 下创建需求：

```bash
cp my_doc/每日复盘/harness/automation/steering/REQ_TEMPLATE.md \
   my_doc/每日复盘/harness/automation/steering/open/REQ-001.md
```

2. 填写需求模板：

```markdown
# REQ-001: 早盘增加北向资金流分析

- **创建时间**: 2026-07-21 17:00
- **优先级**: P1(高)
- **影响范围**: 早盘分析
- **状态**: OPEN

## 需求描述
早盘分析中增加北向资金的行业分布和个股流向数据，
作为板块评分的加权因子。

## 期望结果
早盘评分体系新增"北向资金"维度，权重10%。
每日早盘报告增加北向资金流向摘要。

## 约束/注意事项
- 北向数据走东财接口，注意限流
- 仅交易日有效（北向资金仅在交易日有数据）
```

3. 在 `REQ_INDEX.md` 中登记。

4. 下次自动化任务执行时自动读取并纳入工作范围。

**状态流转**：
```
OPEN → IN_PROGRESS (自动化任务推进)
     → ADOPTED (你确认采纳)
     → REJECTED (你拒绝)
     → IMPLEMENTED (已实现)
```

### 4.2 报告 BUG 或问题

每日复盘项目没有独立的 BUG 跟踪系统。如果发现复盘报告中的问题：

1. **数据错误**（如价格/涨跌幅不准确）→ 检查 `a-stock-data` 数据源，或直接告诉 Claude
2. **逻辑错误**（如分析框架应用不当）→ 更新对应经验文件，或告诉 Claude 在下次复盘时注意
3. **Staging 生成错误**（如次日 prompt 中数据/逻辑错误）→ 手动修改 staging 文件，或重跑复盘

### 4.3 手动为特定复盘补充指令

如果你对即将执行的早盘/复盘有特殊要求（如"今天重点看半导体""港股异常关注一下"），不需要走 Steering 系统。直接修改 Staging 文件即可：

```bash
# 在次日早盘 staging 中追加你的关注点
echo "## 用户补充关注" >> my_doc/每日复盘/harness/staging/今日-早盘分析.md
echo "- 重点看半导体板块是否止跌" >> ...
```

Staging 文件会在下次复盘时被归档，不会被覆盖。

## 6. 经验管理：如何沉淀和查阅经验

### 6.1 经验文件说明

| 文件 | 内容 | 大小 |
|------|------|------|
| `投资经验.md` | 市场判断、跨市映射、超跌反弹、数据纪律、信号设计 | ~31KB |
| `短线机会经验.md` | 做T纪律、跷跷板套利、跨市场套利、事件套利 | ~10KB |
| `报告审阅经验.md` | 三轮审阅流程、16项数据校验、8项逻辑检查、8类常见错误 | ~7KB |

### 6.2 经验如何生成

每次收盘复盘执行时，自动从当日的分析判断中提取经验，追加到对应的经验文件。

**关键纪律**：
- 经验**不带日期标签** — 是持续积累的知识，不是日记
- 发现**冲突**时**修正**而非追加 — 新旧经验矛盾时，修正旧条目
- 经验文件有**大小上限** — `auto_experience_health.md` 每周日检查（300行警告，500行强制合并）

### 6.3 手动添加经验

直接在对应的经验文件中追加：

```markdown
## 新经验标题

{经验内容}
```

下次复盘时，Claude 会加载最新的经验文件作为分析框架。

### 6.4 查看经验健康报告

自动化任务在每周日 09:07 执行 `auto_experience_health.md`，检查：
- 大小控制（超阈值触发合并）
- 重复检测（相似度 >80%）
- 矛盾检测（文件内 + 跨文件）
- 过时检测（不再适用的经验）
- 章节完整性

查看执行日志：
```bash
cat my_doc/每日复盘/harness/automation/logs/experience_health_*.log
```

## 7. 调仓操作：如何更新持仓

### 7.1 调仓流程

1. **执行交易**：在实际券商账户中完成买卖
2. **更新调仓日志**：在 `每日调仓.md` 中记录：
   ```markdown
   | 2026-07-21 | 买入 | 512480 | 半导体ETF | 20000份 | 1.20 | 技术面止跌反弹 |
   ```
3. **更新当前持仓表**：修改 `每日调仓.md` 的"当前持仓"表
4. **下次复盘自动同步**：收盘复盘时会自动将 `每日调仓.md` 的持仓同步到 `config/持仓.md`

### 7.2 调仓记录格式

```markdown
## 当前持仓

| 代码 | 名称 | 持仓份额 | 成本价 | 当前价 | 盈亏% | 占比 |
|------|------|---------|--------|--------|-------|------|
| 159227 | 航空航天ETF | 50000 | 0.85 | 0.92 | +8.2% | 15% |

## 调仓记录

| 日期 | 操作 | 代码 | 名称 | 份额 | 价格 | 理由 |
|------|------|------|------|------|------|------|
| 2026-07-17 | 卖出 | 512010 | 医药ETF | 30000 | 0.72 | 止损 |
| 2026-07-17 | 买入 | 159227 | 航空航天ETF | 50000 | 0.85 | 突破平台 |
```

| 提优化需求 | `steering/open/` 下创建 `REQ-{NNN}.md` |
| 给下次复盘加特别关注 | 直接编辑 `staging/今日-复盘分析.md` |
| 想加一条经验 | 直接追加到对应经验文件 |
| 查看经验库 | `cat harness/experience/投资经验.md` |
| 今天是不是交易日 | `python trading_calendar.py --status` |
| 现在是不是交易时段 | `python trading_calendar.py --market-open` |
| 查看定时任务 | "列出所有 cron 任务" |
| 注册/刷新定时任务 | "执行 setup_automation_cron.md" |
| 查看持仓 | `cat harness/config/持仓.md` 或 `cat 每日调仓.md` |
| 查看执行状态 | `cat harness/automation/config/task_state.json` |
| 上次复盘有哪些预测错了 | 打开 `reports/{日期}/复盘报告.md` 的"早盘预测回顾"部分 |
| 检查经验库有没有冲突 | 等周日自动检查，或手动看 `auto_experience_health.md` |
| 复盘报告有错误 | 更新 `报告审阅经验.md` 对应的错误模式，下次复盘会自动检查 |
