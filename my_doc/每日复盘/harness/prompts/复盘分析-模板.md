### 执行口径备忘（不写入报告）

- 主策略为 **S4_多资产动量轮动**（ETF 为主，辅以每日信号驱动的短线操作）
- **涨跌幅（标准口径）**：`涨跌幅 = (今日收盘价 - 昨日收盘价) / 昨日收盘价 × 100%`（与券商软件/腾讯财经一致，复盘报告涨跌幅必须用此口径）
- **辅助指标**：开盘缺口 = (今开 - 昨收) / 昨收；日内波动 = (今收 - 今开) / 今开；涨跌幅 ≈ 开盘缺口 + 日内波动
- **数据验证（执行前必做）**：① 价格跳变检测：任一标的 `|今收/昨收 - 1| > 15%` → 排查份额调整（合并/拆分），确认除权后再比较（异常数据 → 运行提示 + BUG 工单，见任务 5.5）；② 数据源交叉验证：早盘与收盘数据优先同一数据源（腾讯财经），混用 mootdx/腾讯须交叉验证"昨收"；③ 昨收核对：收盘腾讯"昨收" ≠ 早盘"现价"参考基准时，标注数据源差异

### 1b. 全市场异动扫描（行业/题材版）

> 扫描全市场**行业板块 + 题材（概念）板块**（而非个股/ETF），找出日内振幅最大的 10 个板块（上涨 5 个 + 下跌 5 个），
> 结合资金面、题材热度、新闻分析原因，总结可复用经验。
>
> **为什么扫行业/题材而非 ETF（REQ-004，2026-08-31 复盘教训）**：ETF 扫描存在严重重复问题——2026-08-31 复盘下跌组振幅 TOP5 出现 4 只地产 ETF（159707/515060/159768/512200），同一主题占满名额，信息密度低。行业/题材板块是**主题的单一代表**（一个行业/概念 = 一个板块指数），天然去重，直接呈现"哪个主题在剧烈异动"，与早盘板块扫描（第五节）口径一致，映射更直接。
>
> **异动定义**：板块指数日内振幅 = (板块最高 - 板块最低) / 板块最低 × 100%。振幅越大=异动越剧烈。
> 注意区分日内波动 vs 开盘缺口：若板块因开盘跳空而振幅大，需说明缺口贡献占比。

**参考脚本（东财 clist，可直接抄用）**：

```python
import requests

def board_scan(fs: str = "m:90+t:2", pz: int = 200) -> list:
    """拉板块行情（东财 clist）。fs: m:90+t:2=行业 / m:90+t:3=概念。
    返回字段: 名称/代码/最新/涨跌幅/今开/最高/最低/昨收/成交额/上涨家数/下跌家数/领涨股。"""
    url = "https://push2.eastmoney.com/api/qt/clist/get"
    params = {
        "pn": "1", "pz": str(pz), "po": "1", "np": "1",
        "fltt": "2", "invt": "2", "fs": fs,
        # f2最新 f3涨跌幅 f4涨跌额 f6成交额 f12代码 f14名称 f15最高 f16最低 f17今开 f18昨收
        # f104上涨家数 f105下跌家数 f128领涨股 f136领涨股涨跌幅
        "fields": "f2,f3,f4,f6,f12,f14,f15,f16,f17,f18,f104,f105,f128,f136",
    }
    r = requests.get(url, params=params, headers={"User-Agent": "Mozilla/5.0"}, timeout=15)
    return r.json().get("data", {}).get("diff", []) or []
```

> **数据源纪律**：行业/概念板块数据用东财 push2（零鉴权、字段含板块指数 OHLC）；东财不可达才降级腾讯代理。东财接口走 `em_get` 限流（间隔 ≥1s）。

#### 1b.2 板块异动筛选

从行业（~100 个）+ 概念（~400 个）板块中按以下步骤筛选：

1. **排除非主题类概念**：排除无实际交易主题含义的板块（名称含"融资融券/沪股通/深股通/港股通/MSCI/标普道琼斯/富时罗素/转融券/两融/注册制/预盈预增/预亏预减/破净/高送转/次新股/股权激励/QFII/机构重仓/社保重仓/基金重仓/百元股/低价股/昨日涨停/昨日连板/昨日触板"等）
2. **流动性过滤**：排除成交额 < 100 亿的板块（板块级成交额远大于单 ETF，低流动性板块异动无参考意义）
3. **计算指标**：涨跌幅 = f3/100；振幅 = (f15 - f16) / f16；开盘缺口 = (f17 - f18) / f18（板块指数口径）
4. **类型标注**：行业 / 概念
5. **去重（关键，防"4 只地产 ETF"类重复）**：行业板块优先；若某概念板块与已入选行业板块主题重叠（名称含相同主题词，如"房地产"行业 vs "房地产概念"），**合并为一行**（类型列标注"行业(+概念)"，取振幅大者），不允许同一主题占多行
6. **分组排序**：按涨跌分组，上涨组按振幅从大到小取前5，下跌组同样取前5

#### 1b.3 原因分析

对筛选出的 10 个异动板块，逐个分析异动原因：

1. **主题归因**：该行业/题材当日表现的驱动（题材热度词频、政策/事件催化、外盘映射、龙头股异动）
2. **资金面归因**（如数据可获取）：
   - 对应板块主力资金净流入/流出情况
   - 板块内涨停/跌停家数（情绪面佐证，用领涨股 + 涨跌家数列交叉验证）
3. **联动归因**（板块特有）：
   - **行业 vs 概念一致性**：同一主题的行业与概念板块是否同步异动（如"房地产"行业与"房地产概念"同跌）= 主题级信号
   - **主题间传导**：异动板块是否提示持仓风险或机会（如贵金属领跌 → 持仓黄金 ETF 需警惕）
   - **龙头股验证**：领涨/领跌股是否为板块代表性标的（防止"指数失真"）

### 2. 持仓复盘

逐只审视今日持仓表现，**涨跌幅以文件头"执行口径备忘"的标准口径（vs 昨收）为准**，重点关注大涨或大跌的标的：

- **大涨**：判断是否需要锁定利润。结合技术面（均线、MACD、RSI、成交量等）给出 **减仓 / 持有 / 加仓** 的明确建议及理由；
- **大跌**：回溯盘前、盘中是否存在可识别的消息或信号，评估本次下跌是否可提前规避，并记录改进点。
- 每只标的列出三项数据：**涨跌幅（vs 昨收）、开盘缺口、日内波动**，用于区分"是开盘跳空造成的还是盘中走势造成的"。

#### 🚨 T+1 约束规则（新增持仓复盘必读）

**A股/场内权益 ETF 实行 T+1**：当日买入的份额，**当日无法卖出**（次日 T+1 起才可卖出）。

- **禁止批评"当日新增持仓未止盈/未减仓/达目标未锁定利润"**——当日买入的份额客观上不具备卖出条件，"尾盘达目标未止盈"是**伪命题**，不得作为复盘缺陷记录（8/27 半导体ETF 512480 教训：当日建仓当日收超目标价，复盘却批评"未止盈"，逻辑错误）。
- **当日新增持仓的正确复盘口径**：
  1. 评估**建仓执行质量**：触发价 vs 成交价偏差、实际仓位 vs 建议仓位、是否严格按信号/纪律执行（"触发即市价执行"等）；
  2. 评估**建仓逻辑兑现度**：建仓理由（信号/催化/板块）当日是否成立；
  3. 将 **"次日止盈/持有/止损"决策**（含止盈线、止损线、仓位处理预案）写入"次日核心关注"，不在当日复盘里作"应止盈而未止盈"的评判。
- **做T复盘同理**：正T（先买后卖）仅适用于 T+0 品种（跨境/债券 ETF）或"卖出已持有底仓后再买回"的反T；权益 ETF 当日买入份额不可当日卖出，做T建议与复盘不得要求"当日买入当日卖出"。

- **误触发**：触发条件满足但市场方向与信号预判相反（条件设计过于宽松）
- **漏触发**：触发条件未满足但实际出现了信号预判的机会（条件设计过于严格）

**决策质量标准**（信号方向是否正确、触发条件是否合理）：
- **S (卓越)**：方向完全正确，触发条件精准，执行后获显著正收益
- **A (正确)**：方向正确，触发条件合理，避免损失或获得收益
- **B (中性)**：方向正确但触发条件需调整（过于严格/宽松）
- **C (偏差)**：方向基本正确但时机/仓位设置有问题
- **D (错误)**：方向错误，或逻辑依据已被证伪
- **F (严重错误)**：方向完全相反，执行会导致重大亏损

**执行质量标准**（用户是否严格按触发条件执行）：
- **A**：严格按触发条件执行，无犹豫/无提前/无滞后
- **B**：基本按触发条件执行，有轻微偏差（价格/时间偏差<10%）
- **C**：执行了但偏离触发条件较大
- **D**：应执行但未执行（错过信号）
- **F**：不应执行但执行了（违反信号纪律）

**升级质量评级（仅针对从关注列表升级的盘中追加信号，v2.0）**：
- **U-S**：升级时机精准，升级后信号获利
- **U-A**：升级方向正确，升级后信号平盘或微利
- **U-B**：升级方向正确但时机偏早/偏晚
- **U-C**：假突破升级——原观察信号本身不该触发（升级条件过于宽松），升级后亏损
- **U-F**：该升级但未升级——方向确认明确但升级条件未触发（升级条件设计错误）

> 这是 Harness 层的核心步骤：用今日复盘的结果生成次日的可执行 prompt。

**步骤：**

1. **读取模板框架**：参考 `harness/prompts/早盘分析-模板.md` 和 `harness/prompts/复盘分析-模板.md` 获取固定结构

2. **收集次日输入数据**：
   - 当前持仓：`harness/config/持仓.md`
   - 可用金额：`config/持仓.md` 的 `可用金额` 行
   - 今日市场表现：`reports/{today}/复盘报告.md` + `reports/{today}/早盘报告.md`
   - 近期经验：`harness/experience/投资经验.md`、`harness/experience/短线机会经验.md`
   - 次日事件日历：通过 `a-stock-data` + WebSearch 研究次日重大事件、财报、政策节点

3. **生成 `harness/staging/今日-早盘分析.md`**（次日早盘可执行 prompt）：
   - 填入当日持仓表
   - 填入可用金额（持仓快照区顶部）
   - 填入次日事件日历
   - 填入今日核心矛盾分析
   - 填入逐只持仓映射与操作判断
   - **填入非持仓板块机会扫描行**：建仓建议列按 `{图案} {分类名}` 格式填充，备注只允许三选一（`🟢 建仓`/`🟡 关注`/`🔴 回避`），禁止自定义备注；扫描池须 6 类逻辑全覆盖（外盘映射/消息催化/资金确认/超跌反抽/防御红利/业绩驱动-财报窗口强制，REQ-003），接近建仓门槛的板块标注"准建仓：差{维度}"；**若预计无 🟢 建仓，预填"无建仓原因分析"框架**（最高分板块短板/市场环境归因/建仓前置条件）
