## 三、数据口径（重要，先读）

> 以下口径与券商软件一致，复盘时严格遵守。

### 涨跌幅（标准口径）

```
涨跌幅 = (今日收盘价 - 昨日收盘价) / 昨日收盘价 × 100%
```

这是券商软件、腾讯财经等所有行情终端统一使用的计算方式。**复盘报告的涨跌幅必须用此口径。**

### 辅助指标

| 指标 | 公式 | 用途 |
|------|------|------|
| 开盘缺口 | (今开 - 昨收) / 昨收 | 判断高开/平开/低开幅度 |
| 日内波动 | (今收 - 今开) / 今开 | 判断日内走势方向与力度（低开高走/高开低走等） |

涨跌幅 ≈ 开盘缺口 + 日内波动（忽略二阶小量）。分析时先用涨跌幅判断涨跌，再用开盘缺口+日内波动拆解成因。

### 数据验证（执行前必做）

1. **价格跳变检测**：若任一 ETF 的 `|今收/昨收 - 1| > 15%`，必须排查是否发生份额调整（合并/拆分），确认除权后再比较
2. **数据源交叉验证**：早盘与收盘数据优先使用同一数据源（腾讯财经）；若混用 mootdx/腾讯，须交叉验证两源"昨收"是否一致
3. **昨收核对**：收盘腾讯的"昨收" ≠ 早盘报告中"现价"的参考基准时，需标注数据源差异

### 1. 大市表现复盘

### 2. 持仓复盘

逐只审视今日持仓表现，**涨跌幅以任务三的标准口径（vs 昨收）为准**，重点关注大涨或大跌的标的：

- **大涨**：判断是否需要锁定利润。结合技术面（均线、MACD、RSI、成交量等）给出 **减仓 / 持有 / 加仓** 的明确建议及理由；
- **大跌**：回溯盘前、盘中是否存在可识别的消息或信号，评估本次下跌是否可提前规避，并记录改进点。
- 每只标的列出三项数据：**涨跌幅（vs 昨收）、开盘缺口、日内波动**，用于区分"是开盘跳空造成的还是盘中走势造成的"。

#### 2b. 做T建议复盘

- **已触发的做T建议**：实际执行了吗？若执行，结果盈亏如何？预估胜率与实际结果对比
- **未触发的做T建议**：触发条件设置是否合理？是否过于严格（错过机会）或过于宽松（触发但不该做）？
- **未给出做T建议但实际存在机会的标的**：复盘时发现早盘未识别但实际存在的做T机会，记录为何遗漏

**触发准确性标准**：
- **准确触发**：触发条件满足时，市场方向与信号预判一致，执行后有正收益预期
- **误触发**：触发条件满足但市场方向与信号预判相反（条件设计过于宽松）
- **漏触发**：触发条件未满足但实际出现了信号预判的机会（条件设计过于严格）

**决策质量标准**（信号方向是否正确、触发条件是否合理）：
- **S (卓越)**：方向完全正确，触发条件精准，执行后获显著正收益
- **A (正确)**：方向正确，触发条件合理，避免损失或获得收益
- **B (中性)**：方向正确但触发条件需调整（过于严格/宽松）
- **C (偏差)**：方向基本正确但时机/仓位设置有问题
- **D (错误)**：方向错误，或逻辑依据已被证伪
- **F (严重错误)**：方向完全相反，执行会导致重大亏损

**执行质量标准**（用户是否严格按触发条件执行）：
- **A**：严格按触发条件执行，无犹豫/无提前/无滞后
- **B**：基本按触发条件执行，有轻微偏差（价格/时间偏差<10%）
- **C**：执行了但偏离触发条件较大
- **D**：应执行但未执行（错过信号）
- **F**：不应执行但执行了（违反信号纪律）

**信号遗漏检测**（复盘时必答）：
1. 是否存在**早盘未识别但实际应发出的信号**？（如：某个标的盘中出现了清仓条件但早盘未生成清仓信号）
2. 是否存在**信号方向正确但被错误取消**？（如：北向一票否决触发但实际应保留某条信号）
3. 是否存在**触发条件设计缺陷**？（过于严格导致错过 / 过于宽松导致误触发）
4. **信号触发记录是否完整**？（是否存在触发条件满足但未在信号触发记录中记录的情况？是否存在触发记录中"用户操作"为空但实际已执行的情况？）

**步骤：**
a. 读取 `每日调仓.md` → 解析"## 1. 当前持仓"表格（此为权威持仓来源）
b. 校验：表头列数 = 4（股票名称 / 代码 / 持仓量（份） / 成本价（元）），至少有一行数据 → 否则中止并报错
c. **先比对**：将新解析的持仓与 `config/持仓.md`（同步前版本）对比，记录差异：
   - 新增标的（如：+黄金ETF 518880）
   - 移除标的（标的已清仓，如：-180ETF 510180）
   - 数量变化（加仓/减仓导致份数变化）
   - 代码修正（如：黄金ETF代码从错误159915修正为518880）
d. **记录差异后**再覆写 `harness/config/持仓.md`，保持与 `每日调仓.md` 的当前持仓表完全一致
e. 若用户当日有调仓操作但 `每日调仓.md` 未更新 → 提醒用户先更新调仓日志
f. **将差异记录（步骤c的输出）保留**，供任务5中的"八、持仓变更"节使用

### 6. 生成次日 staging prompts（Harness 流程）

> 这是 Harness 层的核心步骤：用今日复盘的结果生成次日的可执行 prompt。

**步骤：**

1. **读取模板框架**：参考 `harness/prompts/早盘分析-模板.md` 和 `harness/prompts/复盘分析-模板.md` 获取固定结构

2. **收集次日输入数据**：
   - 当前持仓：`harness/config/持仓.md`
   - 今日市场表现：`reports/{today}/复盘报告.md` + `reports/{today}/早盘报告.md`
   - 近期经验：`harness/experience/投资经验.md`、`harness/experience/短线机会经验.md`
   - 次日事件日历：通过 `a-stock-data` + WebSearch 研究次日重大事件、财报、政策节点

3. **生成 `harness/staging/今日-早盘分析.md`**（次日早盘可执行 prompt）：
   - 填入当日持仓表
   - 填入次日事件日历
   - 填入今日核心矛盾分析
   - 填入逐只持仓映射与操作判断
   - 填入操作清单、核心关注时间表、跨品种约束
   - 填入上期预判回顾（今日预判 vs 今日实际）

4. **生成 `harness/staging/今日-复盘分析.md`**（次日复盘可执行 prompt）：
   - 填入当日持仓表
   - 填入特别关注项（根据今日市场核心变量）
   - 填入上交易日核心回顾（今日的核心特征+核心教训+次日核心变量）

5. **归档当日 staging**：将当日的 staging 文件归档到 `harness/archive/{today}/`
