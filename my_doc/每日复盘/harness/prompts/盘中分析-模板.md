# 盘中分析（模板）

> 本文件是**永久模板**，包含盘中分析的固定框架、数据收集步骤和信号验证/生成规则。
> **盘中分析无需 staging**——市场状态随时变化，执行时直接读取本模板，配合实时数据运行。
> 执行时间：A股交易时段内（9:30–15:00），可多次执行。

---

## 一、任务说明

### 执行时机
- A股交易时段内（9:30–15:00），随时可触发
- 建议执行节点：10:30（开盘1小时后，方向初步明确）、13:30（午后方向确认）、突发异动时

### 输入
- `my_doc/每日复盘/reports/{yyyyMMdd}/每日信号.md`（当日早盘生成的信号清单）
- `my_doc/每日复盘/harness/config/持仓.md`（当前持仓）
- `my_doc/每日复盘/harness/experience/短线机会经验.md`（做T纪律参考）

### 输出
1. **原地更新 `每日信号.md`**：信号状态变更 + 盘中验证记录 + 盘中追加信号
2. **聊天摘要**：信号变更汇总 + 市场快照 + 新信号/无新信号

### 关键原则
- ✅ 只修改"待执行"状态的信号；不触碰"已执行/已过期/已取消"
- ✅ 新信号严格遵守与早盘信号相同的格式（可量化触发条件+有效时段+仓位）
- ✅ 无新机会时强制输出"当前无新增信号机会"，不编造
- ✅ 每次执行追加新的验证记录，不覆盖历史记录
- ❌ 不对早盘分析的全市场预判做系统性修正（那是复盘的任务）
- ❌ 不修改早盘设定的核心操作纪律（如"开盘30分钟不操作"）

## 二、数据收集（三步并行取数）

> 工具：`a-stock-data`（取数）。所有A股数据走此通道。

盘中分析数据需求比早盘精简——不需要隔夜外盘、不需要事件日历，聚焦**当下正在发生的事情**。

### 步骤 1：大盘快照（必须，不封IP）

```python
# 腾讯财经 — 指数+持仓ETF批量行情
from a_stock_data import tencent_quote  # 实际执行时从 a-stock-data SKILL 抄代码

codes = ['000001','000688','399006',  # 上证/科创50/创业板指
         '159227','159326','512480','512800','510180','159697','159915']  # 7只持仓ETF
quotes = tencent_quote(codes)
```

获取：实时价、涨跌幅、今开、最高、最低、昨收、**量比**（vol_ratio，字段49）、成交额、振幅。

### 步骤 2：板块扫描（并行）

**2a. 行业板块排名** — 了解资金在往哪流动：
```python

from a_stock_data import industry_comparison
comp = industry_comparison(15)  # 前15+后15
```

**2b. 强势股归因** — 今日什么题材在涨：
```python
# 同花顺热点 reason tags（零鉴权 73ms）
from a_stock_data import ths_hot_reason
hot = ths_hot_reason()  # 当日强势股+题材标签
```

**2c. 打板情绪** — 市场风险偏好温度计：
```python
# 涨停池+炸板率+连板高度
from a_stock_data import limit_up_sentiment, em_zt_pool, em_dt_pool
from datetime import datetime
today_str = datetime.now().strftime("%Y%m%d")

# 返回: zt_count, zb_count, dt_count, break_rate%, max_height, ladder{板数:家数}
```

### 步骤 3：资金面（并行）

**3a. 北向资金分钟流向** — 最关键边际信号：
```python
# 同花顺 hsgtApi（零鉴权）
from a_stock_data import hsgt_realtime
north = hsgt_realtime()
if not north.empty:
    last = north.dropna().iloc[-1]

```

**3b. 持仓ETF量价快照** — 已含在步骤1的 tencent_quote 中，重点关注量比和振幅。

### 数据优先级

| 优先级 | 数据 | 端点 | 封IP风险 | 为什么重要 |
|--------|------|------|---------|-----------|
| 1 | 持仓ETF实时价+量比 | 腾讯 `tencent_quote` | 无 | 判断触发条件最直接数据 |
| 2 | 北向分钟流向 | 同花顺 `hsgt_realtime` | 无 | 一票否决条件+方向信号 |
| 3 | 行业板块排名 | 东财 `industry_comparison` | 低(em_get) | 新机会发现 |
| 4 | 强势股归因 | 同花顺 `ths_hot_reason` | 无(零鉴权) | 题材热度判断 |
| 5 | 打板情绪 | 东财 `limit_up_sentiment` | 低(em_get) | 市场情绪温度计 |

## 三、信号触发条件验证（核心步骤）

> 本节是盘中分析的核心——逐条验证早盘生成的信号是否已触发。

### 3.1 读取信号清单

从 `reports/{yyyyMMdd}/每日信号.md` 的信号总表中提取：
- 所有状态为 **"待执行"** 的信号
- 跳过状态为"已执行""已过期""已取消"的信号
- 从信号触发记录表检查用户操作列是否已有填写（防止重复触发）

### 3.2 判断信号是否仍在有效时段内

当前时间 v.s. 信号的有效时段：

```
当前时间 < 有效时段开始 → 信号尚未进入窗口，保持"待执行"不验证
当前时间 ∈ 有效时段内   → 取实时数据验证触发条件
当前时间 > 有效时段结束 → 信号已过期，更新状态为"已过期"

### 3.2a 紧急度优先验证 + 75%窗口强制过期（v2.0 新增）

在逐条验证前，先按以下规则排序和过滤：

**验证排序**：高紧急度信号优先验证（高 > 低），同紧急度内按 P0 > P1 > P2。

**75%窗口强制过期检查**（规则4，P0豁免）：
```
对每条"待执行"的非P0信号：
  窗口已过时长 = 当前时间 - 有效时段开始
  窗口总时长 = 有效时段结束 - 有效时段开始
  若 窗口已过时长 / 窗口总时长 > 75% 且信号仍未触发
    → 更新状态为"已过期"，在验证记录中注明"75%窗口过期"
```

**50%窗口自检**（规则3）：
```
对每条"待执行"的非P0信号：
  若 窗口已过时长 / 窗口总时长 > 50% 且信号仍未触发
    → 评估当前价格距触发条件的距离
    → 所需价格变动 > 日内波动率 × 剩余时间比例 → 标记"接近过期"并提前释放关注度
```
```

### 3.3 触发条件→数据端点映射

| 条件类型 | 典型条件示例 | 取数端点 | 判断方法 |
|----------|------------|---------|---------|
| **价格阈值** | "10:30前不创新低(>1.062)" | `tencent_quote` → low/price | 对比当前价/最低价与阈值 |
| **量比条件** | "成交量萎缩至前日60%以下(量比<0.6)" | `tencent_quote` → vol_ratio(字段49) | 量比值直接可用 |
| **北向条件** | "北向开盘30分钟流出>50亿" | `hsgt_realtime` → 累计净买入 | 取最新累计值判断 |
| **板块涨跌** | "半导体单边下跌未反弹" | `tencent_quote` 板块ETF / `industry_comparison` | 观察该板块ETF方向 |
| **打板情绪** | "日韩触发SIDECAR" | WebSearch + `limit_up_sentiment` | 外部事件+市场情绪交叉验证 |
| **跨品种约束** | "多只解禁股开盘跌停+上证跌幅>2%" | `em_dt_pool` + `tencent_quote('000001')` | 两个条件AND判断 |
| **商品价格** | "WTI电子盘继续走高" | WebSearch 或商品期货实时数据 | 外部商品价格走势 |

### 3.4 逐条验证流程

对每条"待执行+有效时段内"的信号：

1. **识别条件类型**：从触发条件文本中识别需要哪些数据
2. **取实时数据**：用对应端点拉取
3. **判断是否触发**：对比实时数据与触发阈值
4. **更新状态**：
   - 触发条件满足 → 状态更新为"已触发"
   - 在"盘中验证记录"中标注触发时间+当前值+判断依据
5. **未触发**：保持"待执行"，在验证记录中标注检查时间+当前值+距触发还有多远

### 3.5 验证记录格式

在 `每日信号.md` 的信号总表与执行记录之间，追加或更新"盘中验证记录"块：

```markdown
## 盘中验证记录

| 验证时间 | 标的 | 操作类型 | 仓位 | 当前状态 | 关键数据 | 判断 | 信号ID |
|----------|------|:------:|:---:|:------:|----------|------|--------|
| 10:35 | 银行ETF 512800 | 正T | 1/3 | 待执行→**已触发** | 量比=0.52 < 0.6 ✅, 当前价=1.078 > 1.062 ✅, 日经+1.2%未暴跌 ✅ | 三条件全部满足，正T可执行 | SIG-20260720-04 |
| 10:35 | 银行ETF 512800 | 正T | 1/3 | 待执行→**待执行** | 半导体当前+1.3%(反弹中)，不满足单边下跌条件 | 等待方向确认 | SIG-20260720-05 |
| 10:35 | 银行ETF 512800 | 减仓 | -1/4 | 待执行→**已过期** | 日经+1.2%未触发SIDECAR | 条件不满足，信号过期 | SIG-20260720-01 |
```

> 若盘中多次执行，追加新记录行（不覆盖旧行），保持审计追踪。

### 3.6 信号触发记录生成

> 当某条信号的触发条件被验证满足时，在信号总表状态更新之外，
> **必须同时在 `每日信号.md` 的"信号触发记录"表中追加一行**。

**触发记录追加规则**：

1. **何时追加**：信号状态从"待执行"变更为"已触发"时，同步追加触发记录
2. **追加位置**：在 `每日信号.md` 的 `## 信号触发记录` 表格中追加新行
3. **不可重复**：同一信号ID只触发一次（检查是否已有触发记录）
4. **即时提示**：触发记录生成后，在聊天摘要中以 🔔 标记提示用户

**触发记录字段填充规则**：

| 字段 | 填充规则 |
|------|---------|
| 触发时间 | 当前时间（HH:MM格式） |
| 信号ID | 从信号总表复制 |
| 优先级 | 从信号总表复制 |
| 标的 | 从信号总表复制 |
| 操作类型 | 从信号总表复制 |
| 触发条件摘要 | 从信号总表的"触发条件"字段截取核心条件（≤30字），并标注实测数据 |
| 当前状态 | 固定填"已触发" |
| 建议操作 | 根据操作类型生成一句话操作指令（如"正T买入→计划日内卖出"、"减仓1/4至安全线"） |
| 用户操作 | 初始留空，待用户填入 |

**示例触发记录**：
```markdown
| 10:35 | SIG-20260721-04 | P1 | 银行ETF 512800 | 正T | 半导体单边下跌确认，量比=1.8 ✅, 跌幅-2.3% ✅ | 已触发 | 10:00-10:30执行买入，计划日内卖出 | （待填入） |
```

**与盘中验证记录的关系**：
- 信号触发记录 = 信号已触发 → 需要用户行动 → 仅追加已触发信号，每条一行
- 盘中验证记录 = 所有信号的持续监控 → 覆盖已触发/待执行/已过期所有状态，每次执行追加多行
- 同一条信号可以同时出现在两个表中（触发记录记录"触发时刻"，验证记录记录"持续验证过程"）

## 四、盘中追加信号生成（三级阈值）

> 仅当盘中出现早盘分析**未覆盖**的新机会时，才生成追加信号。
> 三级阈值防止信号泛滥——多数盘中检查应落在 Tier 3（无新信号）。

### 4.1 前置检查：是否属于"早盘已覆盖"

在生成任何新信号前，先确认：
- 这个标的/方向是否已在早盘信号中覆盖？（如早盘已有半导体正T信号，盘中不再新增同方向半导体信号）
- 这个板块是否已在早盘非持仓扫描中评估过且评分<3.0？（是→说明逻辑不支持，不追加）

### 4.2 Tier 1 — 强信号（可生成 P1 操作信号）

触发条件（满足**任意 1 条**即可）：

| 条件 | 判断标准 | 数据源 |
|------|---------|--------|
| **北向盘中剧烈逆转** | 北向从开盘净流出>30亿反转为净流入>10亿，或反之 | `hsgt_realtime` |
| **板块级涨停潮** | 单板块≥5只涨停且板块ETF涨幅>5% | `em_zt_pool` + `industry_comparison` |
| **持仓触及关键止损/止盈位** | 任一持仓标的跌幅>8%或从成本价盈利>20% | `tencent_quote` 对比成本价 |
| **突发重大催化** | 东财全球资讯出现与持仓直接相关的重大新闻 | `eastmoney_global_news` |
| **V反三信号齐备** | ①价格结构信号(低开后未创新低+突破开盘价) ②量价配合(放量+价格回升) ③资金归属(北向仍流出但价格在涨=内资接管) | `tencent_quote` + `hsgt_realtime` |

Tier 1 新信号格式：优先级=P1，操作来源="盘中信号"，其他字段与早盘信号一致。

### 4.3 Tier 2 — 观察信号（可生成 P2 观察信号）

触发条件（需**至少满足 3/5 条**）：

| 条件 | 判断标准 | 数据源 |
|------|---------|--------|
| **板块排名大幅跃升** | 某板块从早盘排名后50%跃升至前20% | `industry_comparison` 与早盘报告第五节对比 |
| **量比异常** | 某持仓或关注ETF量比>2.0且方向明确 | `tencent_quote` vol_ratio |
| **持续资金流入** | 某板块连续3个5分钟主力净流入为正 | `eastmoney_fund_flow_minute` |
| **新催化标签** | 同花顺热点出现新题材标签（非早盘已识别标签），且关联≥3只个股 | `ths_hot_reason` 词频对比 |
| **联动走势** | 两个以上关联板块出现一致性方向（如半导体+科创50+创业板同向>2%） | `tencent_quote` 指数+ETF联动检查 |

Tier 2 新信号格式：优先级=P2，操作来源="盘中信号"，触发条件可略宽松但必须可量化。

**Tier 2 盘中观察信号的升级条件设计（v3.0 新增）**：

盘中追加的 P2 观察信号同样需要填写"升级条件"列（P1 操作信号填"—"）。盘中观察信号的升级条件按以下三类模板设计：

- **建仓观察**（新板块/新标的）：`方向确认>30min+{板块}ETF涨幅>1.5%→升级为P2加仓信号`
- **加仓观察**（持仓回调/突破）：`方向确认>30min+量比>1.5+{标的}不破关键位→升级为P1正T信号`
- **风控观察**（持仓恶化/跷跷板异常）：`确认恶化>20min+{标的}跌幅>2%+北向确认流出→升级为P1减仓信号`

升级条件的数据端点映射：
- 方向确认>Xmin → 从盘中验证记录的连续判断中推断
- 量比>阈值 → `tencent_quote` → vol_ratio(字段49)
- ETF涨幅/跌幅>阈值 → `tencent_quote` → price涨跌幅
- 北向确认 → `hsgt_realtime` → 累计净买入方向

### 4.4 Tier 3 — 默认：无新信号

当 Tier 1 和 Tier 2 条件均不满足时，**强制输出**：

> ℹ️ 当前无新增信号机会。早盘生成的 N 条信号仍在有效期内，按原计划执行。

**禁止行为**：
- ❌ 为了"有输出"而编造模棱两可的信号
- ❌ 将早盘已覆盖的信号换个说法重新生成
- ❌ 在没有量化触发条件的情况下添加"关注"信号

### 4.5 新信号生成检查清单

每条新信号生成前，逐项检查：

- [ ] 触发条件是否**可量化**？（禁止模糊描述如"如果走强"）
- [ ] 有效时段是否明确？（如"10:30-14:00"，不能写"全天"）
- [ ] 仓位建议是否合理？（T仓位不超过总持仓10%，新开仓需附风险评估）
- [ ] 是否与现有早盘信号重复或矛盾？
- [ ] 是否已交叉引用 `harness/experience/短线机会经验.md` 的做T纪律？
- [ ] 是否有明确的退出条件？（止损/止盈/过期自动失效）

## 五、输出操作

### 5.1 更新每日信号.md

对 `reports/{yyyyMMdd}/每日信号.md` 执行以下修改：

**A. 更新信号总表状态列**：
- 将已验证触发的信号状态从"待执行"改为"已触发"
- 将已过期的信号状态从"待执行"改为"已过期"

**A2. 追加信号触发记录**：
- 对每条状态变为"已触发"的信号，在"信号触发记录"表中追加一行（格式见 3.6 节）
- 不可重复追加（检查是否已有同名信号ID的触发记录）

**B. 追加/更新盘中验证记录块**（在信号总表之后）：
```markdown
## 盘中验证记录

| 验证时间 | 标的 | 操作类型 | 仓位 | 当前状态 | 关键数据 | 判断 | 信号ID |
|----------|------|:------:|:---:|:------:|----------|------|--------|
| HH:MM | 标的名称 | 操作 | XX% | 原状态→新状态 | 实测数据 | 判断依据 | SIG-YYYYMMDD-NN |
```

**C. 追加盘中新信号到信号总表**（如有新信号）：
盘中追加信号直接追加到信号总表末尾，与早盘信号共用相同的列结构。信号ID自动顺延早盘编号。


## 六、安全护栏

### 护栏 1：信号文件不存在
若 `reports/{yyyyMMdd}/每日信号.md` 尚未生成（早盘分析未执行或信号未产出）：
- ⚠️ 警告用户："当日每日信号.md 不存在，可能早盘分析尚未执行。仍会产出市场快照供参考。"
- 跳过信号验证和生成步骤，仅输出市场快照

### 护栏 2：多次盘中执行（累计单调更新）
- 每次执行追加新的验证记录行，不覆盖旧行
- 状态更新遵循单调规则：待执行→已触发/已过期（不逆向）
- 已标记"已触发""已执行"的信号不重复修改
- 同一信号在多次执行中状态不变时，可在验证记录中标注"维持XX状态"

### 护栏 3：用户已执行信号（跳过验证）
- 读取"信号触发记录"表，若某信号的"用户操作"列已有填写（已执行/部分执行/放弃）→跳过触发条件验证
- 若用户手动填写了用户操作但信号总表状态仍为"待执行/已触发"→同步更新为"已执行"
- 若"用户操作"列为空但信号已触发→正常进行触发条件验证（首次触发时追加触发记录）

### 护栏 4：非交易时段执行
- 当前时间 < 9:30 → 建议执行早盘分析
- 当前时间 > 15:00 → 建议执行复盘分析
- 周末/节假日 → 警告："当前非A股交易日，实时数据为最近交易日收盘数据。"

### 护栏 5：无机会强制声明
- Tier 1 和 Tier 2 均不满足时，强制输出："当前无新增信号机会。"
- 禁止为填充"信号总表"而编造信号
- 如果用户坚持要求追加信号但确实无机会→输出"经全面扫描，当前无满足量化触发条件的盘中机会。"
