# BUG-010: auto_logic_inspect 检查脚本缺陷 — C1/C2/C3 引号语法错误 + C4/D2 缺 UTF-8 导致 Windows 上无法运行

- **组件**: prompts/（auto_logic_inspect.md C1/C2/C3/C4/D2）
- **严重程度**: P2(中)
- **违反的正确性定义**: 自动化检查脚本必须可执行——"文件存在性/内容必须用脚本验证"，脚本自身崩溃=检查形同虚设
- **状态**: FIXED
- **auto_fix_eligible**: true
  - 判定理由：确定性修复——C1/C2/C3 的 `f = 'f'my_doc/...''` 改为 f-string `f = f'my_doc/...'`；C4/D2 的 `python -c` 加 `-X utf8`（或 open 加 `encoding='utf-8'`）
- **发现时间**: 2026-08-27T17:25 CST
- **发现方式**: 代码巡检（auto_logic_inspect 实测执行时发现）
- **来源 REQ**: N/A
- **预期行为**: C1/C2/C3/C4/D2 脚本按 prompt 原样复制即可执行并输出真实检查结果
- **实际行为**:
  - **C1/C2/C3 语法错误**：`f = 'f'my_doc/每日复盘/reports/{today}/早盘报告.md''` 中 `'f'` 与后续标识符拼接 → `SyntaxError: invalid syntax`，脚本**编译即失败**，检查无法执行（本次巡检由 Agent 手工修正引号后才得以运行）
  - **C4/D2 编码失败**：脚本用 `python -c`（无 `-X utf8`）+ `open(path, 'r')`（无 `encoding='utf-8'`）读取 UTF-8 的 task_state.json → Windows 默认 GBK 解码报 `UnicodeDecodeError('gbk', ..., 'illegal multibyte sequence')`：
    - C4 实测误报 `C4:WARN: task_state.json 不存在或损坏`（实际文件正常，检查未真实执行）
    - D2 同理会误报 `D2:FAIL: 读取 task_state.json 失败`
- **复现步骤**:
  1. 复制 auto_logic_inspect.md C1 段脚本到 `python -X utf8 -c "..."` 执行 → SyntaxError
  2. 复制 C4 段脚本（不带 -X utf8）执行 → UnicodeDecodeError → 误报 "task_state.json 不存在或损坏"
  3. 复制 D2 段脚本（不带 -X utf8）执行 → UnicodeDecodeError → 误报 FAIL
- **受影响文件**:
  - `my_doc/每日复盘/harness/automation/prompts/auto_logic_inspect.md`（C1/C2/C3 引号 + C4/D2 编码）
- **潜在影响**: 三条报告检查（C1/C2/C3）与两条状态检查（C4/D2）在 Windows 环境按原样无法真实执行——要么崩溃要么误报，削弱逻辑巡检对"报告章节缺失/状态不一致"的真实捕获能力
- **建议修复**: ① C1/C2/C3：`f = f'my_doc/每日复盘/reports/{today}/早盘报告.md'`（f-string 语法，`-X utf8` 下可直接跑）；② C4/D2：脚本命令加 `-X utf8`，或 `open(..., encoding='utf-8')`；③ 参照同文件 B1/B2/B3/D3 已用 `python -X utf8` 的写法统一风格

## 测试证据
```
# C1 段（原样）
python -X utf8 -c "... f = 'f'my_doc/每日复盘/reports/{today}/早盘报告.md'' ..."
→ SyntaxError: invalid syntax (<string>, line 6)

# C4/D2 段（原样，无 -X utf8）
python -c "... open('...task_state.json', 'r') ... json.load(f) ..."
→ UnicodeDecodeError('gbk', ..., 57, 58, 'illegal multibyte sequence')
→ C4 输出: C4:WARN: task_state.json 不存在或损坏（误报）

# 修复后实测
python -X utf8 -c "... f = f'my_doc/每日复盘/reports/{today}/早盘报告.md' ..." → 正常执行
python -X utf8 -c "... open('...task_state.json', 'r', encoding='utf-8') ..." → C4:PASS（WARN: staging_generated 字段为空）、D2:PASS
```

## 附注
- 同文件 B1/B2/B3 已使用 `python -X utf8`（可正常运行），说明是 C4/D2 遗漏所致，非环境问题
- 关联：BUG-008/009 反映检查关键词与报告结构漂移；本 BUG 反映脚本本身无法运行——三者都说明 auto_logic_inspect 自检能力需加固
