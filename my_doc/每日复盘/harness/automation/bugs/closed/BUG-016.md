# BUG-016: 复盘读取过期持仓/调仓 — dashboard TOS 云端模式只写云端，本地文件不更新

- **组件**: `etf-strategies/dashboard/portfolio.py`（TOS 严格零本地写）、复盘/早盘/盘中/周报 prompts（本地文件读取）、`etf-strategies/scripts/sync_holdings_cloud.py`（修复）
- **严重程度**: P1（数据一致性命门：复盘/早盘基于过期持仓出判断）
- **状态**: FIXED（修复已实施 + 全量验证通过 + 历史错误产出已复核修正，2026-09-01 用户确认关闭）
- **发现时间**: 2026-08-31T16:20 CST（用户报告）
- **发现方式**: 用户提问"今日有 2 笔调仓但复盘报告未读取"→ 排查

## 根因（已实证）

- dashboard「持仓/资产」页面在 **TOS 云端模式**（`etf-strategies/scripts/config/cloud.json` 已配置，2026-08-28 15:18 创建）下，`portfolio._md_write()` 按"严格零本地"只写云端 `holdings/每日调仓.md`/`holdings/持仓.md`，**本地 `my_doc/每日复盘/每日调仓.md` 等文件不更新**（本地文件 mtime 停留在 2026-08-28 11:25）。
- 每日复盘/早盘/盘中/周报 prompt（`auto_evening_review.md` 第十步 10.1/10.2、`auto_morning_analysis.md` 1.3b/1.3c/4.1、`auto_intraday_check.md`、`auto_weekly_portfolio.md`、`复盘分析-模板.md` 4.5）用 `open()` 读取**本地文件** → 读到过期数据。
- 8/31 用户在 dashboard 录入 2 笔调仓（云端 TOS 已确认存在）：`2026-08-31 软件ETF招商 159899 卖出 2,000@0.707`（SIG-02 止损执行）+ `2026-08-31 黄金ETF 518880 卖出 1,300@9.106`（SIG-01 减仓执行）；但 8/31 复盘报告读到本地过期文件 → 误报"今日调仓：无"、"SIG-01/02 触发但均未执行"、P0 执行率 0%，并把过期 6 持仓/现金 21,163 写回 `config/持仓.md`。

## 预期行为

复盘/早盘/盘中/周报读取的 `每日调仓.md`/`config/持仓.md` 与 dashboard「持仓/资产」页面同源（TOS 模式下拉取云端权威副本）。

## 实际行为（修复前）

8/31 复盘报告：`今日调仓：无（8/31 无调仓记录）`、`SIG-01 黄金减仓（1,300份）与 SIG-02 软件止损（2,000份）触发但均未执行`、`P0 执行率 0%` —— 与云端账本事实（已执行 2 笔）完全相反。

## 修复方案（已实施 + 测试通过）

1. `etf-strategies/dashboard/portfolio.py` 新增 `pull_holdings_to_local()`：把云端 `holdings/每日调仓.md`+`holdings/持仓.md` 拉回本地（未配置云端/无对象则跳过）。
2. 新增 `etf-strategies/scripts/sync_holdings_cloud.py`：独立入口，输出 `PULLED`/`SKIP`，退出码 0/1，供 prompt 前置调用。
3. 4 个自动化 prompt + `复盘分析-模板.md` 4.5 增加强制前置步骤"第零步：同步云端持仓/调仓到本地"；`daily-review-harness` SKILL.md 同步说明。
4. `etf-strategies/dashboard/scheduler.py` `_run_prompt` 运行前自动拉取。
5. 测试：`tests/test_portfolio_trades.py` 新增 3 个单测（云端有对象/无对象/未配置），etf-strategies 全量 407 passed，harness 全量 215 passed。
