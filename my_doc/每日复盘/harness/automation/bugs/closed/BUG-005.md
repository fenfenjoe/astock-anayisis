# BUG-005: D4 信号模型一致性检查脚本失效 — CHECK_TARGETS 解包错误（二元组 vs 三元组）

- **组件**: prompts/（auto_logic_inspect.md D4）+ lib/consistency_check.py
- **严重程度**: P1(高)
- **违反的正确性定义**: D4 信号模型一致性 — 手动模板/自动化 prompt/编排层三处信号标记应无漂移，且该检查必须可自动执行
- **状态**: FIXED
- **auto_fix_eligible**: true
  - 判定理由：确定性修复——auto_logic_inspect.md D4 解包代码与 lib CHECK_TARGETS 结构同步即可
- **发现时间**: 2026-08-26T17:07 CST
- **发现方式**: 代码巡检（auto_logic_inspect D4 执行报错）
- **来源 REQ**: N/A
- **预期行为**: D4 脚本遍历 CHECK_TARGETS 读取 7 个目标文件并调用 check_consistency，输出 D4:PASS/FAIL + 明细报告
- **实际行为**:
  - lib/consistency_check.py 的 CHECK_TARGETS 自 v2.0 起为三元组 `(label, path, role)`（含角色字段，definer/consumer 检查不同标记集）
  - auto_logic_inspect.md D4 脚本仍按二元组解包 `for label, path in CHECK_TARGETS:` → 运行时 `ValueError: too many values to unpack (expected 2)`，D4 必然崩溃
  - 人工修正解包为三元组后检查通过（D4:PASS，7 个文件信号标记齐全）——说明**信号模型本身无漂移，但 D4 自动化检查能力已失效**
- **复现步骤**:
  1. 原样运行 auto_logic_inspect.md 的 D4 检查命令
  2. `from lib.consistency_check import ... CHECK_TARGETS` 后 `for label, path in CHECK_TARGETS:`
  3. 抛出 `ValueError: too many values to unpack (expected 2)`，D4 标记为 ERROR，检查无法完成
- **受影响文件**:
  - `my_doc/每日复盘/harness/automation/prompts/auto_logic_inspect.md`（D4 解包代码）
  - `my_doc/每日复盘/harness/automation/lib/consistency_check.py`（CHECK_TARGETS 三元组定义，正确，勿改）
- **潜在影响**: 信号模型防漂移检查静默失效——若未来三处信号标记再次漂移（如 v2.0 A 区修复前的状态），D4 将无法发现；巡检报告将 D4 标为 ERROR 而非 PASS/FAIL
- **建议修复**: 将 auto_logic_inspect.md D4 脚本解包改为 `for label, path, role in CHECK_TARGETS:`（与 lib 对齐），其余逻辑不变
