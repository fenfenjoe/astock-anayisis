# BUG-034: 第十六步最终验证脚本 HTML 检查大小写 bug — 复盘报告.html 永远误报失败

- **组件**: prompts/（auto_evening_review.md 第十六步验证脚本）
- **严重程度**: P2
- **违反的正确性定义**: 报告产出完整性验证应准确反映产出状态；HTML 已正确生成却误报失败 → 验证失真

- **auto_fix_eligible**: true

- **来源 REQ**: N/A
- **预期行为**: `auto_evening_review.md` 第十六步验证脚本应正确识别含 `<!DOCTYPE html>` 和 `<style>` 的完整 HTML 文档并输出 ✅
- **实际行为**: 验证脚本第 1601 行 `if '<!DOCTYPE html>' not in html_content.upper() or '<style>' not in html_content:` **永远为 True**（误报失败）：
  - `html_content.upper()` 将内容全转大写，`<!DOCTYPE html>` → `<!DOCTYPE HTML>`
  - 但字面量 `'<!DOCTYPE html>'` 中 `html` 为小写 → 不在全大写内容中 → `not in` 恒为 True → 任何合法 HTML 都被判失败
- **复现步骤**:
  1. 生成合法 `复盘报告.html`（首行 `<!DOCTYPE html>`，含 `<style>`）
  2. 运行第十六步验证脚本
  3. 观察：`❌ 复盘报告.html 不是完整 HTML 文档（缺 DOCTYPE 或 <style>）` 恒出现，即使文件完全正确
- **受影响文件**:
  - `my_doc/每日复盘/harness/automation/prompts/auto_evening_review.md`（第十六步验证脚本 L1601，修复大小写比较）
  - `my_doc/每日复盘/harness/automation/prompts/auto_evolution_weekly.md`（第四步验证脚本 L114，**2026-10-09 发现同类模式**）
- **潜在影响**: 每次复盘第十六步验证均误报 HTML 失败 → 复盘标记失败阻塞；2026-10 起 HTML 强制产出，该 bug 将每个交易日复现。本次已用修正版脚本确认 HTML 实际合格（`'<!doctype html>' in html_content.lower()` = True）；进化周报第四步验证同样恒误报（2026-10-09 实测触发）
- **建议修复**: 验证脚本改为 `if '<!doctype html>' not in html_content.lower() or '<style>' not in html_content.lower():`（全小写比较，兼容大小写变体）
