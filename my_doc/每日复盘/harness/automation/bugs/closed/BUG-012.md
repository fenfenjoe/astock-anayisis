# BUG-012: parse_signal_markdown 无法解析带 markdown 加粗的状态列（**已触发**）

- **组件**: lib/signal_tracking.py / tests/test_signal_tracking_parse.py
- **严重程度**: P1(高)
- **违反的正确性定义**: 信号入库（8.6.1）要求解析当日每日信号.md 中所有"已触发/已执行/部分执行"信号；盘中信号文件状态列使用 **加粗** 格式（盘中 agent 写入 `**已触发**`），解析器 `_TRACKABLE_STATUSES = {'已触发','已执行','部分执行'}` 不匹配 → 解析 0 条 → signal_tracking.json 从未被写入当日信号 → 信号收益追踪失效
- **状态**: FIXED
- **auto_fix_eligible**: true
  - 判定理由：确定性修复（单元格剥离 `**` 标记），有单测覆盖
- **发现时间**: 2026-08-31T15:58 CST
- **发现方式**: 复盘验证（8.6.1 信号入库解析 0 条）
- **来源 REQ**: N/A（REQ-001 信号收益追踪功能回归缺陷）
- **预期行为**: 盘中信号文件状态列为 `**已触发**`/`**已执行**` 时，parse_signal_markdown 应剥离加粗标记后正确匹配状态并入库
- **实际行为**: `_parse_table_rows` 原样返回 `**已触发**`，`status not in _TRACKABLE_STATUSES` → 跳过全部信号，解析结果 0 条
- **复现步骤**:
  1. 生成带 `**已触发**` 状态列的每日信号.md（盘中 agent 标准格式）
  2. 调用 parse_signal_markdown(md_text, today)
  3. 返回空列表（实际应为 1+ 条记录）
- **受影响文件**:
  - `lib/signal_tracking.py`（`_parse_table_rows` 单元格剥离 `**`，新增 `_strip_md` helper）
  - `tests/test_signal_tracking_parse.py`（新增 TestParseMarkdownBoldStatus 3 用例）
- **潜在影响**: 未修复则 8/31 起所有 P0/P1 已触发信号的入库静默失败，信号质量仪表盘/收益追踪全部失真
- **建议修复**: 已完成——`_strip_md()` 剥离 `**` 后匹配；回归 214 passed（1 环境性失败与修复无关）
