- **组件**: prompts/（auto_morning_analysis.md 1.3c 内嵌校验脚本）
- **严重程度**: P2
- **违反的正确性定义**: staging 持仓新鲜度校验应只比较真实持仓表；误报导致校验信号失真（本次 staging 第一节持仓表与 config 实际一致，却报 12 个 STALE/MISMATCH）
- **状态**: OPEN
- **auto_fix_eligible**: false
  - 判定理由：涉及 prompt 内嵌解析脚本逻辑修改（过滤表格标题/限定表头列），需人工确认改动范围；非确定性自动修复
- **发现时间**: 2026-09-03T09:30 CST
- **发现方式**: 复盘验证（早盘 1.3c 校验执行）
- **来源 REQ**: N/A
- **预期行为**: 1.3c 只提取 staging 中「持仓表」（表头含 股票名称/代码/持仓数量/成本价）的行做比较；[FAIL] 仅当真实持仓过期（数量/成本与 config 不同或已清仓/新增）
- **实际行为**: 解析器按 `len(parts)>=4 且 parts[1] 为 6 位数字` 的宽松条件抓取 staging 中**所有**含代码行，将第五节「板块机会扫描」、6.1/6.2「持仓评分/做T建议」等分析表行（如 512660 军工/航空航天 2仓@3、002142 持仓不变@回调至底部）误判为持仓，导致 12 个 STALE/MISMATCH 误报。staging 第一节真实持仓表（宁波 400@33.563 等 5 行）与 config/持仓.md 一致
- **复现步骤**:
  1. 运行早盘 1.3c 校验脚本（`python _tmp_13c_holdings_fresh.py`）
  2. 读取 staging/今日-早盘分析.md：第五节板块扫描表行 `| 军工/航空航天 | 512660 | 2 | 3 | ... |` 与 6.2 做T表行 `| 宁波银行 | 002142 | 不操作 | 打新底仓 | ... |` 均被 len(parts)>=4 匹配 → 报 STALE/MISMATCH
  3. 输出 [FAIL] 12 errors，但真实持仓与 config 一致
- **受影响文件**:
  - `my_doc/每日复盘/harness/automation/prompts/auto_morning_analysis.md`（1.3c 内嵌校验脚本：需限定表头 `股票名称|代码|持仓数量（份）|成本价` 或限定表格区域为 staging「一、我的持仓」节）
- **潜在影响**: 每次早盘 1.3c 均误报 [FAIL]，按流程处理「忽略 staging 持仓、以 config 覆写」虽保守安全（不引入错误持仓），但掩盖真实过期信号——若某日真实持仓过期，同样报 FAIL 无法区分；并污染报告运行提示与 BUG 工单噪音
- **建议修复**: 1.3c 解析增加表头行识别：仅当行首列匹配「股票名称」且第二列代码行才进入候选；或先定位 staging 中「## 一、我的持仓」标题到下一标题之间的表格区域再解析（与 D1/复盘模板 4.5 解析方式一致）
