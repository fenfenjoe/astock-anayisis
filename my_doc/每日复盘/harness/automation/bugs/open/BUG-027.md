# BUG-027: 东财资金流 fflow 的 secid 前缀遗漏「5 开头沪市 ETF」→ 10 只沪市 ETF 资金流静默返回空数组

- **组件**: a-stock-data skill 内嵌 `eastmoney_fund_flow_minute()` / `stock_fund_flow_120d()` + 每日复盘盘中检查 §2.3 / 收盘复盘资金面取数
- **严重程度**: P2
- **违反的正确性定义**: 资金面数据须可稳定取到且标的口径正确（数据纪律：静默空返回 = 伪"数据源不可用"）
- **状态**: OPEN
- **auto_fix_eligible**: false
  - 判定理由：涉及金融数据取数口径（secid 市场前缀），且修复点在 skill 文件中（跨项目边界），需人工确认后同步修复
- **发现时间**: 2026-09-10T15:59 CST
- **发现方式**: 复盘验证（收盘复盘资金面取数时独立发现）
- **来源 REQ**: N/A
- **预期行为**: 按代码推导东财 secid 时，沪市品种（`5` 开头 ETF/基金、`6` 开头股票、`9` 开头）统一映射为 `1.`，深市（`0/1/2/3` 开头）为 `0.`，北交所（`4/8`）另行处理 → 任何沪深 ETF/个股的资金流端点（`push2*/api/qt/stock/fflow/kline/get`）均应返回当日累计序列。
- **实际行为**: skill 内嵌实现为 `secid = f"1.{code}" if code.startswith("6") else f"0.{code}"`——**只覆盖 6 开头，遗漏 5 开头沪市 ETF**。沪市 ETF 被拼成 `0.518880` 等非法 secid，接口**静默返回空数组**（HTTP 200 + `data.klines=[]`），无异常抛出 → 表现为"该 ETF 无资金流数据"。
  - 9/10 收盘复盘实测：首轮 17 个标的（5 持仓 + 12 关注）**仅 7 个取到**，10 只失败全部为 `5` 开头沪市 ETF：518880 / 512800 / 512400 / 515880 / 512480 / 512660 / 510300 / 588000 / 510050 / 512880。改用 `secid=1.<code>` 重取后**全部成功**：518880 **+1.50 亿**、512880 +1.53 亿、588000 **-5.31 亿**、510300 -1.18 亿、515880 -1.03 亿、512400 -0.43 亿、512480 -0.42 亿、512660 -0.28 亿、512800 -0.04 亿、510050 +0.71 亿。
  - **同日盘中痕迹**：9/10 13:30 检查点对 518880/512800/512400/515880/512480/512660 六只 ETF 资金流"返回空"，14:00 记为"覆盖缺口恢复"——实为本缺陷的表现（当时诊断为数据源瞬时不可用，属误诊）。
- **复现步骤**:
  1. GET `https://push2delay.eastmoney.com/api/qt/stock/fflow/kline/get?secid=0.518880&klt=1&lmt=500&fields1=f1,f2,f3,f7&fields2=f51,f52,f53,f54,f55,f56,f57`
  2. 观察 HTTP 200 但 `data` 为 null / `klines` 为空数组（静默失败，非报错）
  3. 改 `secid=1.518880` 重取 → 正常返回 240 条分钟累计序列（09:31~15:00），末值 f52 = +1.50 亿（当日主力累计）
- **受影响文件**:
  - `.dsh/skills/a-stock-data/SKILL.md` 第 1051 行（`eastmoney_fund_flow_minute`：`secid` 前缀规则）
  - `.dsh/skills/a-stock-data/SKILL.md` 第 994 / 1550 / 1784 行（同类缺陷：`market_code = 1 if code.startswith("6") else 0`，影响 `stock_fund_flow_120d` 等端点）
  - `.dsh/skills/a-stock-data/SKILL.md` 第 1826 / 1905 / 2315 行（`prefix = "sh" if code.startswith("6") else "sz"`，同类遗漏 5 开头沪市 ETF）
  - `my_doc/每日复盘/harness/automation/prompts/auto_intraday_check.md`（§2.3 资金流取数：建议内联「统一映射」说明，避免抄到错误实现）
- **潜在影响**: ① 沪市 ETF 资金面数据**静默缺失**，且被误诊为"数据源瞬时不可用/覆盖缺口"，不进入工单；② 持仓中黄金ETF(518880) 长期受影响——9/10 全天"主力 +1.5 亿净流入"这一关键 P0-B 支撑证据在 13:30 检查点曾缺失；③ 影响 Tier2「持续资金流入」判定、板块资金归因、防御资金持续性判别（经验"防御资金持续性四要素"中"ETF 层面资金是否与板块同向放大"依赖该数据）；④ 同类缺陷散布 SKILL.md 至少 6 处，逐一排查成本高。
- **建议修复**: ① 在 a-stock-data skill 内统一提供 `_secid(code)` 纯函数（`5/6/9→1.`、`4/8→bj 规则`、其余→`0.`）并替换全部 6 处内联写法；② 增加"空数组即告警"纪律：取数为空时先打印 secid 与代码→前缀映射再判定数据源不可用，避免静默降级；③ 复盘/盘中 prompt 的资金流取数段落注明"沪市 ETF 用 1. 前缀"，并加一条冒烟断言（如 518880 必须非空）。
- **Related / 去重说明**: 与 **BUG-024**（fflow `f51` 累计值被求和 → 数值放大）**同模块但根因不同**（BUG-024 = 序列口径；本单 = secid 前缀导致空返回）；与 **BUG-022**（信号标的代码错配 516880≠515880）**不同**（BUG-022 = 标的选错；本单 = 同一标的的 secid 拼接错）。三者共同构成"资金面取数三缺陷"，建议一并修复与回归。
