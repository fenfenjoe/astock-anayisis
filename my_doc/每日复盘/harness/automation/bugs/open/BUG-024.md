# BUG-024: 盘中检查主力资金流口径不一致（fflow f51 累计值被求和 → 数值放大 10~20 倍）

- **组件**: prompts/（auto_intraday_check.md §2.3 资金面 / §4 Tier 2「持续资金流入」）+ 缺 lib 取数口径固化
- **严重程度**: P2
- **违反的正确性定义**: 数据准确性 / 跨检查点口径一致性（同一指标同日必须单调可比）
- **状态**: OPEN
- **auto_fix_eligible**: false
  - 判定理由：涉及资金面口径（金融计算类），需人工确认「累计值 / 分时增量 / 区间求和」三者的权威定义与展示格式后再固化，误修会静默污染所有后续资金面章节 → 按项目纪律标记 MANUAL_REVIEW
- **发现时间**: 2026-09-10T11:02 CST
- **发现方式**: 复盘验证（盘中检查 11:00 检查点实测比对 10:00 / 10:30 日志）
- **来源 REQ**: N/A
- **预期行为**: 同一交易日内，同一标的的「主力净流入」在不同检查点之间应为**口径一致、量级单调可比**的序列；9:40/10:00/10:30/11:00 四个时点的数值应满足 09:40 ≤ 10:00 ≤ 10:30 ≤ 11:00（净流入方向不变时）。
- **实际行为**: 口径混用，跨检查点数值差 10~20 倍，且非单调：
  | 标的 | 09:40 日志 | 10:00 日志 | 10:30 日志 | 11:00 实测（累计值） |
  |------|-----------|-----------|-----------|---------------------|
  | 黄金ETF 518880 | +1619/+1564/+1522万 | **+6.36亿** | +0.50亿 | **+1.007亿** |
  | 宁波银行 002142 | — | **+5.57亿** | +0.65亿 | **+0.861亿** |
  | 工商银行 601398 | — | **-5.52亿** | -0.18亿 | **-0.153亿** |
  | 电网设备ETF 159326 | — | **-5.23亿** | -0.30亿 | **-0.303亿** |
  | 航空航天ETF 159227 | — | **-1.39亿** | — | **-0.069亿** |

  **根因（已数值验证）**：东财 push2/push2delay `api/qt/stock/fflow/kline/get` 字段 **f51 是当日累计净流入**（实测 518880 序列 09:31=+87万 → 10:59=+9517万 → 11:01=+10065万，单调递增）。
  - **10:00 检查点对整条序列求和**当成了「累计主力」：10:00 前 30 根求和 = +5.52亿（黄金）/ +4.37亿（宁波银行）/ -5.69亿（工行）/ -4.40亿（电网设备）/ -1.19亿（航空航天）——与日志所报 +6.36 / +5.57 / -5.52 / -5.23 / -1.39亿 量级、方向完全吻合，可直接判定为「求和」而非「取末值」。
  - **10:30 检查点取末值**（口径正确）→ 数值与 11:00 实测同量级且单调（黄金 0.50亿 → 1.007亿）。
  - 09:40 检查点报的是「分钟净流入 +1619/+1564/+1522万」，数值本身即累计值（约 1600万），但被描述为「分钟净流入」→ 表述口径亦不一致。
- **复现步骤**:
  1. 交易时段调用 `https://push2delay.eastmoney.com/api/qt/stock/fflow/kline/get?klt=1&lmt=0&secid=1.518880&fields1=f1,f2,f3,f7&fields2=f51,...`，观察 f51 序列单调递增 → 证明为累计值
  2. 对比上表 09:40 / 10:00 / 10:30 / 11:00 四个检查点日志中「主力净流入」数值 → 非单调、量级差 10~20 倍
- **受影响文件**:
  - `my_doc/每日复盘/harness/automation/prompts/auto_intraday_check.md`（§2.3 资金面 / §4 Tier 2「持续资金流入（连续 3 个 5 分钟净流入 >1000 万）」——需固化「f51=累计值，取末值；需要增量时做差分」并示例）
  - `my_doc/每日复盘/harness/automation/logs/2026-09-10/intraday_1000.log`（错误数值已写入日志，需人工标注更正，不重写历史）
- **潜在影响**:
  1. **Tier 2「持续资金流入（连续 3 个 5 分钟净流入 >1000 万）」判定失真**：求和口径会把任何标的都放大 10 倍以上，使该条件近乎恒真/恒假，导致信号追加或漏发。
  2. **资金面叙述与复盘归因被污染**：10:00 检查点的「黄金ETF 累计 +6.36亿」「工行 -5.52亿（分钟转正）」等结论方向虽偶合、量级完全错误，晚间复盘若直接引用会造成归因偏差。
  3. **跨检查点趋势判断失效**：同一指标非单调即无法做「资金流入扩大/收窄」类趋势判断（今日 10:00→10:30 的「黄金 6.36亿→0.50亿」曾被当作变化描述）。
- **建议修复**:
  1. 在 `auto_intraday_check.md` §2.3 明确资金面取数口径：**主力净流入 = 序列末值（累计）**；如需「近 N 分钟净流入」则用 `末值 - N 分钟前值`（差分），并各给出 1 行示例代码。
  2. 考虑新增 `lib/fund_flow.py` 纯函数 `cumulative_main_net(klines)` / `delta_main_net(klines, minutes)`，配套 pytest 用例（单调性断言：累计序列非单调即抛错），供盘中/复盘共用。
  3. 在 §5.3「盘中验证记录」的「关键数据」列统一标注口径后缀（如 `+1.007亿(累计)`），避免歧义。
  4. 人工在 `intraday_1000.log` 追加「数值口径更正」批注（不重写历史），并在 9/10 复盘报告中以 11:00 实测值为准。
