# BUG-029: cloud_upsert_signals 批量异构键 upsert 静默失败（返回 0 但底层可写入）

- **组件**: lib/signal_tracking_cloud.py + lib/signal_tracking.py（cloud_db.upsert_many）
- **严重程度**: P2（中）
- **违反的正确性定义**: auto_intraday_check.md §5.2「触发价/触发时间云库写入（任务4）」——所有已触发信号必须把 触发价+触发时间 写云库 `trigger_price`/`trigger_time`；写失败不阻塞但要记录到日志
- **状态**: OPEN
- **auto_fix_eligible**: true
  - 判定理由：确定性修复（批量失败时逐条回退或归一化键集），不涉及金融计算口径
- **发现时间**: 2026-09-15T10:13 CST
- **发现方式**: 手动发现（10:00 盘中检查 §5.2 云库写入步骤实测）
- **来源 REQ**: N/A（任务4 云库写入步骤）
- **预期行为**: `cloud_upsert_signals([...])` 对任意记录集合（含键集异构：部分行带 trigger_price/trigger_time，部分不带）都应成功写入云库并返回成功条数
- **实际行为**: 批量传入键集异构的行（SIG-01 带 trigger_price/trigger_time，SIG-02~05 不带）时，PostgREST 报 `HTTP 400 PGRST102: All object keys must match` → `cloud_upsert_signals` 捕获异常返回 **0**（静默失败）。同一批记录**逐条**（单行批量）写入全部成功（5/5）。09:40 检查点单条写入（SIG-01 仅 1 行）时键集同构故未暴露
- **复现步骤**:
  1. 构造 2+ 条 signal_tracking 记录，其中至少 1 条含 trigger_price/trigger_time（其余不含）——即盘中已触发+待执行信号混合批次
  2. 调用 `cloud_upsert_signals(records)`
  3. 观察返回 0（无异常抛出），但逐条 `cloud_db._req(POST)` 均成功
- **受影响文件**:
  - `lib/signal_tracking_cloud.py`（cloud_upsert_signals：批量失败无逐条回退；to_row 跳过 None 列导致行键异构）
  - `etf-strategies/cloud_db.py`（upsert_many：批量 POST 未按同键约束归一化，未对 PGRST102 做逐条降级）
- **潜在影响**: 盘中检查 §5.2 云库写入若多信号混合批次（P0 触发+P1 待执行），会静默返回 0 → 调用方误判「写失败/云库不可达」→ 触发降级路径或漏报；Dashboard「信号触发记录」表数据来源（trigger_price/trigger_time 非空行）可能缺失
- **建议修复**: `cloud_upsert_signals` 内批量失败（HTTP 400 PGRST102 或异常）时**逐条回退**（每行单独 POST），逐条成功计数；或 `upsert_many` 在 PostgREST 报 PGRST102 时自动按行拆分重试。附：09:40 写入 SIG-01 的 signal_date 为 null（记录未带 signal_date/trigger_date 字段）→ 建议 prompt §5.2 示例强制带 `signal_date`
