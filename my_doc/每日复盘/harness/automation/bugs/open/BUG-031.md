# BUG-031: p0_tracking 执行率统计口径将「显式放弃/未触发」计入分母，与零容忍问责语义不符

- **组件**: lib/p0_tracking.py（parse_p0_signals / calc_p0_execution_rate）+ prompts/auto_evening_review.md 8.6.5
- **严重程度**: P2（中）
- **违反的正确性定义**: P0 执行率 = 已执行 P0 / 已触发 P0（auto_evening_review.md 8.6.5）——「已触发」应仅指**触发条件满足且应执行**的 P0；显式放弃（合法终态）与未触发（守位成功）不应计入问责分母
- **状态**: OPEN
- **auto_fix_eligible**: true
  - 判定理由：确定性修复（parse 时按状态语义区分触发/放弃/未触发），不涉及金融计算口径
- **发现时间**: 2026-09-15T16:0x CST
- **发现方式**: 收盘复盘验证（第八步 8.6.5 P0 追踪实测）
- **来源 REQ**: REQ-007（P0 执行零容忍）
- **预期行为**: 2026-09-15 三条 P0：SIG-01 黄金（已触发未执行→问责）、SIG-02 工行（显式放弃→合法终态不问责）、SIG-03 电网（未触发守位→不算缺失）→ 执行率应计 **0/1 = 0%**（1 条应执行未执行）
- **实际行为**: `parse_p0_signals` 将 3 条 P0 全部计为「触发」，`calc_p0_execution_rate` 得 **triggered=3, executed=0, rate=0.0%** → 统计口径把显式放弃（SIG-02）与未触发（SIG-03）计入分母，与零容忍问责语义不符（真正问责点仅 SIG-01）。跨日库 p0_tracking.json 沿用该口径，P0 告警 streak 计算可能虚高
- **复现步骤**:
  1. 构造 3 条 P0 信号：1 条「已触发未执行」、1 条「显式放弃」、1 条「未触发守位」
  2. 调用 `parse_p0_signals` + `calc_p0_execution_rate`
  3. 观察执行率 = 0/3 = 0.0%（预期 0/1 = 0%）
- **受影响文件**:
  - `lib/p0_tracking.py`（parse_p0_signals 状态映射 + calc_p0_execution_rate 分母判定）
- **潜在影响**: P0 执行率数字失真（分母含合法放弃/未触发）→ 连续 0% 天数告警可能虚高或虚低，影响 REQ-007 零容忍问责的准确性；跨日 streak 统计需对齐「应执行未放弃」口径
- **建议修复**: parse_p0_signals 在解析时按「响应状态/最终结果」区分：🚨已触发（含未执行告警）→ 计触发；已放弃/显式放弃 → 不计入分母（或单独计数）；监控中/未触发 → 不计入分母。calc_p0_execution_rate 分母 = 仅「应执行未放弃」的 P0 数，返回值附 `waived`（放弃数）与 `not_triggered`（未触发数）供报告区分

## 测试证据

```
  输入 3 条 P0（SIG-01 已触发未执行 / SIG-02 显式放弃 / SIG-03 未触发守位）
  parse_p0_signals → triggered=3（全部计入）
  calc_p0_execution_rate → rate=0.0%（0/3）
  报告语义口径: 真正应执行未执行 = SIG-01 黄金（0/1 = 0%）
  结论: 统计口径与零容忍问责语义不符，须修正分母判定
```
