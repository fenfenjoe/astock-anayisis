# BUG-033: cloud_enabled()/cloud_db.enabled() 未覆盖 pgdirect 后端：pgdirect 配置下误报 False → cloud_upsert_signals 提前 return 0（数据实际已写入），云库可用性判断系统性失真

- **组件**: lib/signal_tracking_cloud.py + etf-strategies/cloud_db.py
- **严重程度**: P2
- **违反的正确性定义**: 无
- **状态**: OPEN
- **auto_fix_eligible**: true
  - 判定理由：确定性修复：cloud_db.enabled() 在 _BACKEND=="pgdirect" 时应返回 _PG_ENABLED；signal_tracking_cloud.cloud_enabled() 同步受益
- **发现时间**: 2026-09-21T09:48
- **发现方式**: 盘中检查(09:40)
- **来源 REQ**: N/A
- **预期行为**: CLOUD_DB_BACKEND=pgdirect 且 PG 连接参数齐备（PGHOST/PGUSER/PGPASSWORD/PGDATABASE）时，cloud_db.enabled() 与 cloud_enabled() 应返回 True
- **实际行为**: cloud_db.enabled() 恒返回 _ENABLED（仅检查 SUPABASE_URL/SUPABASE_SERVICE_KEY 的 postgrest 后端），pgdirect 后端 _PG_ENABLED=True 时不反映 → signal_tracking_cloud.cloud_enabled()=False → cloud_upsert_signals 提前 return 0（实际 upsert_many 走 pgdirect 成功 5 条）；另：当前进程环境预设 CLOUD_DB_BACKEND=postgrest + SUPABASE_URL（无 SERVICE_KEY）遮蔽 .env 的 pgdirect 配置，setdefault 不覆盖 → 需显式覆盖环境变量
- **复现步骤**:
  1. os.environ 预设 CLOUD_DB_BACKEND=postgrest + SUPABASE_URL（无 SERVICE_KEY）
  2. 运行 cloud_db.enabled() → 返回 False（_ENABLED=False，尽管 .env 配置了 pgdirect 且 _PG_ENABLED=True）
  3. signal_tracking_cloud.cloud_upsert_signals(recs) → 内部 if not cloud_enabled(): return 0（数据实际经 upsert_many 写入）
- **受影响文件**:
  - `etf-strategies/cloud_db.py (enabled() 函数)`
  - `lib/signal_tracking_cloud.py (cloud_enabled())`
- **潜在影响**: 所有自动化任务（早盘/盘中/复盘）对云库可用性的判断系统性失真：cloud_enabled() 误报 False → §5.2/§5.3 云库写入被跳过或误判失败；早盘日志声称 5/5 入库但云库/本地均无今日信号（数据完整性缺口，本次检查已补写）
- **建议修复**: cloud_db.enabled(): _BACKEND=="pgdirect" 时返回 _PG_ENABLED（否则返回 _ENABLED）；另建议 _load_env 对 CLOUD_DB_BACKEND 用直接覆盖（os.environ[k]=v）而非 setdefault，避免环境变量遮蔽 .env 配置

