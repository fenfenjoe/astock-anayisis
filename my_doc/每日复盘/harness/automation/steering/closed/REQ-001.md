# REQ-001: 信号收益追踪系统

- **创建时间**: 2026-07-24
- **优先级**: P1(高)
- **影响范围**: 收盘复盘
- **状态**: CLOSED

## 需求描述

当前每日信号系统缺少跨日收益追踪机制。信号在日内触发/过期后即被归档，无法追踪触发了的信号实际带来了多少收益（或避免了多大损失）。需要在复盘环节新增一个持久化的信号追踪数据库，自动计算每条已触发信号的P&L，并输出汇总统计。

核心诉求：
1. 记录每条已触发信号从入场到出场的完整生命周期
2. 自动结算到期信号（按紧急度区分追踪期限）
3. 区分"已实现P&L"和"避免的损失"两个维度（卖出信号）
4. 在复盘报告中展示本日结算信号 + 累计追踪统计

## 期望结果

- `signal_tracking.json` 持久化追踪所有已触发信号的P&L
- 每日复盘自动更新追踪库，结算到期信号
- 复盘报告中可查看信号收益汇总
- 胜率/平均持有天数等统计指标可用

## 约束/注意事项

- 历史信号（7/24之前）不回溯，从实施日开始追踪
- 追踪库使用JSON格式，遵循现有 task_state.json 模式
- 买入信号P&L=(出场价-入场价)×份额；卖出信号P&L=(卖出价-成本基准)×份额
- 卖出信号额外计算"避免的损失"=(卖出价-N日后价格)×份额
