## 需求描述

**背景（9/9 黄金 P0 案例）**：SIG-20260909-01 黄金 P0 减仓评估 09:30 触发（开盘 8.97 破 9.0 防线）→ 全天 6 检查点告警 → **13:30 出现条件反转**（ETF 站回 9.0 上方 + 现货金 13:55 站上 4400 美元/盎司）→ 14:00/14:30 检查点提示"可评估显式放弃"（金价企稳+ETF 收复防线）→ 但 **用户 14:45 截止前既不执行也不显式放弃** → 收盘复盘按 REQ-007 规则标记"未执行（错过）"，零容忍问责。

**问题**：REQ-007 提供了"显式放弃"合法终态（P0 触发后若条件反转可声明放弃），但**缺少"放弃确认"交互机制**——检查点只单向提醒"可显式放弃"，没有强制用户二选一回复（放弃/执行）。结果：
1. 用户在条件反转时既不执行也不声明，最终一律按"错过"问责——**无法区分"主动判断不操作"（合法放弃）与"遗忘"（纪律缺失）**，问责准确性下降；
2. "显式放弃"合法终态形同虚设——9/9 黄金是首次明确出现"该放弃而未声明"的条件反转案例，未来 P0 触发后条件反转场景（如外部强催化逆转）会重复出现。

**目标**：为 P0 信号设计"放弃确认"交互——盘中检查末次告警（或条件反转首次出现时）要求用户明确回复"放弃/执行"二选一，回复"放弃"则记录为显式放弃（合法终态，不计入执行率缺失）；回复"执行"或超时未回复 → 按错过问责。

## 期望结果

1. P0 信号盘中检查发现"条件反转"（如防线收复+外部强催化）时，检查点自动生成"放弃确认"提示（二选一：放弃/执行），并记录在每日信号.md 的 P0 执行追踪节；
2. 用户回复"放弃" → P0 执行追踪最终结果=显式放弃（合法终态，P0 执行率计算时不作为"执行缺失"计入，单独统计"显式放弃"数）；
3. 用户回复"执行"或截止前未回复 → 最终结果=已执行/未执行（错过），按现规则处理；
4. P0 执行率统计口径扩展：触发=执行+显式放弃+错过（3 类），执行率=已执行/(已执行+错过)，显式放弃单独披露——防止"显式放弃"被滥用（需设置放弃次数阈值，如连续 ≥2 次放弃 → 告警审视信号设计）。
