## 需求描述

**问题（2026-09-10 实证）**：当日 `evening_review` 出现**两个实例并行执行**——实例 A 由调度链路于 15:53~16:03 执行（产出 staging×2 / archive/20260910 / p0_tracking / signal_tracking / PENDING #13 / BUG-025/026 / REQ-011/012 / 复盘报告初稿），实例 B 由用户显式请求于 15:53~16:13 执行同一 prompt。两实例在同一时间窗内对**同一批文件**读写，暴露出三类风险：

1. **归档损坏风险（最严重）**：`auto_evening_review.md` 第 11.0 步要求"**先归档当日 staging 原件，再覆盖生成次日 staging**"。两实例并行时，实例 B 若在实例 A 已覆盖 staging 之后再执行 11.0，就会把**次日（09/11）内容**复制进 `archive/20260910/`，导致当日原件永久丢失——**这正是 BUG-002（"先覆盖后归档致原件丢失"）的同一失效模式，只是在并行场景下重新具备触发条件**。本次实际未触发（实例 B 检测到 staging 已被 15:58 覆盖、archive 已含 9/9 版原件，改为仅核对不重跑 11.0），但**属侥幸规避而非机制保障**。
2. **重复写入 / 后写覆盖**：两实例都会写 `task_state.json`、`p0_tracking.json`、`signal_tracking.json`、`PENDING_CONFIRMATION.md`、`BUG_INDEX.md`、`每日信号.md`、`复盘报告.md`。本次两实例数据一致（独立复采互证），但若一方数据源降级或口径不同，后写者会静默覆盖先写者的正确结果，且无任何冲突提示。
3. **并发重复消耗**：同一任务的数据采集（东财 push2delay 分页 5+6 页 × 2、17 只标的 fflow、全 A 5,912 只分页 60 次、push2ex 4 池）被完整执行两次，既浪费额度也增加东财风控暴露。

**根因**：复盘/早盘类任务**只有幂等性检查，没有运行锁**。`task_scheduler.py` 的 `check_running()` 只覆盖**调度器派发的实例**（本次 `running_tasks` 为空，因实例 A 并非调度器派发链路，实例 B 为用户手动触发）→ 手动触发与调度触发之间、或多会话之间，互不可见。而 prompt 第 1.3 步的幂等检查以"复盘报告是否存在且为今日生成"为准 —— 两实例在报告尚未落盘的窗口期会**同时判定"需强制执行"**。

## 期望结果

① **跨实例互斥锁**：`evening_review` / `morning_analysis` / `intraday_*` 在 step 1.3 之后、step 2 之前获取统一运行锁（文件锁或 `task_state` 内的 `run_lock` 字段，含 `instance_id` / `acquired_at` / `pid`），已持锁时**第二个实例必须显式退出**（输出"检测到运行中实例 {id}（{acquired_at}），本次退出"），不得静默并行；锁带 stale 超时（建议 45 分钟，与 `check_running()` 一致）。
② **手动触发优先级可配置**：允许用户显式请求"以抢占方式接管"（如 `--takeover`），此时必须先把在跑实例的**中间态产物**落到 `logs/` 并输出接管说明，再继续。
③ **归档幂等保护**：11.0 步在复制前校验"待归档 staging 的目标日期 == 今日"，若发现 staging 已指向次日（说明已被覆盖）→ **跳过复制并写 `archive/{today}/归档说明.md`**（降级路径），同时立 BUG；避免把次日内容写进当日归档。
④ **写入前置校验**：对 `task_state.json` / `p0_tracking.json` / `signal_tracking.json` / `每日信号.md` / `复盘报告.md` 的写入，采用"读-改-写 + mtime/版本戳校验"：若发现文件在本实例读取后被他人修改 → 输出冲突告警并保留双方副本（`.conflict` 后缀），不静默覆盖。
⑤ **可观测**：`logs/{date}/evening_review.log` 头部记录 `instance_id` 与锁获取结果；并发情形在报告中"运行提示"一行提示，并按 §13.5 建单。
⑥ **测试**：`lib/run_lock.py` 纯函数（获取/释放/stale 判定/冲突检测）+ `lib/staging_verify.py` 增加"目标日期 == 今日"校验函数，均含单测。

## 约束/注意事项

① 本需求只解决**同日同任务的实例互斥**，不改变既有幂等语义（1.3 幂等检查保留）；
② 锁文件须放 `harness/automation/config/` 或 `logs/` 下，不得写入 reports/ 污染产出；
③ 不得因加锁导致**任务被永久阻塞**——stale 超时与 `--clear-running` / 手动接管通道必须齐备；
④ 与 BUG-002（先覆盖后归档）互补：BUG-002 解决"步骤顺序"，本 REQ 解决"并发条件下同一顺序被破坏"；
