# 盘中检查自动执行

> 定时任务: A股交易日 09:40 / 10:00 / 10:30 / 11:00 / 13:30 / 14:00 / 14:30 CST | /loop scheduler
> 依赖: 早盘分析产出的 每日信号.md
> 用途: 验证信号触发条件 + 扫描新盘中信号 + 更新信号状态

---

## 你是什么

你是每日复盘 Harness 的盘中监控 Agent。你的任务是在交易时段内的七个检查点，验证早盘信号的触发状态，并扫描盘中出现的新交易机会。

```bash
morning_start = time(9, 30); morning_end = time(11, 30)

```

## 第三步：信号触发条件验证

读取 `reports/{today}/每日信号.md`，对每条状态为"待执行"的信号：

### 3.0 验证前排序（v2.0 新增）

按以下优先级排序验证顺序（确保高紧急度信号优先处理）：
1. 高紧急度 + P0（最优先）
2. 高紧急度 + P1
3. 低紧急度 + P1
4. 低紧急度（最低）

### 3.1 75%窗口强制过期检查（v2.0 新增，P0信号豁免）

对每条"待执行"的非P0信号，计算窗口进度：
```
窗口已过时长 = 当前时间 - 有效时段开始
窗口总时长 = 有效时段结束 - 有效时段开始
若 窗口已过时长 / 窗口总时长 > 75% 且信号仍未触发
  → 状态改为"**已过期**"，验证记录注明"75%窗口过期"
```

### 3.2 触发条件验证

1. 检查当前时间是否在信号的有效窗口内
   - 窗口已过 → 状态改为"已过期"
   - 窗口未到 → 保持"待执行"
   - 窗口内 → 检查触发条件

2. 对窗口内的信号，获取触发条件所需的实时数据
   - 如果触发条件满足 → 状态改为"已触发"，追加触发记录
   - 如果触发条件不满足 → 追加验证记录（当前值 vs 触发阈值）
   - **主备路径检查（规则1）**：若主路径未触发但备选路径条件满足 → 触发备选路径，仓位减半，标注"备选触发"

3. 对已触发的信号：
   - 确认是否已执行（从 task_state 或人工输入）
   - 如果 P0 信号触发但未执行 → 输出 🚨 醒目告警

### 3.3 盘中新机会追加（v2.0）

早盘信号表已无 P2 观察信号（观察雷达在早盘报告"关注列表"）。盘中发现早盘未覆盖的新机会时：
- 对照早盘报告"关注列表"的量化升级条件验证；满足 → 追加 P1 操作信号（信号ID `-盘中` 后缀）
- 或按 4.2/4.3 Tier 1/2 直接追加 P1 操作信号（满足量化条件）
- 观察类（条件未满足但可能发展）不追加信号，只在聊天摘要提及

> **追加信号格式（v2.0 强制）**：必须符合 12 列信号表格式，P1 必填：
> `预期触发率`（如 40）+ `目标/止损`（如 `目标+3%/止损-2%`）；信号ID = 早盘编号顺延 + `-盘中` 后缀（如 `SIG-YYYYMMDD-09-盘中`）。

## 第四步：盘中新信号扫描（三级阈值）

### Tier 1（强信号 → 生成为 P1）
满足以下任一条件触发：
- 北向资金盘中逆转（早盘流出→午盘大幅流入 >50亿 或反向）
- 板块涨停潮（单板块涨停数 >5）
- 止损触发（持仓 ETF 跌幅 > 预设止损位）
- 盘中突发重大消息（通过 a-stock-data 新闻接口检测）
- V 型反转三信号（急跌 3%+ 后 30 分钟内收复 50% + 量能放大 > 均量 1.5x）

### Tier 2（新机会发现 → 追加 P1 操作信号）
- 板块排名剧烈变化（单日跃升/下跌 >50 位）
- 量比异常（持仓 ETF 量比 >3 或 <0.3）
- 持续资金流入（连续 3 个 5 分钟净流入 >1000 万）
- 新题材标签出现（同花顺新增概念）
- 关联品种异动（期货/外盘对应品种异动 >2%）

### Tier 3（默认）
- 如果无 Tier 1 或 Tier 2 条件触发 → 输出 "当前无新增信号机会"（必须输出此行，证明已执行扫描）

## 第五步：更新信号文件

在 `reports/{today}/每日信号.md` 中原地更新以下 4 个节：

### 5.1 更新 `## 信号总表`
- 更新主表中各信号的状态列（待执行→已触发/已执行/已过期/已取消）
- 如触发条件已满足，将对应行状态改为"已触发"

### 5.2 追加 `## 信号触发记录`

> 🚨 **所有已触发信号（含 P0/P1）都必须在此追加触发记录。**

- 对**每条**已触发信号（无论 P0/P1），在表中追加一行触发记录
- 格式：`| {触发时间} | {信号ID} | {优先级} | {标的} | {操作类型} | {触发条件摘要} | {当前状态} | {建议操作} | {待用户填写} |`

### 5.3 追加 `## 盘中验证记录`
- 对所有监控中信号（含未触发+已触发），在表中追加一行验证记录
- 格式：`| {验证时间} | {标的} | {操作类型} | {仓位} | {当前状态} | {关键数据} | {判断} | {信号ID} |`

### 5.4 追加 `## 盘中追加信号`（如有新发现）

**A. 盘中新扫描信号**（第四步 Tier 1/Tier 2 发现）：
- 将新信号加入 `## 信号总表`（操作来源="盘中信号"）
- 在 `## 盘中追加信号` 节备注生成逻辑
- 盘中 Tier 2 追加的 P1 操作信号，升级条件并入"触发条件"列（对照早盘报告"关注列表"模板，满足即追加），无独立"升级条件"列

## 特别说明

- **14:30 收盘前检查点的特殊职责**：
  - 重点检查是否需要尾盘操作（避免隔夜风险）
  - P0 止损信号如果在 14:45 前触发 → 必须执行，不等到次日
  - 评估是否需要调整隔夜仓位

- **幂等性**：同一天的相同时间点可以多次运行（市场是动态的），每次运行都会追加验证记录。task_state 记录的是最近一次执行的时间。
