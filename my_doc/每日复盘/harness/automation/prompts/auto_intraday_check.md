## 第三步：信号触发条件验证

读取 `reports/{today}/每日信号.md`，对每条状态为"未触发"的信号：

### 3.0 验证前排序（v2.0 新增）

按以下优先级排序验证顺序（确保高紧急度信号优先处理）：
1. 高紧急度 + P0（最优先）
2. 高紧急度 + P1
3. 低紧急度 + P1
4. 低紧急度（最低）

### 3.1 75%窗口强制过期检查（v2.0 新增，P0信号豁免）

对每条"未触发"的非P0信号，计算窗口进度：
```
窗口已过时长 = 当前时间 - 有效时段开始
窗口总时长 = 有效时段结束 - 有效时段开始
若 窗口已过时长 / 窗口总时长 > 75% 且信号仍未触发
  → 状态改为"**已过期**"，状态列注明"75%窗口过期"，并写云库 status='expired'（§5.3）
```

### 3.2 交易价驱动触发验证（v3.0 价格规则）

对每条信号，用 a-stock-data 获取标的最新价，按**交易价**驱动判定：

1. 检查当前时间是否在信号的有效窗口内
   - 窗口已过 → 状态改为"已过期"（写云库 status='expired'）
   - 窗口未到 → 保持"未触发"
   - 窗口内 → 用最新价 vs 交易价判定

2. **未触发 → 已触发（价格达到交易价）**：
   - 买入信号：现价 ≥ 交易价 → 状态改"已触发"，追加触发记录 + 写云库 status='triggered' + trigger_price/trigger_time（§5.2）
   - 卖出信号：现价 ≤ 交易价 → 状态改"已触发"，同上
   - 若现价未达交易价 → 保持"未触发"，在状态列/摘要注明（现价 vs 交易价）
   - **主备路径检查（规则1）**：若主路径未触发但备选路径条件满足 → 触发备选路径，仓位减半，标注"备选触发"
   - 注意：除交易价外，其余触发条件（量比/方向/放量等）仍需一并满足；交易价是**必要价位**而非充分条件

3. **已触发 → 已过期（触发后回落离开交易价，v3.0）**：
   - 对已触发的信号，若现价回落离开交易价且尚未执行：
     - 买入信号：现价跌破交易价（冲高回落到交易价下方）→ 状态改"已过期"，注明"触发后回落未执行"
     - 卖出信号：现价升破交易价（反弹回交易价上方）→ 状态改"已过期"，注明"触发后反弹未执行"
   - 同步写云库 status='expired'（§5.3）
   - **已执行（已买入/已卖出）的信号不再因价格回落改过期**

4. 对已触发的信号（未过期）：
   - 确认是否已执行（从 task_state 或人工输入）；已执行 → 状态改"已执行"
   - **触发价/触发时间记录（任务4）**：确认触发时，把 触发价 + 触发时间（HH:MM）记入 §5.2 的触发记录，并**写云库** `trigger_price`/`trigger_time`（见 §5.2 云库写入步骤）
   - **条件单辅助话术（REQ-007，降低人工盯盘依赖）**：P0 触发时向用户输出建议附带条件单模板：
     > 💡 建议设置条件单：标的 {名称}({代码})，触发价 {交易价}，动作 {操作}，数量 {份额}，有效期至 14:45；或人工盯盘 14:45 前执行。
     > （任务4：不再维护 `## P0 执行追踪` 登记表，条件单话术保留）

### 3.3 盘中新机会追加（v2.0）

早盘信号表已无 P2 观察信号（观察雷达在早盘报告"关注列表"）。盘中发现早盘未覆盖的新机会时：
- 对照早盘报告"关注列表"的量化升级条件验证；满足 → 追加 P1 操作信号（信号ID `-盘中` 后缀）
- 或按 4.2/4.3 Tier 1/2 直接追加 P1 操作信号（满足量化条件）
- 观察类（条件未满足但可能发展）不追加信号，只在聊天摘要提及

> **追加信号格式（v3.0 强制）**：必须符合 14 列信号表格式，P1 必填：
> `预期触发率`（如 40）+ `交易价`（触发条件关键价位）；买入信号另必填 `目标价`/`止损价`；
> 信号ID = 早盘编号顺延 + `-盘中` 后缀（如 `SIG-YYYYMMDD-09-盘中`）。

## 第四步：盘中新信号扫描（三级阈值）

### Tier 1（强信号 → 生成为 P1）
满足以下任一条件触发：
- 北向资金盘中逆转（早盘流出→午盘大幅流入 >50亿 或反向）
- 板块涨停潮（单板块涨停数 >5；**建仓须叠加"所属主线不弱化"联防，主线指数回落>1% 降级为观察，建仓用评估仓≤可用×1/4 或改为回踩确认，REQ-003**）
- 止损触发（持仓 ETF 跌幅 > 预设止损位）
- 盘中突发重大消息（通过 a-stock-data 新闻接口检测）
- V 型反转三信号（急跌 3%+ 后 30 分钟内收复 50% + 量能放大 > 均量 1.5x）

### Tier 2（新机会发现 → 追加 P1 操作信号）
- 板块排名剧烈变化（单日跃升/下跌 >50 位）
- 量比异常（持仓 ETF 量比 >3 或 <0.3）
- 持续资金流入（连续 3 个 5 分钟净流入 >1000 万）
- 新题材标签出现（同花顺新增概念）
- 关联品种异动（期货/外盘对应品种异动 >2%）

### Tier 3（默认）
- 如果无 Tier 1 或 Tier 2 条件触发 → 输出 "当前无新增信号机会"（必须输出此行，证明已执行扫描）

md = Path(f'my_doc/每日复盘/reports/{today}/每日信号.md').read_text(encoding='utf-8')
recs = parse_signal_rows_all(md, date.today().isoformat())
print('解析信号:', len(recs), '条')
for r in recs:
    print(' -', r['signal_id'], r['priority'], r['name'], r['trade_type'], r['status'])
if recs and cloud_enabled():

    print('云库 upsert 成功:', ok, '/', len(recs))

## 第六步半：盘中经验反思（事件驱动，新增 — 记忆体系 Phase 2）

> **铁律**：盘中是执行场景，**默认不写经验**——只在强触发时沉淀，且**T2（证伪/校准）优先**：
> 盘中观察到的事实若与既有经验冲突，立即更新旧经验（证据链+置信度），避免错误经验带过夜。

1. **T2 优先**：今日盘面事实与第二步半注入的（或已知的）经验冲突 → 更新对应条目
   （`viking_read` 旧条目 → 追加证据链 `{HH:MM} 盘中 {事实} {置信度调整}` → 贝叶斯：单次证伪 中→低）。
2. **T1 新规律**（仅强信号）：发现明确可复用的盘中新规律（如同板块多 ETF 同步跳水=板块级卖事实，
