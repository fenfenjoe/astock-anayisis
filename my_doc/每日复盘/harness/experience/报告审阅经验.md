# 报告审阅经验

> 本文档沉淀报告审阅中的常见错误模式与检查要点，供早盘报告和复盘报告生成后的质量把关使用。

---

## 一、审阅流程

每份报告初稿完成后，执行2-3轮逐项审阅：

1. **第一轮：数据校验** — 逐项核对数据计算、数据源、时点标注
2. **第二轮：逻辑审阅** — 检查判断一致性、矛盾检测、遗漏项
3. **第三轮：终稿确认** — 修正后整体通读，确认无新引入错误后输出

---

## 二、数据校验清单

### 2.1 涨跌幅计算
- [ ] 涨跌幅 = (今收 - 昨收) / 昨收，不得与"今开 vs 昨收"混淆
- [ ] 开盘缺口 + 日内波动 ≈ 涨跌幅（忽略二阶小量），偏差>0.3%需排查
- [ ] 不同数据源的"昨收"是否一致？混用 mootdx/腾讯时需交叉验证
- [ ] 若 |今收/昨收 - 1| > 15%，确认是否发生份额调整（合并/拆分）

### 2.2 数据源与代码
- [ ] **‼️ ETF代码-名称强制校验**：staging 生成后必须运行 Python 交叉比对脚本，逐代码核对 staging 中的名称与 `config/持仓.md` 中的权威名称是否一致。**禁止跳过此步骤**——"恒生科技ETF | 159227"类错误（159227 实际是航空航天ETF）纯靠人眼/AI自查无法发现，必须机械化比对。
- [ ] 数据时点是否标注？盘中数据是否注明"盘中"而非"收盘"？
- [ ] 美股代码前缀是否正确（usAAPL / usNVDA 等）？
- [ ] 东财数据是否做了除权/复权处理？

### 2.3 数值合理性
- [ ] 涨跌幅、振幅、换手率等数值是否在合理范围（如涨跌停板内）？
- [ ] 北向/主力资金数据单位是否一致（万元 vs 亿元）？
- [ ] "份"数与实际持仓数量是否对应？计算盈亏时份数×价差是否正确？
- [ ] ETF价格是否与历史区间一致（如159697在1.15-1.30区间）？

---

## 三、逻辑一致性检查

### 3.1 内部矛盾检测
- [ ] 同一标的的不同部分（建仓评分 vs 持仓预测 vs 做T建议）判断方向是否一致？
- [ ] "建议加仓"与"风险等级高"是否矛盾？
- [ ] "做T正T"与"预判低开"是否方向一致？
- [ ] 跷跷板效应：若同时建议加仓半导体+银行，是否解释了跷跷板失效条件？

### 3.2 评分与建议匹配
- [ ] 五维评分均分是否与综合得分一致（计算错误）？
- [ ] 得分≥3.8→建仓、3.0-3.7→关注、<3.0→回避的分类是否正确？
- [ ] 高分（≥4.0）是否附带风险锚（"如果错了会在什么情况下错"）？
- [ ] 低分（<2.0）是否给出了清晰的回避理由？

### 3.3 纪律一致性
- [ ] 不追高纪律：晨间已涨>3%的板块，"建仓"是否改为"等回调"？
- [ ] T仓位纪律：单笔T是否超总持仓20%？单日T总仓位是否超50%？
- [ ] 北向一票否决：5日累计净流出>100亿时，建仓建议是否附加严格条件？
- [ ] "买预期卖事实"检查：事件前已反弹的标的，是否考虑了回落风险？

---

## 四、完整性检查

### 4.1 强制推演是否遗漏
- [ ] 反面情景推演：每只持仓是否附带"如果比我预判的强/弱，原因是什么"？
- [ ] 跷跷板双向推演：银行/半导体同向持仓是否做了双向推演？
- [ ] 高开增量资金检查：预判高开的标的，是否回答了"增量资金从哪来"？
- [ ] 超跌反弹条件检查：连续暴跌≥2日的标的，是否强制检查了四条件？

### 4.2 关键时间节点
- [ ] 宏观数据公布时间是否与A股交易时段对齐（美东8:30=北京20:30/21:30≠盘中）？
- [ ] 核心关注时间表中时段划分是否合理（开盘30分钟/上午尾盘/午后/尾盘）？
- [ ] 今日特殊事件（CPI公布、长鑫IPO、空天大会等）是否在时间表中标注？

### 4.3 数据覆盖完整性
- [ ] 美股六大板块龙头股是否全部取到？
- [ ] 日韩关键指标（日经/KOSPI/三星/SK海力士/汇率）是否全部覆盖？
- [ ] 持仓逐只预测是否全部完成（无遗漏标的）？

## 五、格式与表达

- [ ] 表格是否对齐？缺失单元格是否已补齐？
- [ ] 数字格式是否统一（小数位数、百分号、单位）？
- [ ] 标记符号是否一致（⚠️ 🔴 🟠 🟡 🟢 🔥 🔸 ▪ 🆕 📌 ✅）？
- [ ] 引用路径是否正确（如 `my_doc/每日复盘/经验.md`）？

## 六、常见错误模式

| 错误类型 | 典型表现 | 预防方法 |
|----------|----------|----------|
| 昨收混用 | 收盘复盘用了早盘取数时的"现价"而非昨收 | 强制核对数据源昨收一致性 |
| 方向性矛盾 | 建仓评分说"回避"但持仓预测说"加仓" | 跨步骤一致性检查 |
| 单位误读 | 北向资金"万元"当作"亿元" | 检查数值量级合理性 |
| 时间盲区 | 美东时间数据误判为盘中可用 | 强制确认数据公布北京时间 |
| 线性外推 | 美股板块涨X%→预测A股涨X% | 检查是否应用了传导阈值(>3%)和脱敏规则 |
| 公式错误 | 用(今开-昨收)/今开代替涨跌幅 | 核对计算公式 |
| 代码混淆 | 159227(航空航天)被写成"恒生科技ETF"，或其他ETF代码名称张冠李戴 | **强制机械化校验**：staging 生成后必须用 Python 脚本逐代码比对 `config/持仓.md` 的权威映射。禁止纯人工目视检查——同一 AI 既写又查，写错必然查不出 |
| 漏标数据时点 | 报告用到了收盘数据但标注"盘中" | 确认每个数据段的时点 |
| 文件存在性凭推理 | 报告声称"每日信号.md不存在"但文件实际存在，跳过了整个信号复盘 | 文件存在性声明前必须执行 bash test -f 验证 |
| 早盘执行状态误判 | 早盘分析已执行（task_state=completed+报告齐全），但复盘标注"未执行" | 三重检测：task_state+早盘报告+每日信号，任一满足=已执行 |
| 持仓同步顺序错误 | 复盘先写报告后同步持仓，导致报告使用旧持仓数据 | 持仓同步必须在报告输出前完成 |

## 七、审阅后修正原则

1. **修正优先级**：数据错误 > 逻辑矛盾 > 遗漏项 > 格式问题
2. **修正后复验**：每次修正后，至少回看涉及段落上下文3-5行，确认无附带错误
3. **不确定时标注**：无法确认的数据点标注"待核实"而非删除或猜测
4. **修正不引入新错**：修改一个数字时，同步检查报告中其他用到该数字的地方

## 八、每日信号审阅清单

> 本节用于每日信号生成和评价的质量把关。早盘生成信号后审阅生成质量，复盘评价信号后审阅评价质量。

### 8.1 信号生成审阅（早盘报告完成后）

- [ ] 信号是否从早盘分析中正确提取？有无遗漏关键操作建议（如清仓建议写在了报告正文但未提取为信号）？
- [ ] 每条触发条件是否可量化？（禁止："成交量减少" → 必须："成交量萎缩至前日60%以下"）
- [ ] P0信号是否 ≤ 3条？P0信号是否真的"必须执行"？（滥用P0会稀释优先级）
- [ ] 每条信号是否标注了有效时段？（无有效时段 = 无法判断是否过期）
- [ ] 跨品种约束（北向一票否决等）是否作为独立信号存在，而非嵌在备注中？
- [ ] 信号总数是否在 5-10 条范围内？

### 8.2 信号评价审阅（复盘报告完成后）

- [ ] 每条信号是否都给出了决策质量和执行质量评价？
- [ ] 未执行信号的"未执行原因"是否记录？（用户主动放弃 / 触发条件不满足 / 忘记 / 市场变化导致取消）
- [ ] 是否存在"信号方向正确但评价过低"或"方向错误但评价过高"的偏差？
- [ ] 信号遗漏检测是否完成？（三问：未识别信号？被错误取消？触发条件设计缺陷？）
