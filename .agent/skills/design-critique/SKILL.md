# Design Critique — 设计评审与打磨工作流

设计不是一次完成的——它是迭代出来的。本技能提供从**评审→诊断→打磨→极致化**的完整工具链。

**核心原则：Critique before Polish, Audit before Ship.**

---

## 一、命令体系

### 1.1 `/critique` — UX 设计评审

从用户视角审视界面，回答三个问题：

```
评审维度：
├── 层次清晰度：视觉层级是否 ≤ 3 层？用户3秒内能否理解？
├── 信息优先级：最重要的操作是否最显眼？
├── 情感共鸣：界面给人的"感觉"是否符合产品定位？
├── 认知负担：是否有不必要的选择/文字/元素？
├── 操作可达性：核心操作是否在拇指区/视线热区？
└── 品牌一致性：视觉语言是否与品牌匹配？

输出格式：
✅ 做得好的（3点）
⚠️ 可以改进的（3点，按优先级排序）
❌ 需要修复的（如果有）
```

### 1.2 `/audit` — 技术质量检查

从工程视角检查界面实现质量：

```
检查清单：
├── 无障碍（a11y）
│   ├── 对比度是否达标（4.5:1 正文 / 3:1 大文本）
│   ├── 焦点环是否可见
│   ├── 语义化 HTML 是否正确
│   └── 屏幕阅读器能否理解内容
├── 响应式（responsive）
│   ├── 320px 是否可用（最小支持宽度）
│   ├── 768px 布局是否合理
│   ├── 1024px+ 是否充分利用屏幕
│   └── 横屏/竖屏是否都正常
├── 性能（performance）
│   ├── 字体加载是否有 FOUT/FOIT
│   ├── 图片是否优化（webp、srcset、lazy）
│   ├── 动画是否使用 GPU 加速属性（transform/opacity）
│   └── 是否有布局偏移（CLS）
├── 交互完整性
│   ├── 所有交互元素是否覆盖完整状态矩阵
│   ├── 加载/空/错误状态是否都有设计
│   ├── 文本溢出是否有处理（ellipsis/line-clamp）
│   └── 键盘导航是否可用（Tab/Enter/Escape）
└── 代码质量
    ├── CSS 是否有冗余/未使用的样式
    ├── 类名是否有意义（不是 .box1 .red-text）
    └── 是否使用了语义化颜色 Token 而非硬编码色值
```

### 1.3 `/polish` — 打磨对齐

将界面从"功能可用"提升到"设计精良"：

```
打磨步骤：
1. 字体：标题/正文对比是否明显？字号阶梯是否协调？
2. 间距：元素间间距是否一致（8px 基准）？呼吸感是否足够？
3. 对齐：所有元素是否严格对齐网格？有无"差1px"的偏移？
4. 色彩：灰色是否带色相？暗色模式下文本是否过亮？
5. 阴影：阴影深度是否与海拔层级一致？
6. 圆角：圆角是否全局一致（不要混用 4px 和 8px）？
7. 过渡：hover/active 状态过渡是否平滑（150-200ms）？
8. 微文案：按钮/标签/提示文字是否简洁有力？
```

### 1.4 `/animate` — 动效增强

为界面添加有目的的动效：

```
动效层次（由低到高）：
1. 基础层：hover 色变过渡 + 按钮按下反馈
2. 入场层：列表逐项 stagger 入场（每个延迟 50-80ms）
3. 滚动层：元素视口 reveal（translateY 20px → 0 + opacity 0 → 1）
4. 叙事层：页面切换有意义过渡 + SVG 路径绘制
5. 极致层：鼠标跟随 + 视差 + 粒子效果

规则：
- 使用 cubic-bezier(0.16,1,0.3,1) 作为默认缓动
- 入场动画不超过 500ms
- 禁止 bounce/elastic 缓动
- 尊重 prefers-reduced-motion
```

### 1.5 `/typeset` — 字体修正

修复字体问题：

```
检查项：
1. 标题字体是否有"特征"？（不要用 Inter/系统字体做标题）
2. 标题与正文是否有明显字体对比？
3. 字号阶梯是否使用标准化比例（1.25 major-third）？
4. 行高是否合适（标题 1.2-1.3，正文 1.5-1.7）？
5. 字重是否表达正确层级（标题 bold/正文 regular/辅助 light）？
6. 中英文混排是否有合理的间距？
7. 数字/数据是否使用等宽/tabular-nums？
```

### 1.6 `/colorize` — 色彩优化

```
检查项：
1. 是否存在纯灰 #808080 系列？→ 灰色加色相偏移
2. 是否存在紫色→蓝色渐变？→ 替换
3. 彩色背景上是否用了灰色文本？→ 使用半透明白/深色
4. 暗色模式文本是否用纯白？→ 降至 rgba(255,255,255,0.85)
5. 品牌色是否有完整的 50-950 阶梯？
6. 语义色（成功/警告/危险/信息）是否区分清晰？
7. 暗色模式下色彩是否"刺眼"？（降低饱和度）
```

### 1.7 `/delight` — 愉悦感

在不牺牲可用性的前提下添加愉悦时刻：

```
手法：
1. 微妙 hover 动效（按钮 1.02x 放大 + 阴影提升）
2. 成功反馈动画（checkmark 绘制、短暂庆祝色）
3. 加载状态趣味化（品牌元素替代通用 spinner）
4. 空状态插画/趣味文案（而非空白页面）
5. 彩蛋交互（长按/连续点击的隐藏反馈）

原则：愉悦感是加分，不是干扰。不能增加等待时间。
```

### 1.8 `/overdrive` — 极致效果

推动设计达到最高水准（仅用于关键页面）：

```
方向（选1-2个）：
├── 3D 元素：Three.js/Spline 嵌入
├── Canvas 粒子：品牌色粒子背景
├── 文字效果：逐字动画/渐变文字/SVG 遮罩
├── 视差多层：前景/中景/远景 3 层视差滚动
├── WebGL 滤镜：图像着色器效果
├── 自定义光标：品牌化光标样式
└── 音频反馈：微交互音效（需用户允许）

警告：这些效果会增加加载体积和复杂度，仅用于品牌站/落地页等场景。
```

### 1.9 `/harden` — 健壮性加固

确保界面在各种边界条件下正常工作：

```
加固维度：
├── 内容边界
│   ├── 文本超长（3x 预期长度）
│   ├── 文本超短（空/单字）
│   ├── 数字溢出（超大数字、负数、0）
│   └── 特殊字符（emoji、RTL文字、URL）
├── 布局边界
│   ├── 极窄容器（200px）
│   ├── 极宽容器（2560px）
│   ├── 动态字体缩放（用户设 200% 字体大小）
│   └── 无图片（图片加载失败时的 fallback）
├── 状态边界
│   ├── 快速连续点击
│   ├── 网络断开/恢复
│   ├── 离线缓存
│   └── JS 禁用（是否有 noscript fallback）
└── 国际化
    ├── 德语/芬兰语等长单词
    ├── 中文/日文换行规则
    └── 日期/数字格式化
```

## 二、44 条反模式检测规则

**每次完成前端代码后必须自动运行以下检测：**

### 色彩反模式（10条）
| # | 反模式 | 正确做法 |
|---|--------|---------|
| 1 | 紫色→蓝色渐变 | 品牌色渐变或纯色 |
| 2 | 纯灰 #808080 系列 | 灰色带色相偏移（蓝灰/紫灰/暖灰） |
| 3 | 彩色背景上灰色文本 | 半透明白色或深色 |
| 4 | 暗色模式纯白 #fff | rgba(255,255,255,0.85) |
| 5 | 暗色模式高饱和色 | 暗色模式下降饱和度 30% |
| 6 | 纯黑 #000（非暗色背景） | #111 或 #1a1a1a（带色相） |
| 7 | 青色+暗色背景（AI cliché） | 品牌色替代 |
| 8 | 单色无层次 | 至少 3 个 Surface 层级 |
| 9 | 对比度不足（灰色文本） | 检查 4.5:1 标准 |
| 10 | 语义色混淆（红=成功） | 绿=成功/红=危险/黄=警告 |

|---|--------|---------|

| 13 | 标题/正文无对比 | 衬线标题 + 无衬线正文 |
| 14 | 字号阶梯随意 | 使用 major-third (1.25) 比例 |

### 布局反模式（8条）

## 三、典型工作流

### 新建 → 评审 → 打磨
```
1. 完成前端代码
2. 运行 /audit（技术质量）
3. 运行 /critique（UX 评审）
4. 修复发现的问题
5. 运行 /polish（打磨对齐）
6. 再次 /audit 确认
```

### 已有页面 → 提升
```
1. 运行 /critique 找到改进点
2. 依次运行：/typeset → /colorize → /animate → /polish
3. 对关键页面追加 /delight
4. 最终 /harden 加固
```

### 反模式扫描（快速）
```
直接运行 44 条反模式检测
→ 输出带 ✅/⚠️/❌ 标记的检查结果
→ 针对 ❌ 项给出具体修复代码
```

---

**记住：不要一次性用所有命令。选最需要的 2-3 个，深度执行。**
