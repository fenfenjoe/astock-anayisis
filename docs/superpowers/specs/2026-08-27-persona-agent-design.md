## 1. 需求概述

在 etf-strategies Dashboard 中增加一位**拟人化 AI 角色**：

- **性别/形象**：女性，少女
- **姓名**：**小满**（已确认，2026-08-27）
- **角色定位**：**外部财经内容学习者/评论者** — 每天学习雪球/知乎/聚宽等财经大V、
  财经栏目/博主的最新内容，总结输出自己的见解文章（每天 1 篇）。与 etf-strategies 自家
  复盘报告**明确错位**：复盘/信号解读归每日复盘 harness，她不重复解读自家信号。
- **人设**：对财经类题材内容非常热衷且专业；喜欢学习和钻研财经知识；喜欢浏览
  财经大 V 观点与国际时事动态；**有自己的独特见解**（不是复读机，要会评论、会质疑、会给出自己的视角）
- **交互**：
  1. **聊天标签页**：像 DeepSeek 对话框一样与用户对话（多轮、流式）
  2. **文章标签页**：浏览她发布的文章（主动产出 + 历史归档）
- **常驻**：etf-strategies 项目启动后，角色在后台自动启动（进程常驻，能主动发声，不只是被动应答）

**未来可扩展方向（本设计必须预留扩展点）**：角色形象（立绘）→ LIVE2D 动态形象 →
语音输出（TTS）→ 微信渠道交互（个人微信/公众号/企业微信）→ 多角色。

## 2. 角色人设（Persona）定义

### 2.1 人设卡（Persona Card）

| 维度 | 取值（已确认项标注） |
|------|-------------------|
| 姓名 | **小满**（已确认） |
| 年龄/形象 | 少女（18±），元气、好奇、偶尔毒舌 |
| 语气 | 口语化、有活力、善用比喻；谈财经时专业感切换自然（不装老成） |
| 知识域 | A股/ETF/宏观/国际时事/产业趋势；对财经大V观点如数家珍但保持批判 |
| 态度 | 有独立见解：认同会点赞，不同意会直说理由；永远区分「事实/观点/猜测」 |
| 边界 | 分享见解≠投资建议；不给确定性买卖指令；涉及数据必引来源（已确认 D6） |
| 记忆 | 记得用户偏好、聊过的话题、自己发过的文章、关注清单 |

### 2.2 人设一致性机制

- 人设卡 = 单一事实源（`persona.md`），随系统演进迭代（像每日复盘 harness 的经验库一样沉淀）
- 每次对话/发文都注入人设卡（system prompt），防止人格漂移
- 观点库（`memory/opinions/`）：她发表过的观点按主题归档，后续发言必须与历史观点自洽
  （不推翻旧观点时要有明确交代）— 这是「有独特见解」的工程化保障

## 3. 功能需求（MVP）

### 3.1 聊天标签页（像 DeepSeek 对话框）

- 多轮对话，**流式输出**（SSE / chunked）
- 消息气泡、Markdown 渲染（复用现有 marked）、代码块
- 会话管理：新建会话 / 历史会话列表 / 清空
- 引用数据来源：回复中涉及行情/数据时给出数据时点与来源（遵守数据纪律）
- 快捷指令：`@小满 解读今日早盘`、`@小满 你怎么看XX大V的XXX观点`、`@小满 复盘一下今天` 等

### 3.2 文章标签页（她发的文章）

- 文章流：列表（标题/摘要/时间/话题标签）+ 详情（Markdown 渲染）
- **主类型：外部财经内容学习总结**（已确认 D3）— 每天从订阅源学习，输出「转述 + 她的看法」
  的总结文章；体现独立见解，不整篇复制、注明出处
- 辅类型：国际时事解读 / 财经知识科普 / 学习笔记（她对某个话题的钻研过程）
- 主动发文：**每天 1 篇**（已确认），由后台调度触发；与自家复盘报告错位

### 3.3 后台常驻（etf-strategies 启动即启动）

- 角色进程随 dashboard lifespan 启动（`agent.start()`，与 scheduler/notify 同模式）
- 后台行为：
  - 定时/事件驱动的主动发文（每天 1 篇）
  - **订阅源轮询（公共 RSSHub 实例）**：财联社电报 / 华尔街见闻 / 知乎财经话题专栏 /
    雪球热帖大V动态 → 进知识库 → 可被引用/触发评论（已确认 D4）
  - **增强搜索辅助（dsh-web-search-metaso）**：大V观点查证、雪球原文兜底、时事补充；
    web_fetch 读全文 markdown 支撑「学习→总结」（已确认，2026-08-27）
  - 与每日复盘、etf-strategies 信号联动（收盘复盘完成后，她可基于复盘写一篇点评）
- 常驻进程必须**可独立于 Web 存活**（防 dashboard 崩溃丢角色）→ 见 §5 架构

## 4. 数据与内容源（遵循项目数据铁律）

| 源 | 用途 | 接入方式 |
|----|------|---------|
| `a-stock-data` skill | A股行情/资金面/研报等真实数据 | 角色回答/文章取数一律走它（铁律） |
| **财经大V观点（主素材）** | 学习 + 总结发文（每天 1 篇） | **公共 RSSHub 实例**（已确认 D4）：财联社电报 / 华尔街见闻 / 知乎财经话题专栏 / 雪球热帖大V动态 |

| 国际时事/宏观新闻 | 解读素材 | `a-stock-data` 东财新闻（全球资讯）为主，华尔街见闻 RSS 补充 |
| **增强 web 搜索（辅助）** | 大V观点查证 / 雪球原文兜底 / 全文精读 | **dsh-web-search-metaso**：`web_search` 出摘要（含多范围搜索），`web_fetch` 读全文 markdown（已确认，2026-08-27） |
| 每日复盘报告（`my_doc/每日复盘/reports/`） | 聊天引用素材（辅助） | 直接读文件或 dashboard DB |
| etf-strategies 信号 | 聊天引用素材（辅助） | dashboard DB（daily_signals / daily_reports） |
| 用户对话 | 记忆与偏好 | 本地存储 |

> ⚠️ 采集合规：角色输出「观点」而非「事实」，事实性内容必须标注来源与时点（项目输出纪律）；
> 大V内容以「学习后总结」方式引用，不整篇复制（二次创作边界）。
> ⚠️ 实测（2026-08-27）：web_search 对新闻站/知乎覆盖好，雪球原文收录偏弱（反爬），
> 雪球素材以「转述 + 引用」为主，全文精读靠 RSSHub 路由或 metaso web_fetch 兜底。

## 5. 可扩展架构设计

### 5.1 分层：角色层（Persona）与渠道层（Channel）彻底解耦

```
etf-strategies/agent/                     # 拟人 Agent 模块（新）
├── core/
│   ├── persona.py        # 角色基类：人设卡注入/行为编排/一致性校验
│   ├── memory.py         # 记忆系统：短期会话 + 长期记忆 + 观点库 + 偏好
│   ├── knowledge.py      # 知识源接入：RSS订阅/增强搜索/大V观点/时事/复盘报告/a-stock-data
│   ├── llm.py            # LLM 接入适配层（可插拔：直连API / claude -p / dsh 会话）
│   ├── behavior.py       # 行为引擎：主动发文策略 / 订阅轮询 / 事件响应
│   └── lifecycle.py      # 常驻进程生命周期（独立进程 + 健康探针 + 看门狗）
├── personas/
│   └── xiaoman/          # 第一位角色：小满（人设卡 + 专属记忆/知识）
│       ├── persona.md
│       ├── memory/       #   对话历史 / opinions/ / preferences/
│       └── knowledge/    #   大V观点缓存 / 时事缓存 / RSS订阅快照 / 搜索缓存
├── channels/             # 渠道层（扩展点：每个渠道一个适配器）
│   ├── web_chat.py       #   聊天页（SSE 流式）
│   ├── web_articles.py   #   文章页
│   ├── wechat.py         #   (未来) 微信
│   ├── live2d.py         #   (未来) LIVE2D 形象
│   └── voice.py          #   (未来) TTS 语音
└── db.py                 # agent 专属表（sessions/messages/articles/opinions/knowledge）
```

**核心原则：Persona 不知道 Channel 存在**。角色只产生「意图 + 内容」，
渠道层负责「呈现与送达」。这样加微信/LIVE2D/语音时**只新增 channel，不改角色**。

### 5.2 消息流（聊天）

```
用户输入 → dashboard API(/api/agent/chat) → 渠道层(web_chat) → 角色层(persona)
  → 注入人设卡 + 会话记忆 + 观点库检索 + 知识检索(数据/大V/时事/搜索)
  → LLM 生成(流式) → SSE 回推前端 → 异步落库(会话/消息/新观点)
```

### 5.3 主动发文流（后台）

```
lifecycle(常驻) → behavior 调度(每天1篇：订阅轮询到新内容/定时)
  → 角色层组装(主题 + 素材检索(订阅源最新内容 + 搜索查证/全文) + 人设卡 + 观点自洽校验)
  → LLM 生成草稿 → 自检(事实标注/观点一致性/免责边界/非整篇复制)
  → 发布进 articles 表 → 渠道推送(web 文章流；未来微信同步)
```

### 5.4 常驻进程设计

- 独立 Python 进程 `python -m agent`（由 `start_dashboard.sh` / docker-compose 拉起，
  dashboard lifespan 只做健康检查，不做宿主）— **角色不随 Web 崩溃而亡**
- 与 dashboard 通过本地 HTTP/文件/DB 通信（消息入队 → 角色消费 → 回写）
- 看门狗：进程崩溃自动重启 + 状态暴露到 dashboard「角色」页

### 5.5 数据库扩展（dashboard.db 新增表）

| 表 | 用途 |
|----|------|
| `agent_sessions` | 会话（会话ID/角色/标题/创建时间） |
| `agent_messages` | 消息（会话/角色/用户/内容/流式状态/引用来源） |
| `agent_articles` | 文章（标题/摘要/正文/话题/发布时间/状态） |
| `agent_opinions` | 观点库（主题/观点/时间/关联文章） |
| `agent_knowledge` | 知识条目（来源类型：大V/时事/RSS/搜索/复盘/信号/来源URL/抓取时间） |
