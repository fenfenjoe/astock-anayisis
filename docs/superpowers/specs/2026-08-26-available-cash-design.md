# 建仓份额计算设计 — 可用金额引入

> 日期：2026-08-26 | 状态：已批准（用户逐节确认）
> 范围：每日复盘 harness 的信号生成 + 持仓同步链路
> 方案：A（逻辑全下沉 lib，prompt 只调用渲染）

## 1. 背景与问题

**问题：未持仓标的（新开仓/建仓）生成信号时，系统无法计算应买入的份额。**

- 已持仓标的的做T/减仓份额可计算：`比例 × 持仓数量`（如 7,900份 × 1/4 = 1,975份，数据源 `config/持仓.md`）。
- 未持仓标的的建仓信号无任何锚点：模板只有 `观察/半仓试探/1,000份` 这类经验值，没有"总资金 × 比例"的公式。
- 后果：建仓信号仓位列写 `观察`（=0份），被 2026-08-26 的"无份额不追踪收益"策略（signal_tracking.py）正确排除在收益追踪之外——但份额本身就该能被算出来，而非永远缺失。

**用户方案**：在 `每日调仓.md` 增加 `## 0. 可用金额`（已添加，当前 25,701 元），系统生成份额时读取剩余资金。

## 2. 目标与非目标

### 目标
1. 可用金额沿 `每日调仓.md → config/持仓.md → staging → 早盘分析` 全链路传递，config/持仓.md 为唯一权威。
2. 建仓信号份额 = `可用金额 × 分级比例 / 价格`（100 份整数取整），分级按信号置信度。
3. 可用金额与当日调仓自动交叉验证，偏差告警（不阻塞）。

### 非目标
- 不做自动记账（可用金额仍由用户手动维护，系统只读取+验证）。
- 不改动已持仓标的的做T份额计算（沿用 `比例 × 持仓数量`）。
- 信号生成语义判断仍走模板层，不代码化（只把份额计算下沉 lib）。

## 3. 核心设计决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 建仓比例 | **分级**：P1 直接建仓=可用金额 1/3；观察升级建仓=1/4；试探/低置信=1/5 |
| config 存储 | 顶部独立行 `可用金额: 25701 元`（注释与持仓表之间） |
| 交叉验证 | 自动：期望新值 = 旧值 + Σ卖出 − Σ买入，偏差>容差(1元)告警不阻塞 |
| 份额用价 | 早盘生成用**昨收**估算；触发后收益追踪仍用盘中验证 `现价` 为入场价 |
| 实现形态 | 逻辑下沉 `lib/position_sync.py`（纯函数+TDD），prompt 只调用渲染 |

## 4. 数据格式约定

### 4.1 每日调仓.md（用户维护，现状保持）

```
## 0. 可用金额

25701
```

解析规则：`## 0. 可用金额` 小节标题后首个数字行，支持 `25,701` 千分位。

### 4.2 config/持仓.md（同步脚本写入）

```
# 当前持仓

> 本文件由每日复盘自动同步自 每日调仓.md，反映最新持仓状态。
> 最后更新: 自动同步
可用金额: 25701 元

| 股票名称 | 代码 | 持仓数量（份） | 成本价（元） |
...
```

放在注释与表格之间。所有现有解析器（代码-名称校验 `staging_verify.check_etf_code_names`、D1、staging 校验）只认 6 位代码表格行，此行天然安全（已验证）。

### 4.3 信号表仓位列（建仓信号输出格式）

```
| ... | 建仓 | ... | 2,000份(可用×1/3) | SIG-... |
```

- 份额 = `calc_position_shares` 结果（100 份整数）。
- 资金不足 100 份 → 写 `资金不足`（=0份，不追踪）。
- 追踪收益的 `_parse_quantity` 可解析 `N份(...)` 格式（正则 `([\d,]+)\s*份`）。

## 5. lib/position_sync.py 设计

三个纯函数，不读写磁盘、不调用外部 API（与 signal_tracking.py 同构）。

```python
# 建仓份额分级比例（信号置信度越高仓位越大）
POSITION_RATIOS = {
    'open_high': 1/3,   # P1 直接建仓（高置信）
    'upgrade': 1/4,     # 观察→升级建仓（盘中）
    'probe': 1/5,       # 试探/低置信
}

def parse_available_cash(md_text: str) -> int | None:
    """解析每日调仓.md 的 `## 0. 可用金额` → int；缺失/非数字 → None"""

def verify_cash_change(old_cash: float, new_cash: float,
                       trades: list[dict], tolerance: float = 1.0) -> list[str]:
    """交叉验证：期望新可用金额 = 旧值 + Σ卖出额 - Σ买入额；
    实际与期望偏差 > tolerance → 返回告警（不抛异常）。
    trades: [{'direction': '买入'|'卖出', 'qty': int, 'price': float}]"""

def calc_position_shares(available_cash: float, price: float, ratio: float) -> int:
    """建仓份额 = floor(可用金额×比例/价格/100)×100（ETF 100份整数）；
    价格≤0 / 可用金额≤0 / 比例≤0 / 不足100份 → 0"""
```

## 7. 边界处理

| 情况 | 行为 |
|------|------|
| 每日调仓.md 可用金额缺失/非数字 | 同步脚本 WARN **不中止**（持仓同步必须完成），config 保留旧值；早盘建仓信号标"可用金额未知，暂不定份额" |
| 交叉验证偏差 > 容差（默认 1 元） | 告警提示"可能漏记交易或金额未更新"，不阻塞 |
| 算出资额 < 100 份 | 仓位列写"资金不足"（=0份，不追踪） |
| 现价缺失 | 无法算份额，标"待盘中现价确认" |

## 8. 测试清单（TDD 先行）

- `parse_available_cash`：正常 `25701` / 千分位 `25,701` / 缺失→None / 非数字→None
- `verify_cash_change`：无交易值不变→无告警 / 今日买入→期望减少一致 / 今日卖出→期望增加一致 / 偏差>容差→告警 / tolerance 参数生效
- `calc_position_shares`：25,701×1/3÷昨收→100份整数取整 / 不足100份→0 / price=0、cash=0→0
