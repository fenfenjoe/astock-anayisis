# 每日信号模块优化设计 — 信号质量闭环

> 日期：2026-08-26 | 状态：已批准（用户逐节确认）
> 范围：每日复盘 harness 的信号生成 + 监控闭环
> 方案：C（混合）— 生成靠模板优化 + 监控靠代码

## 1. 背景与问题

每日信号模块（早盘生成 → 盘中验证 → 复盘评价）存在两个结构性问题：

**问题 1：触发率低，信号参考意义不大。**
- 8/25 的 9 条信号 0 触发 0 执行，7 条过期（连续多日"0 触发 0 执行"）。
- 根因：信号"重验证轻机会"——大部分信号是验证型（防御线确认/农业延续/反抽观察），本质是验证早盘已预判的结论，触发率天然趋近 0。

**问题 2：无触发后监控机制，无信号质量检查闭环。**
- `signal_tracking.json` 只有 2 条信号、最后更新停在 2026-08-18（停摆 8 天）。
- 根因：追踪依赖"已触发"信号，触发率≈0 导致空转；统计逻辑散落在 prompt 中，无强制驱动、无量化质量指标。

## 2. 目标与非目标

### 目标
1. 信号从"8 条低触发率验证雷达"改为"**4-6 条高价值短线机会信号**"（P0 风控 ≤3 + P1 操作 2-4）。
2. 建立完整监控闭环：触发入库 → 目标价结算 → 质量仪表盘 → 周报 → 校准回流。
3. 全部质量指标**自动化计算**（A 层 8 项，无人工依赖：触发率/目标达成率/平均达标天数/平均盈亏比/单笔最大亏损/方向准确率/预期vs实际偏差/信号期望价值）。

### 非目标
- 不改动持仓/板块扫描/做T 等其它 harness 模块。
- 不做 B 层指标（执行率/执行偏差/误漏触发分类）——等用户操作列有数据积累后再加。
- 信号生成不代码化（保留 LLM 语义判断，走模板层）。

## 3. 核心设计决策（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 信号定位 | 机会型为主，少而精（4-6 条） |
| 优化范围 | 生成优化 + 监控闭环都做 |
| 观察信号（P2 雷达）| **完全移除信号表** → 早盘报告新增"关注列表"章节 |
| 监控形态 | 复盘内嵌质量仪表盘 + 周度信号质量周报 |
| 触发率目标 | P1 周触发率 ≥40%；每月 ≥5 条实际触发并执行 |
| 指标集 | A 层 8 项自动指标 + C 层校准（紧急度/优先级）|
| 结算模式 | **目标价达成判定**（非恒定 T+3 卖出）|
| 周报时点 | 下周三收盘后（上周全部信号 T+3 结算完成）|

## 4. 信号生成优化（模板层）

### 4.1 新信号表结构

```
| 优先级 | 标的 | 触发条件 | 操作类型 | 状态 | 方向 | 紧急度 | 预期触发率 | 目标/止损 | 有效时段 | 仓位 | 信号ID |
```

- **新增列**：
  - `预期触发率`：P0 填"—"（不考核）；**P1 必填百分比**（生成时估计，复盘校准）
  - `目标/止损`：格式 `目标+3%/止损-2%`（或显式目标价，如 `目标1.75/止损1.66`）；P1 必填目标，止损推荐
- **删除列**：升级条件、预期收益日、操作来源、生成依据（观察信号移除后不再需要；来源信息移到信号表下方注释）

### 4.2 信号构成（每天 4-6 条）

| 类型 | 数量 | 特性 |
|------|------|------|
| P0 风控 | ≤3 | 普跌否决/黄金守位/科技回避等纪律。**不考核触发率**（不触发=市场安全）|
| P1 操作 | 2-4 | 高置信度短线操作（正T/减仓/建仓/锁利）。**考核触发率 + 目标达成率** |

### 4.3 P1 信号生成规则（写入模板第九节）

1. **双向设计**：每条 P1 = 触发路径（明确价位/量能+仓位+时段）+ 证伪路径（什么情况说明早盘判断错→信号作废）。杜绝"既不触发又无信息量"。
2. **必填预期触发率**：生成时估计（如 40%）。
3. **必填目标/止损**：短线止盈目标（目标收益率或显式目标价）+ 止损线。
4. **短线定位**：所有 P1 按目标价结算口径设计（快进快出）。
5. **验证型判断禁止进信号表**（防御延续/农业延续/反抽观察等 → 报告正文 + 关注列表）。

### 4.4 新增"关注列表"章节（早盘报告内，非信号表）

- 观察雷达全部移入此处，含量化升级条件（沿用现有 `方向确认>Xmin+{阈值}→升级为...` 格式）。
- 盘中 Tier 1/2 发现满足 → **临时追加信号**（操作来源="盘中信号"），不预先占信号名额。

## 5. 目标价结算模式（核心变化）

### 5.1 结算规则（触发后 T+3 交易日内）

| 情形 | 判定 | 结算口径 |
|------|------|---------|
| 收盘价达到目标价 | **达标** | 按目标价结算 P&L；持有天数=达标日−触发日 |
| 未达目标，T+3 到期 | **未达标** | 按 T+3 收盘价结算（可能正/负）|
| 触发止损价（可选）| **止损** | 按止损价结算（提前退出）|

### 5.2 为什么不用恒定 T+3 卖出

短线正T"第 2 天到目标、第 3 天回落"被恒定卖出误判为亏损；目标价模式按实际交易逻辑（到目标就止盈）结算，并自然生成"目标实现速度"维度。

## 6. 监控闭环（代码层）

### 6.1 修复并强制驱动 signal_tracking.json

- 复盘 prompt 增加**强制入库步骤**：`parse_signal_markdown → merge_new_signals → 写盘`（复用 `lib/signal_tracking.py` 现有函数）。
- `settle_due_signals` 改为目标价结算模式（见 §5.1）；P0 风控信号不结算（纪律无 P&L）。

### 6.2 新增 lib/signal_quality.py（纯函数，不读写磁盘）

```python
calc_trigger_rate(signals, priority=None)        # 触发率（P1 分层，周/累计）
calc_target_hit_rate(settled)                    # 目标达成率 = 达标 ÷ 已结算（函数仅接收 settled）
calc_avg_hit_days(settled)                       # 平均达标天数（快进快出验证，目标1-2天）
calc_avg_profit_loss_ratio(settled)              # 平均盈亏比 = 平均盈利单 ÷ 平均亏损单（按 pnl 正负，非 outcome）
calc_direction_accuracy(settled)                 # 方向准确率（buy: settle≥entry; sell: settle≤entry）
calc_expected_vs_actual(signals)                 # 预期触发率 vs 实际触发率偏差（avg_gap=实际−预期均值, 负=偏乐观）
calc_signal_expected_value(settled)              # 信号期望价值 = 平均单次 P&L（触发率在仪表盘单独显示）
calc_max_loss(settled)                           # 单笔最大亏损（短线风控，min pnl）
generate_quality_dashboard(signals, settled, price_lookup, today)  # 汇总为仪表盘数据
```

### 6.3 结算数据流（复盘时）

解析已触发信号 → 入库 → 腾讯财经拉 T+3 收盘价（含 T+3 日内每日收盘价用于达标判定）→ 自动结算 → 生成仪表盘数据 → 渲染到复盘报告。

## 7. 复盘内嵌质量仪表盘 + 周报

### 7.1 复盘 2c 扩展为"信号质量仪表盘"

| 维度 | 指标 | 阈值/目标 |
|------|------|----------|
| 触达 | P1 触发率（周/累计）| ≥40% |
| 结果 | 目标达成率 | ≥50% |
| 结果 | 平均达标天数 | 1-2 天 |
| 结果 | 平均盈亏比 | ≥1.5 |
| 结果 | 单笔最大亏损 | 风控线 |
| 方向 | 方向准确率 | ≥60% |
| 校准 | 预期 vs 实际触发率偏差 | ±20pp 内 |
| 价值 | 信号期望价值 | 为正 |

**预警规则**：
- P1 周触发率 <40% → ⚠️ 黄色预警 + 建议（条件过严/信号类型需调整）
- 目标达成率 <50% → 检查目标价设定是否过高
- 预期触发率系统性高估（实际 < 预期−20pp）→ 生成时下调

### 7.2 周度信号质量周报

- 产出：`reports/weekly/信号质量周报.md`
- 内容：本周指标趋势（触发率/达成率/盈亏比/期望价值）+ 信号价值排名（保留/淘汰/调整建议）+ 环比上周
- 生成时点：**下周三收盘后**（16:30，与 experience_health 12:47 错峰）——上周最晚（周五）触发的信号 T+3=下周三完成结算，数据完整

## 10. 验收标准

1. P1 信号周触发率 ≥40%（低于则仪表盘预警）。
2. 每月 ≥5 条实际触发并执行的信号。
3. signal_tracking.json 每日复盘后自动更新（不再停摆）。
4. 每日复盘报告含自动生成的信号质量仪表盘（A 层 7 项指标）。
5. 每周三收盘后生成 `reports/weekly/信号质量周报.md`。
6. 全部新逻辑有 pytest 覆盖（test_signal_quality.py + 扩展 test_signal_tracking.py）。
