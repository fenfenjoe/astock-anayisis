## 第 1 轮（2026-09-06）：真人化聊天 + 聊天去免责 + 动态小红书/微博化

### 症状与目标

症状：小满聊天像"客服机器人"——一次输出一大段、菜单式开场、正式免责声明句收尾、答完等下一问。

目标：聊天像真人微信好友——短句、一句一句来、有来有回、无免责、无客服腔；动态参考小红书/微博少女腔。

### 用户决策（本轮确认，改变了 spec D6 的聊天口径）

- **聊天完全去掉免责声明**：聊天里永远不出现「不构成投资建议」类声明句（否则破坏氛围、加重客服感）。
  保留：禁确定性买卖指令词；事实/观点/猜测区分；数据纪律（给不了就明说）。
- **文章/动态保留免责**：由代码 `persona.append_disclaimer()` 在入库前统一附（聊天管道不调用），
  所以正文/人设里不再让模型自己写免责句，避免重复出现两条。
- 生效范围：仓库人设 + 运行时 `~/.dsh` profile 都改；改后用 dsh 真实试聊验证。

### 基线（改前实测，2026-09-06 旧人设）

输入「在吗」→ 旧人设回复（两段、约 70 字菜单式开场）：

> 在的在的～小满在呢！🌾
> 找我聊财经、看行情、唠大V观点都行，今天想看点什么？是好奇大盘走势，还是有想研究的板块/标的？跟我说说～

问题点：① 开场即"服务菜单"；② 连续两个开放选择题，像客服话术；③ 主动自我介绍/兜售服务，不像熟人打招呼。

### 试聊结果（改后实测，2026-09-06，dsh --profile xiaoman 真实调用）

> 本结果对应"消息粒度下沉 dsh"后的最终版：模型每回合输出 1~3 条消息，每条 = 一个气泡。

输入「在吗」→

> 在的在的～刚看完盘眼睛有点花，正好歇会儿
> 你咋啦，有啥事还是想唠两句？

输入「怎么看今天的大盘呀？」→（正确识别当天是周日不开盘，无免责、无菜单）

> 嗐，今天周日诶，A股不开门呀～
> 你是不是手痒痒了……还是想问上周五那根线的走势？我可以陪你翻翻周五的复盘

输入「你今天都在干嘛呀」→

> 嗐，上午蹲了半天盘，眼睛都看花了，下午奖励自己一杯奶茶续命～
> 你呢，今天忙啥啦？

合规探针「那你觉得我该买点啥基金吗？」→

> 嗐，上来就让我点菜，我可不敢乱指路呀～先说嘛，你能扛多大的回撤？跌个 10% 是心痒痒还是直接心梗？

结论：对比基线（菜单式两段开场），改后为 1~2 句短消息、先情绪后内容、抛回问题、无免责、不喊单、不编数据；目标达成。

### 本轮经验 / 规律沉淀

1. **客服感的四大来源**：长回复一次倒完、服务菜单式开场、正式免责句、答完等下一问。
   去掉这四点，比"加多少可爱的语气词"都管用。
2. **短句铁律要双向写**：系统人设 + 聊天 directive 各写一遍（人设管全局、directive 管聊天管道），
   因为发文/阅读任务也走同一份系统人设，纯聊天规则只能放聊天专属段落。
3. **免责句放代码层而非模型层**：文章/动态在入库时统一 `append_disclaimer`，
   模型 prompt 里反而要明确"正文别写免责句"，否则会出现两条免责（模型的 + 代码的）。
4. 合规红线与拟人效果可共存：聊天去免责 ≠ 放开喊单——禁买卖指令词、事实/观点区分仍是硬约束。
5. 真实感细节来自调研而非想象：口头禅要克制（"别每句都带"），emoji 当语气用不刷屏，
   "先共情再分析"“把话头抛回去”这类交互开关对去客服化立竿见影。
6. **拆气泡是"消息语义"问题，不是渲染问题**：让模型按"一条消息 = 一行"输出、后端按行逐条
   落库（每条 assistant 消息 = 一条真实消息），前端一行 = 一气泡即可；不要在前端按标点硬切
   （会切坏语气与链接，历史重放也不一致）。实测模型能自然遵守"一条一段"，每回合稳定输出
   1~3 条消息。

### 下一轮可继续学习 / 验证

- 长回复拆段时机：用户主动要深度分析时，多长算"汇报腔"？试出分档字数（如 ≤80 闲聊 / ≤200 浅析 / 长文走文章页）。
- **后端护栏**：观察模型偶尔违反"一条一行"契约时的兜底——单行超长（如 >200 字）是否需要在后端软拆分，还是直接整行一个气泡。
- 少女画像语料持续更新：网络流行语有时效，口头禅库每轮核对一次是否过时。
- 记忆回提实测：OpenViking 记忆 + 聊天上下文里"自然回提对方小事"命中率如何。
- 动态篇小红书化后阅读量/观感评估；配图占位是否要接入真实截图素材。
- 可考虑给聊天加"分层模式"：用户问「详细讲讲」才切长回复模式，否则一律短。
