## 二、设计目标

1. **研究底座**：建立分钟级历史数据研究库（1min K线 + 分钟资金流 + 分钟北向），本地缓存、增量更新、多源容错，稳定支撑批量统计。
2. **描述性统计**：时间窗口画像计算（振幅/反转率/单边率/模拟胜率），输出"时间×状态"二维热力图。
3. **数据验证**：对既有做T纪律先验逐条统计验证（支持/证伪/部分支持 + 置信度），不靠感觉。
4. **归因分析**：窗口适合度的机制归因（结构/事件/状态三层），产出"机制解释 + 失效条件"。
5. **做T回测**：分钟级模拟做T回测（复用 cost.py 成本口径），样本外验证。
6. **信号增强**：早盘/盘中做T信号注入"窗口画像 + 归因依据"，让每条做T信号带数据佐证。
7. **小满可调用**：研究能力封装为小满可用的 skill/工具，聊天/分析均可触发；研究成果沉淀 OpenViking（贝叶斯更新）。
8. **Dashboard 可见**：新增"做T研究"展示（窗口热力图/归因卡片/验证结论），做T信号行展示窗口依据。
9. **不破坏现有流程**：报告产出、信号追踪、Generator-Evaluator、REQ 闭环全部继续工作。

### 3.1 核心概念 1：时间窗口画像（Window Profile）

把交易日切成**15 分钟窗口**（9:30-9:45 … 14:45-15:00，共 16 窗），对每个窗口计算一组"波动质量"指标，作为"该时段适不适合做T"的量化画像：

| 指标 | 定义 | 回答的问题 |
|------|------|-----------|
| 振幅 | 窗口内 (high-low)/pre_close | 什么时候动得大 |
| 已实现波动率 | 窗口内分钟收益 std | 波动稳定性 |
| 反转率 | 窗口内出现"先跌后涨/先涨后跌"且幅度>阈值 的天数占比 | 波动是否"可逆结构" |
| 单边率 | 窗口内单边趋势（无有效反转）天数占比 | 波动是否"纯单边"（做T危险） |
| 模拟胜率 | 窗口低点买/高点卖（假设先见之明）扣成本后盈利天数占比 | 可实现性上限 |
| 样本量 | 有效天数 | 统计显著性 |

**关键洞察**：适合做T的窗口 = **高振幅 + 高反转率 + 低单边率**。单一振幅会骗人（普跌日振幅最大但做T必亏）——这就是"波动量 vs 波动质量"的分离，是方案与"只看振幅"式分析的本质区别。

### 3.2 核心概念 2：状态分层（State Split）

时间效应**依赖市场状态**，必须做二维：**时间窗口 × 当日状态**。

| 状态 | 判定口径（可自动计算） |
|------|----------------------|
| 普涨日 | 全市场上涨家数占比 > 70% |
| 普跌日 | 全市场下跌家数占比 > 70% |
| 震荡日 | 涨跌家数接近 + 指数振幅 < 阈值 |
| 极化日 | 外盘熔断级恐慌 + 涨跌比>1:10 + 标的缺口>1.5% 单边无反弹（复用既有经验判定） |
| risk-off | 油金同涨 / 系统性普跌 / 北向大幅流出 |

状态标记从日线数据自动计算（复用 `trading_calendar.py` + 全市场涨跌家数），存入研究库按日打标。

### 3.3 核心概念 3：先验验证（Prior Validation）

对既有做T纪律逐条做统计检验，输出"先验 vs 数据结论"：

| 先验纪律 | 验证设计 |
|---------|---------|
| 开盘30分钟不操作（9:30-10:00 波动随机） | 统计 9:30-10:00 窗口反转率/单边率 vs 其余窗口；若该窗口单边率最高 → 验证支持 |
| 10:00-10:30 方向确认窗口 | 统计 10:00-10:30 V反出现条件概率 + 模拟胜率 |
| 跷跷板 9:45-10:00 提前激活 | 统计该窗口板块资金流切换频次 |
| 尾盘 14:30 后 | 统计尾盘振幅/方向持续性与隔夜溢价 |
| 外盘熔断次日 10:30 后企稳 | 事件对齐：熔断次日样本的 10:30 后企稳率 |
| 普跌日不做T | 统计普跌日各窗口模拟胜率（预期<50%） |

**输出**：每条结论标注 支持/证伪/部分支持 + 样本量 + 置信度。发现"先验与数据冲突"时按贝叶斯原则更新 OpenViking 经验（不彻底否定，调置信度）。

### 3.4 核心概念 4：归因分析（Attribution）

对高适合窗口做三层机制归因：

1. **结构机制**：窗口适合度 vs 成交量占比/U型分布/盘口厚度的相关性 → 验证"开盘竞价释放/尾盘博弈"等微观结构解释。
2. **事件机制**：日历对齐（宏观数据日、熔断次日、长假前后、北向脉冲）→ 该窗口在事件日的特征偏移。
3. **状态机制**：控制状态后窗口是否仍显著 → 分离"时间效应"与"状态效应"。

**产出物**：每个高适合窗口 = 机制解释 + **失效条件**（机制失效时窗口失效 → 直接决定策略止损与环境过滤器设计）。

## 四、详细设计

### 4.1 数据层：分钟级研究库（research.db）

**位置**：`my_doc/每日复盘/harness/automation/research/`（与 harness lib 同域，prompt 可 sys.path 引用；数据与代码分离）

```
research/
├── research.db              # SQLite 研究库（分钟K线/资金流/北向/状态标记/研究成果）
├── collector.py             # 增量收集器（盘后拉当日全量 + 补缺历史）
├── schema.sql               # 表结构
└── lib/
    ├── window_profile.py    # 窗口画像（纯函数）
    ├── prior_validation.py  # 先验验证（纯函数）
    ├── attribution.py       # 归因分析（纯函数）
    ├── t_backtest.py        # 分钟级做T模拟回测（纯函数，复用 cost.py）
    └── research_store.py    # 成果落库/读取（画像表/验证报告/归因报告）
```

**表结构（schema.sql 草案）**：

```sql
-- 分钟K线（1min，主键 code+ts）
CREATE TABLE IF NOT EXISTS minute_kline (
    code   TEXT NOT NULL,
    ts     TEXT NOT NULL,          -- 'YYYY-MM-DD HH:MM'
    open   REAL, high REAL, low REAL, close REAL,
    vol    REAL, amount REAL,
    PRIMARY KEY (code, ts)
);
CREATE INDEX IF NOT EXISTS idx_mk_code_ts ON minute_kline(code, ts);

-- 分钟资金流（主力净流入，东财 push2 分钟级）
CREATE TABLE IF NOT EXISTS minute_fund_flow (
    code TEXT NOT NULL, ts TEXT NOT NULL,
    main_net REAL,           -- 主力净流入(元)
    PRIMARY KEY (code, ts)
);

-- 北向分钟流向（同花顺 hsgt，262 时间点）
CREATE TABLE IF NOT EXISTS minute_hsgt (
    ts   TEXT NOT NULL,
    north_net REAL,          -- 北向净买入(亿)
    PRIMARY KEY (ts)
);

-- 交易日状态标记
CREATE TABLE IF NOT EXISTS day_state (
    trade_date TEXT PRIMARY KEY,
    state      TEXT,         -- 普涨/普跌/震荡/极化/risk-off
    up_ratio   REAL,         -- 上涨家数占比
    note       TEXT
);

-- 研究成果（画像/验证/归因）
CREATE TABLE IF NOT EXISTS research_outputs (
    kind       TEXT NOT NULL,     -- window_profile / validation / attribution / backtest
    asset      TEXT NOT NULL,     -- 标的代码或 'market'
    state      TEXT DEFAULT 'all',
    window     TEXT DEFAULT '',   -- '09:30-09:45' 或 ''
    payload    TEXT,              -- JSON（指标集/结论/机制）
    created_at TEXT DEFAULT (datetime('now','localtime')),
    PRIMARY KEY (kind, asset, state, window)
);
```

**收集策略**：
- 盘后任务（新增 `research_collect` 定时任务，15:20 或并入 evening_review 前置）拉当日 1min 全量 + 分钟资金流 + 北向，upsert 幂等。
- 历史补缺：首次对标的池（持仓 + 关注列表 + 备选池，建议 ≤20 只）回填 1~2 年 1min K线；mootdx `frequency=8` 每次 800 根（约 3.3 天），按日循环，失败断点续传。
- 多源容错：复用 `backtest/quote_source.py` 的 SourceHealth + MultiSourceQuote 模式（mootdx → 腾讯分时 → 百度），收集器只依赖探测结果选择路径。
- 限流纪律：东财接口走 `em_get` 串行限流（≥1s + 抖动），批量场景 1.5~2s。

> **实现修正（v1.0 Phase 1，2026-10-14 实测环境）**：
> 数据源优先级按当前网络环境实测调整为 **腾讯 ifzq mkline m1（主源）→ mootdx（备源自愈）→ 东财 push2his klt=1（备源自愈）**：
> - 腾讯 ifzq mkline m1：**稳定可用、不封 IP**，单次最大 800 根（~3.3 个交易日），无历史日期分页 → **日增量主源**（收盘后收集当日全量）。
> - mootdx TCP 7709：端口可达但 `bars()` 返回空（海外/受限网络降级，CLAUDE.md 已知问题）→ 备源，恢复后自动补缺。
> - 东财 push2his klt=1：住宅 IP 风控 `RemoteDisconnected`（自 2026-09-02 起 30+ 交易日不可达，BUG-017）→ 备源，恢复后自动补缺。
> **口径调整**：受主源能力限制，Phase 1 收集器为"**收盘后日增量积累 + 源恢复后自动历史补缺**"（`collect_progress` 表断点续传），与项目北向 CSV 自缓存"历史越跑越丰富"模式一致；不编造、不强行回填不可得的历史。`day_state` v1 用三大指数日K方向粗分（普涨/普跌/震荡），涨跌家数细分待 push2 恢复后接入。

### 4.2 计算层：窗口画像（lib/window_profile.py）

纯函数设计（TDD 可测，无 IO）：

```python
def split_windows(df, window_minutes=15) -> list[Window]
def window_amplitude(w) -> float          # (high-low)/pre_close
def window_realized_vol(w) -> float       # 分钟收益 std
def reversal_rate(windows, threshold=0.3) -> float   # 反转天数占比
def one_side_rate(windows, threshold=0.3) -> float   # 单边天数占比
def sim_t_win_rate(windows, cost=..., threshold=0.2) -> float  # 低买高卖扣成本胜率

**输出**：`window_profile` 表 payload = 每窗口 6 指标 + 样本量；聚合为热力图 JSON（16 窗口 × 状态 × 指标）。

### 4.4 计算层：归因分析（lib/attribution.py）

纯函数：
- `correlate_window_fit(window_fit, volume_ratio)` → 结构机制相关
- `event_offset(window_features, event_dates)` → 事件日特征偏移
- `state_partial(window_fit, states)` → 控制状态后显著性（简单分组对比即可，不引入重统计依赖）

输出 `attribution` 表：每高适合窗口一条 {机制, 证据, 失效条件}。

### 4.5 计算层：做T模拟回测（lib/t_backtest.py）

- 规则引擎：对候选窗口跑固定规则模拟（如"10:00-10:30 内低点买、次日/窗口高点卖"、"反T：高开>1% 后 9:45 卖、10:30 前买回"），**复用 `etf-strategies/backtest/cost.py` 成本模型**（佣金+滑点，ETF 无印花税，QDII 加溢价损耗）。
- 输出：净收益口径的窗口收益排名、样本外（后 20% 时间）验证、与先验窗口对比。
- 纪律：**净收益口径是第一铁律**——单笔收益 0.3~1%，成本占比极高，纸面振幅全部作废。

### 4.6 信号增强层：prompt 改造（增量，不破坏现有结构）

**早盘 `auto_morning_analysis.md` §4.5.2 做T建议**，注入窗口画像：

```
📊 做T窗口画像（数据：{标的} 近{N}日 1min 统计，窗口画像库）
  - 高适合窗口: 10:00-10:30（振幅0.9% 反转率68% 模拟胜率58%）——机制：方向确认+情绪稳定
  - 高危险窗口: 09:30-10:00（单边率52%，方向随机）——纪律支持"开盘30分钟不操作"
  - 今日状态: 震荡日 → 参考震荡日画像（若与全样本画像不同，以状态分层结果为准）
  做T建议必须引用窗口画像作为触发窗口选择的依据（"建议窗口"列）

## 六、风险与纪律

| 风险 | 应对 |
|------|------|
| 数据不稳定（mootdx 海外超时/push2 风控） | 多源容错（复用 quote_source）+ 本地缓存 + 断点续传 + 探测先行；研究库是**缓存**不是实时依赖，盘中不依赖它 |
| 过拟合（窗口统计样本内漂亮、样本外衰减） | 强制样本外验证（后 20% 时间）；窗口必须带**失效条件**；周度重算检视漂移 |
| 成本幻觉（纸面振幅≠可赚） | 净收益口径铁律：所有模拟胜率/回测扣 cost.py 成本模型 |
| 状态效应混入时间效应 | 二维画像（时间×状态），归因层做状态分离 |
| 污染现有 prompt 结构（盘中写入失败风险） | 信号新字段**增量列向后兼容**；prompt 改造走 REQ → dev-workflow（TDD 门禁） |
| 东财限流 | 全部走 `em_get` 串行限流；分钟资金流收集器限频 |
| 与现有 REQ 闭环冲突 | 本方案拆解为 REQ 系列（REQ-0xx），走 steering 生命周期 |

**项目铁律延续**：数据获取一律走 `a-stock-data`；REQ 实施必须 dev-workflow（brainstorming → writing-plans → TDD → executing-plans → code-review）；一次性脚本 `_*.py` 跑完即删。
