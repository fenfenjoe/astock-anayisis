## 2. 泄露事件记录

### 事件 2026-08-28：`dashboard/data/.secret_key` 曾入仓库

- **文件**：`etf-strategies/dashboard/data/.secret_key`（64 位 hex，JWT 签名密钥，dashboard 自动生成）
- **发现**：安全检查时发现被 git 跟踪，历史提交 `81bbac4` 起存在于仓库
- **处理**：
  1. `.gitignore` 追加 `etf-strategies/dashboard/data/.secret_key`
  2. `git rm --cached`（保留本地文件）→ 提交 `5d6fdad` → **已推送远端**（`master`）
  3. **密钥轮换**：删除本地 `dashboard/data/.secret_key`，dashboard 下次启动自动生成新 key（`auth.py`：`secrets.token_hex(32)` 写回文件）→ 旧 key 作废，历史中的旧值不可再伪造 JWT
- **未重写 git 历史**（用户确认）：轮换已使旧 key 失效；如需彻底清除可后续用 `git filter-repo`/BFG + `push --force`
- **影响**：轮换后既有登录 token 失效需重登；东财凭据（如曾配置）需用新 key 重新加密配置

### 排查结论（同次检查，均未泄露）

- `.dsh/.credentials.yaml`（DeepSeek key）：**从未提交**，`.dsh/` 整个目录在 .gitignore（`# DSH runtime data`）
- `.claude/settings.json`：仅插件启用 + 自动循环 hook，无真实凭据
- `.env.example`：模板，无值（唯一允许入仓库的 env 相关文件）
- `notify_config.json`：已在 .gitignore

## 4. 防泄漏纪律（新增凭据/文件时自查）

1. **新增任何配置文件前**：先问"里面有没有真实值？"→ 有则入 .gitignore，只提交无值模板
2. **提交前扫一遍**：`git ls-files | Select-String "key|secret|token|cred|passw|\.env"`（PowerShell）
3. **历史里出现过的凭据一律视为泄露**：即使从 HEAD 删除，也要**轮换**（删除/更换 key 让旧值作废），不依赖"删了就行"
4. **远端同步**：删除文件必须 `git push` 推送（不只本地 commit）
5. 公共仓库建议定期做敏感信息扫描（如 gitleaks），或保持仓库 private
