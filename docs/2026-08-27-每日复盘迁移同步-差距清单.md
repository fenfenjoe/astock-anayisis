# 每日复盘 → etf-strategies 迁移同步 — 差距清单与修复计划

> 数据时点：2026-08-27
> 目的：消除「每日复盘逻辑已优化、etf-strategies/dashboard 侧未跟随」造成的两边版本不一致。

## 1. 背景

- **首次迁移**（commit `c4a663b`，2026-08-18）：每日复盘的报告生成与定时任务运行时迁入 `etf-strategies/dashboard`，
  `my_doc/每日复盘/` 保留为**唯一事实源**（prompts/经验/配置/报告数据），dashboard 直接读写同一份数据。
- **迁移后的每日复盘逻辑持续优化**（2026-08-18 → 08-27），dashboard 侧未同步，出现版本漂移：
  - 信号体系升级 v2.0（12 列信号总表 / 预期触发率 / 目标止损 / 关注列表升级 / 移除 P2 观察信号）
  - 持仓配置新增「可用金额」行（`持仓.md`，支持建仓份额计算）
  - 新增 `signal_quality_weekly` 调度任务（周三 16:30 信号质量周报）
  - 报告体系新增「周度组合回顾」等类型

## 2. 现状架构（迁移后的目标形态）

```
etf-strategies/dashboard/           # 运行时（本次同步对象）
├── app.py          FastAPI 入口：lifespan 导入历史 + 启动调度引擎 + 通知 watcher
├── scheduler.py    每日复盘调度器（线程引擎 + claude -p 运行器 + 报告/持仓/交易导入器）
├── api_daily.py    持仓/资产 + 每日信号 + 报告 + 调度 + 通知 API
├── portfolio.py    持仓.md 解析/回写 + 实时估值
├── notify.py       企业微信信号触发通知
├── db.py           SQLite（daily_reports / scheduler_runs / portfolio_* 等表）
└── templates/static/js
my_doc/每日复盘/                    # 唯一事实源（只读/共享，不迁移内容）
└── harness/{prompts,config,experience,automation}/ + reports/
.claude/scripts/task_schedule.json  # 调度定义（dashboard scheduler 读取同一份）
```

**调度双轨**：Windows 计划任务 `dsh-trigger-*` → `dsh_trigger.py` 是当前生产调度；
dashboard 内置调度引擎默认 **auto 关闭、仅手动**（过渡期防双跑），由 UI「⏰ 定时任务」页手动触发。
