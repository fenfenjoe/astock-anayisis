# 每日复盘定时任务迁移至 etf-strategies 设计方案（含 Docker 部署）

> 日期：2026-08-27 | 状态：设计稿（待用户确认决策点后执行切换）
> 目标：dashboard 内置调度器成为每日复盘任务的唯一调度器；报告/信号/运行状态自动刷新到 Web；
>       支持 Docker 部署（容器内完成调度 + 报告生成 + Web 展示）

## 1. 现状与差异

### 1.1 两套调度并存

| 维度 | Windows 计划任务（现行生产） | Dashboard 内置调度器（迁移目标） |
|------|------------------------------|--------------------------------|
| 触发 | `dsh-trigger-*`（16 个计划任务） | `scheduler.py` 引擎（20s tick，时间窗口 7min） |
| 执行引擎 | **dsh headless**（DeepSeek Harness，`node dsh bin.js --profile headless`） | **claude -p**（Claude Code CLI） |
| 幂等 | `scheduler_state.json` | `scheduler_runs.window_key`（SQLite） |
| 交易日历 | 复用 `trading_calendar.py` | 复用 `trading_calendar.py`（同一份） |
| 调度定义 | `task_schedule.json`（21 任务，其中每日复盘侧 16） | 同一份 `task_schedule.json`（按 prompt_file 前缀过滤） |
| 报告导入 | 只写文件，不进 DB | 跑完自动导入 DB → Web 可见 |
| 运行日志 | `.dsh/logs/{task}-{ts}.log` | `scheduler_runs.output` → Web「运行日志」 |
| auto 开关 | 常开 | **默认关（仅手动）** — 过渡期防双跑 |

### 1.2 用户可见性现状（本次要解决的）

- Windows 任务执行状态 **不进 dashboard**（无 scheduler_runs 记录）→「⏰ 定时任务」页看不到
- 报告只在 dashboard **启动时**导入一次 → 之后新报告需手动「重新导入」
- 信号页/报告页 **无自动刷新** → 需手动刷新页面

## 2. 迁移目标架构

```
etf-strategies dashboard（唯一运行时）
├── scheduler.py 引擎（auto 开启，20s tick）
│     ├── 时间窗口判定（task_schedule.json，可调容差）
│     ├── 幂等：scheduler_runs.window_key（唯一权威）
│     ├── 执行引擎（可切换）：dsh headless（主，本地）/ claude -p（辅，Docker/兜底）
│     ├── 跑完自动导入报告/持仓/交易 → DB
│     └── 周期性增量重扫 reports/（mtime 守卫）→ 外部写入的报告也自动进 DB
├── api_daily.py / db.py / portfolio.py / notify.py（不变；新增 /api/scheduler/engine 切换）
└── 前端：报告/信号/定时任务页 30s 自动轮询刷新
Windows 侧：16 个 dsh-trigger-* 任务 Disable（防双跑；保留脚本以便回滚）
```

**关键变化**：
1. 执行引擎：**dsh headless（主，沿用现行 Windows 任务同一执行器）+ claude -p（辅）**，
   通过 `DASHBOARD_SCHEDULER_ENGINE` / UI-API 随时切换（默认 auto：本地有 dsh 用 dsh）
2. 幂等源切换：`scheduler_state.json` → `scheduler_runs` 表
3. 报告自动刷新：后端增量重扫 + 前端轮询
4. 调度窗口：Windows 用 ±3h 容差（任务抖动/休眠恢复），dashboard 用目标后 7min；
   迁移后可放宽为 ±30min（夜间休眠恢复场景），通过常量配置

## 4. 切换操作手册（用户确认后执行）

### 4.1 切换（Windows 本地运行，推荐：计划任务精确触发 + scheduler_cli）

```powershell
# 1) 改造计划任务：创建 etf-trigger-*（调用 etf_trigger.py → dashboard.scheduler_cli），
#    自动停用旧 dsh-trigger-*（保留可回滚）。以管理员身份运行：
powershell -ExecutionPolicy Bypass -File etf-strategies/scripts/setup_etf_scheduled_tasks.ps1            # dry-run 预览
powershell -ExecutionPolicy Bypass -File etf-strategies/scripts/setup_etf_scheduled_tasks.ps1 -Apply    # 实际执行

# 2) 启动 dashboard（引擎 auto 默认关闭——计划任务已是精确触发；报告重扫/前端轮询照常工作）
cd etf-strategies
powershell -ExecutionPolicy Bypass -File scripts/start_local.ps1          # Windows 本地启动
#   - 自动检测 etf-trigger-* / 旧 dsh-trigger-* 并给出调度模式提示
#   - 默认引擎 auto OFF（计划任务精确触发模式）；要引擎轮询触发用 -Auto
#   - DryRun 预览：... start_local.ps1 -DryRun
# Linux/macOS/Docker 启动：./start_dashboard.sh（同样会检测宿主计划任务并提示）

# 3) 验证：Get-ScheduledTask -TaskName 'etf-trigger-*' | Select TaskName, State
#    到点任务自动执行（scheduler_runs 记录 trigger='cron'），报告/信号页 30s 内自动刷新
```

> 备选：不用计划任务时，可开 dashboard 引擎轮询（`DASHBOARD_SCHEDULER_ENABLED=1`，零 token，
> 窗口内 0~7 分钟触发）；cron 触发与引擎 auto 共用 `scheduler_runs.window_key`，双开也互斥不重复。

### 4.2 回滚

```powershell
powershell -ExecutionPolicy Bypass -File etf-strategies/scripts/setup_etf_scheduled_tasks.ps1 -Revert
# 即：删除 etf-trigger-* + 重新启用旧 dsh-trigger-*
# 注意：旧 dsh-trigger 幂等（scheduler_state.json）已落后，回滚后首个任务会重跑一次（正常）
```
