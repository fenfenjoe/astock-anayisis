# Harness 模块改造——工单管理与定时任务迁移方案（方案三）

> 日期：2026-09-10 | 状态：✅ 已实施完成
> 目标：定时任务由 Agent 进程接管执行，BUG/REQ 工单数据上云，Dashboard 新增工单管理页面
> 来源：CHAT.md §3

## 一、背景与问题

### 1.1 现状

1. **定时任务由 Dashboard scheduler.py 执行**：`_run_prompt` 在 Dashboard 内拉起 dsh 子进程执行任务，Agent 进程不参与
2. **BUG/REQ 工单走本地 markdown**：工单数据以 markdown 文件方式在本地流转，无法跨机器查看、无法追踪状态
3. **无工单管理界面**：Dashboard 没有工单相关页面，无法查看执行过程与结果

### 1.2 目标

- 定时任务执行者从小满进程（Agent）接管——Dashboard scheduler.py 改为"通知 Agent 执行"
- BUG/REQ 工单数据放到云库（Supabase）中管理
- Dashboard 后台新增工单管理页面（列表、详情、筛选、重触发）
- 小满处理工单遇到需要人工干预时，通过通知/待办与用户交互

## 二、架构设计

```
┌─────────────────────┐                     ┌─────────────────────┐
│   Dashboard 进程    │                     │   Agent 进程         │
│   (FastAPI :8000)   │                     │   (FastAPI :8020)   │
│                     │  POST /api/agent/   │                     │
│  scheduler.py       │ ───── scheduler ──> │  scheduler_agent.py │
│  _run_prompt()      │     /run/{task_id}  │  execute_task()     │
│  (优先派发Agent)    │                     │  └─ dsh headless    │
│                     │                     │                     │
│  api_tickets.py     │  直接读云库          │  写入云库            │
│  (工单列表/详情)    │ ──── tickets ─────> │  失败自动建单        │
│                     │                     │  通知用户            │
└─────────────────────┘                     └─────────────────────┘
                              │
                    云库 Supabase
                    public.tickets
```

### 2.1 执行流程

1. **Dashboard scheduler.py 到点** → `_run_prompt` 优先 HTTP POST `Agent API /scheduler/run/{task_id}`
2. **Agent 收到请求** → `scheduler_agent.execute_task()` 后台线程执行 dsh headless
3. **执行成功** → 无操作
4. **执行失败** → `_upsert_ticket()` 自动建单到云库 tickets 表 + 发送通知到通知/待办
5. **Dashboard 兜底** → Agent 不可达时，Dashboard 本地执行 dsh/claude（保留旧逻辑）

### 2.2 工单数据模型

```sql
CREATE TABLE public.tickets (
    id          TEXT PRIMARY KEY,      -- 短UUID（12位hex）
    kind        TEXT NOT NULL,         -- 'bug' | 'req'
    title       TEXT,
    description TEXT,
    severity    TEXT DEFAULT 'p2',     -- p0/p1/p2/p3
    status      TEXT DEFAULT 'open',   -- open/analyzing/in_progress/needs_human/resolved/closed
    source_task TEXT,                  -- 来源调度任务 task_id
    assignee    TEXT DEFAULT 'xiaoman',
    created_at  TEXT,
    updated_at  TEXT,
    result      TEXT DEFAULT '',
    log_entries TEXT DEFAULT '[]'      -- JSON 数组，[{ts, step, detail}]
);
```

- 工单 ID：`uuid.uuid4().hex[:12]`（短 UUID，12 位 hex）
- 状态流转：`open → analyzing → in_progress → needs_human → resolved → closed`
- 来源：`source_task` 指向 task_schedule.json 中的 task_id

## 三、实施详情

### 3.1 Agent 侧调度引擎（agent/core/scheduler_agent.py）— 新建

Agent 侧的调度任务执行器（390 行），完全接管 Dashboard scheduler.py 的任务执行职责。

**核心函数**：

| 函数 | 说明 |
|------|------|
| `load_task_defs()` | 读取 task_schedule.json，mtime 缓存（120s） |
| `scoped_tasks()` | 过滤 prompt_file 以 `my_doc/每日复盘/` 或 `etf-strategies/automation/` 开头的任务 |
| `task_due_now()` | 时间窗口 + 星期 + 交易日判定 |
| `execute_task(task_id, trigger)` | 主入口：校验 → 防重入 → 启动后台线程执行 |
| `_run_task_and_record()` | 执行 dsh headless + 记录活动（activity_start/open_close） |
| `_exec_dsh()` | dsh CLI 调用器（node 发现、并发控制、速率限制重试） |
| `_handle_task_result()` | 失败时自动建单 + 发送通知 |
| `_upsert_ticket()` | 生成短 UUID 工单 → 写入云库 tickets 表 |

**关键设计决策**：
- dsh 并发控制：`_dsh_sem = BoundedSemaphore(2)`（最多 2 个 dsh 并发）
- 速率限制重试：检测 rate_limit 标记，退避重试最多 3 次（30s / 60s / 120s）
- 超时：`CLAUDE_TIMEOUT_SECONDS = 3600`（1 小时）
- 输出截断：`OUTPUT_TAIL_CHARS = 8000`

**工单自动建单逻辑**（`scheduler_agent.py:353-381`）：

### 3.2 Dashboard 调度器改造（dashboard/scheduler.py）— 已改

`_run_prompt` 改为"优先通知 Agent 执行，不可达时本地兜底"（`scheduler.py:695-754`）：

```python
def _run_prompt(task: dict, run_id: int) -> None:
    # ── 优先通知 Agent 进程执行 ──
    agent_url = os.environ.get("AGENT_API_URL", "http://127.0.0.1:8020").rstrip("/")
    agent_key = os.environ.get("AGENT_API_KEY", "").strip()
    try:
        r = req.post(
            f"{agent_url}/api/agent/scheduler/run/{task['task_id']}",
            json={"trigger": "auto"},
            headers={"X-Api-Key": agent_key} if agent_key else {},
            timeout=10,
        )
        if r.status_code == 200 and r.json().get("started"):
            agent_executed = True
    except Exception:
        pass

    if agent_executed:
        # 已派发到 Agent，Dashboard 记录即可
        db.scheduler_run_update(run_id, status="running", ...)
        return

    # ── Agent 不可达 → 本地兜底 ──
    if engine == "dsh":
        status, out = _exec_dsh(task)
    else:
        status, out = _exec_claude(task, started)
    # ... 导入器等
```

## 五、验收标准

1. Dashboard 定时任务到点 → 通知 Agent 执行（scheduler_runs 记录"已派发"）
2. Agent 执行成功 → 正常完成；失败 → 自动建单 + 发送通知
3. Dashboard「工单管理」页可查看、筛选、翻页工单列表
4. 工单详情可查看描述、日志、结果
5. 有 source_task 的工单可重触发执行
6. Agent 不可达时 Dashboard 兜底本地执行，不丢任务
