# 进化目标定义（goals.md 示例模板）

> 这是《基于 DeepSeek Harness 的 Agent 自进化框架研究文档》（docs/Agent自进化框架研究.md）第 7 节"可定制层"的落地示例。
> 用户只需维护本文件（目标/指标/验证器/方向/边界/节奏），通用进化引擎据此自动运转。
> 复制为 `goals.md` 后按需修改。每条目标必须**可结算**（有指标 + 有验证器），否则正循环无法运转。

---

## 愿景（Vision）

> 一句话：这个 Agent 最终要成为什么。

```
让 A 股投研 Agent 成为"能持续自我进化的私人投研合伙人"：
预测越来越准、报告越来越可靠、经验越攒越值钱、错误越犯越少。
```

---

## 目标（Goals）

### G-A：提升每日信号命中率（P0，权重 30%）

- **指标（Metrics）**：
  - 信号 T+3 命中率（hit/(hit+stopped+miss)）≥ 45%
  - P0 信号执行率 = 100%
  - 信号决策质量分（复盘仪表盘 8 项均分）≥ 3.5/5
- **验证器（Verifier）**：`settle_due_signals`（T+3 目标价结算，hit/stopped/miss），每日复盘自动跑
- **进化方向（Direction）**：
  - 优先：信号设计 skill（`投资经验.md` 信号设计章节、盘中三级阈值）
  - 其次：做T 胜率校准经验
- **当前状态**：进行中（基线命中率见 `reports/*/每日信号.md` 质量仪表盘）

### G-B：提升报告质量与可靠性（P1，权重 25%）

- **指标（Metrics）**：
  - 报告审阅通过率（3 轮审阅无 A 类问题）≥ 90%
  - 数据错误条数 / 周 ≤ 1（涨幅口径、代码-名称强校验等）
- **验证器（Verifier）**：`报告审阅经验.md` 2-3 轮审阅 + 数据交叉校验脚本（ETF 代码-名称比对等）
- **进化方向（Direction）**：
  - 优先：报告审阅 checklist（G4 评审标准）
  - 其次：数据校验脚本库（防复权/口径错误）
- **当前状态**：进行中

### G-C：降低重复错误（P2，权重 20%）

- **指标（Metrics）**：同一根因错误复发率（dsh-fail-logger 统计）连续 4 周下降
- **验证器（Verifier）**：错误模式库（G3）根因去重计数 + 逻辑巡检（logic_inspect 14 条规则）
- **进化方向（Direction）**：
  - 优先：错误模式库 → 防复发规则（AGENTS.md / 规则文件）
  - 其次：自动化巡检覆盖范围
- **当前状态**：进行中

### G-D：经验库健康度（P3，权重 15%）

- **指标（Metrics）**：经验库体检（大小/重复率/矛盾数/过时条目数）各项在阈值内；有效经验引用率上升
- **验证器（Verifier）**：`experience_health`（周三体检任务）
- **进化方向（Direction）**：经验沉淀协议（G2）+ 融合/修正/弃用机制
- **当前状态**：进行中

## 边界（Boundaries，红线）

> 明确"不进化什么"，防止误进化与目标漂移。

```
- 不进化方向：不做短线妖股/打板高频（能力圈之外）；不碰融资杠杆建议
- 不改动：数据层铁律（所有 A 股数据必须走 a-stock-data，不得另造数据通道）
- 不触碰：reports/（产物目录只读）；用户账户/凭证/身份相关配置
- 涉及金钱/金融/安全/删除类变更：必须人工确认（MANUAL_REVIEW 机制）
- 自动化发现问题→REQ：可自动建单，但 REQ CLOSED 必须用户最终确认
```

---

## 节奏（Cadence）

```
- 指标结算：每交易日复盘（T+3 结算随信号到期自动完成）
- 差距分析 → REQ 生成：每周（周一复盘后批量分析指标缺口）
- 进化候选验证：每周批处理（不用每个小波动都触发，防进化噪音）
- 经验库健康体检：每周三（experience_health）
- 进化周报：每周五（汇总"这周改了什么/为什么/验证了什么/指标怎么变"）
- 连续 3 轮指标无改善的方向：自动暂停 + 回滚最近变更 + 换方向（负反馈）
```
