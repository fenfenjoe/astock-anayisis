## 一、火山 Agent 进化（Agent Evolve）调研

### 1.1 官方定义

> Agent 进化（Agent Evolve，Evolve）是面向 Claude Code、OpenClaw、TraeCode 等 AI 工具的
> **持续进化能力**。Evolve 学习 Agent 的近期会话，识别当前运行时中**可优化的指令文件**，
> 并生成改进建议。建议经用户确认后，Evolve 会将其写入 CLAUDE.md、AGENTS.md 等运行时文件。

**官方文档**：https://docs.volcengine.com/docs/ark/agent-plan-personal-evolve?lang=zh

### 1.2 核心机制（已从文档 + install.sh + bundle 源码完整解析）

```
会话日志 (evidence)
   → evolve import 上传云端
   → 云端管线：sessions → signals → genes → proposals
   → evolve proposals 拉取建议
   → evolve apply --dry-run 预览 diff → 用户确认 → 写入运行时文件
```

**7 个 CLI 命令**：

| 命令 | 写入 | 用途 |
|------|------|------|
| `evolve init` | cloud + `~/.evolve/` | 首次设置，发现可进化能力面 |
| `evolve status` | 无 | 查看设置状态/待处理建议 |
| `evolve import` | cloud | 上传会话日志作证据 |
| `evolve proposals` | 无 | 列出云端建议 |
| `evolve proposal <id>` | 无 | 查看建议详情 + diff 预览 |
| `evolve capability` | cloud(切换时) | 列出可进化面 / 设置 auto-apply |
| `evolve apply <id>` | **运行时文件** | 唯一写文件的命令（dry-run 后确认） |

**关键设计**：
- **进化对象** = 指令文件/Skills（CLAUDE.md、AGENTS.md、SOUL.md、IDENTITY.md、skills/ 等），**不是代码**
- **回滚** = 无 rollback 命令，但 apply 写入带 `<!-- evolvor:chg_xxx -->` 标记，删块即回滚
- **身份** = Ark API key（Authorization: Bearer），key 拥有者即 CapabilityMap owner
- **安全** = apply 前强制 dry-run + 用户确认；会话上传前披露路径与数量
- **后端** = `https://prompt-pilot.cn-beijing.volces.com/case-platform`（HTTP，需 EVOLVE_INSECURE=1）

### 1.3 支持的运行时（关键限制）

| Connector | 可进化面 | 状态 |
|-----------|---------|------|
| `claude_code` | CLAUDE.md、CLAUDE.local.md、~/.claude/CLAUDE.md | ✅ 已支持 |
| `openclaw` | AGENTS.md、SOUL.md、IDENTITY.md、USER.md、TOOLS.md、BOOTSTRAP.md、HEARTBEAT.md、MEMORY.md、skills/ | ✅ 已支持 |
| `trae` | AGENTS.md | ✅ 已支持 |
| `deepseek-harness` | （文档菜单已列，但 install.sh / bundle 均无） | ⚠️ **工具未实现** |

**结论**：火山控制台文档菜单已列出 DeepSeek Harness（规划中），但**当前 Evolve CLI/bundle
只支持 claude_code/openclaw/trae**，DSH 尚无 connector。

### 1.4 与用户理解的自进化的关系

用户理解："将走通的工作流程总结成 skill/workflow，下次遇到类似任务少走弯路"。

火山 Evolve **正是这个方向的实现**：
- 从**真实会话**学习 → 提炼改进 → 写入 **skills/** 指令文件
- 与我们的"指标驱动闭环"（打分离差 → REQ 改进代码）是**互补的两个维度**：
  - 火山 Evolve = **行为/指令层进化**（会话 → skill/指令文件）
  - 当前框架 = **指标/能力层进化**（指标 → REQ → 代码/流程改进）

## 二、专业数据集（DataPro）调研

### 2.1 官方定义

> 专业数据集（DataPro）是 Agent Plan 的 Harness 能力。其中**金融数据库**涵盖全球股票、期货、
> 国内期权、债券、基金等各类上市品种的**基本资料、财务数据、日频行情信息、盈利预测、技术形态**
> 等各类分析指标数据。

**官方文档**：https://console.volcengine.com/ark/region:cn-beijing/docs/82379/2479086

### 2.2 能力细节（从文档解析）

- **触发方式**：Query 中包含股票代码或上市公司名称 + 金融指标描述时，**自动路由**调用金融数据库
- **调用工具**：`dataPro_search`（dataPro-search MCP）
- **查询限制**：单次最多查 **3 只股票/标的/实体**
- **返回结构**：`items[]` → `{查询代码: "002594.SZ", table: {连涨天数, 连跌天数, 创历史新高, ...}}`

**查询示例与能力**：

| 示例 | 能力 |
|------|------|
| `002594 股票 K 线形态分析` | 技术形态（连涨/连跌天数、新高新低） |
| `比亚迪 ROE 盈利水平` | 财务指标（ROE） |
| `五粮液季度业绩季报数据` | 季报业绩 |
| `2022年12月比亚迪汉EV全国销量` | 销量数据 |
| `2018Q1全球玉米美元/吨价格指数` | 全球商品价格 |
| `理想 L9 车身尺寸/底盘配置` | 车型配置 |

### 2.3 与 a-stock-data 对比

| 维度 | a-stock-data（现状） | 火山 DataPro |
|------|---------------------|--------------|
| 数据范围 | A股行情/财务/研报/资金面（mootdx/腾讯/东财等） | 全球股票/期货/期权/债券/基金，日频行情/财务/盈利预测/技术形态 |
| 实时性 | 实时行情（mootdx TCP / 腾讯 HTTP） | **日频**（非实时） |
| 调用方式 | Python API 直接取数（脚本可控） | **NL 语义查询**（dataPro_search，走 Agent Plan MCP） |
| 限制 | 东财限流，需串行 | 单次 3 只标的 |
| 前置 | 无（免费数据源） | **Agent Plan 订阅 + API Key** |
| 稳定性 | 部分源间歇风控（HTTP 000/空） | 火山云服务（稳定） |

### 2.4 关键结论

1. **DataPro 是"语义查询式金融数据库"**（NL→结构化数据），不是传统行情 API
2. **数据是日频**，不适合盘中实时行情（早盘/盘中分析需要分钟级实时数据）
3. **依赖 Agent Plan 订阅**（当前 SSO 过期，无法确认用户是否开通）
4. **定位**：适合作为**日频指标补充**（财务/季报/盈利预测/技术形态），**不能替代**实时行情源

## 三、融合方案建议

### 3.1 自进化方向（火山 Evolve + 当前框架）

**现状差距**：当前框架是"指标驱动闭环"（打分离差→REQ→改代码），**缺"行为/指令层进化"**——
没有系统性地把"走通的工作流"沉淀为 skill。

**推荐路径（两步走）**：
1. **短期（本地实现）**：在现有框架加一层"**工作流沉淀机制**"——每次 REQ 实施成功（CLOSED）后，
   自动把"实施过程/经验"沉淀为 `harness/experience/` + 可复用 skill，下次同类任务直接引用。
   这与火山 Evolve 的"会话→skill"同构，但先本地落地（不依赖云端）。
2. **中期（接火山 Evolve）**：等火山 Evolve 正式支持 DSH（控制台已列，工具未实现），
   用它的 `claude_code` connector 以 `~/.claude/skills/` 为进化面试跑，
   或直接监控官方 release，DSH connector 上线后接入。

### 3.1.1 短期已落地（2026-09-24）：REQ 工作流沉淀机制 ✅

**实现**：`lib/workflow_harvest.py`（纯函数）+ 11 项测试 + 接入 experience_health 第八步。

- `parse_req(text)`：解析 REQ 文档（id/标题/状态/描述/期望/约束/处理记录）
- `build_harvest(req)`：提取任务签名 + 流程时间线 + 关键命令 + 陷阱 + 验收
- `render_skill_md(harvest)` / `write_skill()`：渲染并写盘 `harness/skills/{REQ-ID}.md`
- 触发：experience_health（周三）第八步全量重扫 CLOSED REQ → 幂等生成/更新 skill

**端到端验证**：7 个 CLOSED REQ（REQ-001/002/003/004/005/007/009）全部生成 skill，
产物含任务签名/4 步流程/关键命令（P&L 公式）/陷阱/验收 ✅

**三层沉淀互补**（experience vs workflow_harvest vs OpenViking）：
| 层 | 内容 | 消费方式 |
|----|------|---------|
| `harness/experience/` | 投资规律（Situation/Approach/Reflect） | 分析前注入 |
| `harness/skills/`（新） | 任务工作流（怎么做，从 REQ 沉淀） | 同类任务前检索引用 |
| OpenViking | 证据链（置信度贝叶斯更新） | 检索/健康检查 |

### 3.2 数据源（DataPro 接入）

**结论**：DataPro **不能替代** a-stock-data（日频 vs 实时），但可作**补充**。

**推荐路径**：
1. **保持 a-stock-data 为主**（实时行情必需）
2. **DataPro 作补充**：在取数失败/需要财务深度数据时，fallback 到 DataPro 查询
3. **接入前提**：用户确认 Agent Plan 订阅 + 重新登录 arkcli SSO（当前 refresh_token 失效）

### 3.2.1 DataPro 接入骨架已落地（2026-09-24）✅

**实现**：`lib/datapro_client.py`（纯 Python MCP/HTTP client）+ 11 项测试。

- **endpoint**：`https://datapro.hqd.cn-beijing.volces.com/mcp`（HTTP Streamable MCP）
- **认证**：`X-Agent-Plan-Key` header（环境变量 `AGENT_PLAN_KEY`）
- **工具**：`dataPro_search`（语义查询：财务/日频行情/技术形态/盈利预测）
- **双通道**：`datapro_search()`（mcp SDK）/ `datapro_search_http()`（requests 直连兜底）
- **优雅降级**：未配置 Key / 调用失败 → 返回 None（调用方降级到 a-stock-data），不抛错
- **测试**：Key 检测 / headers / 无 Key 降级 / 解析 / HTTP 协议正确性（mock 验证）

**激活方式**（用户有 Agent Plan Key 后）：
```bash
# 设置环境变量后即可调用
set AGENT_PLAN_KEY=<你的 Agent-Plan-Key>
python -c "from lib.datapro_client import datapro_search; print(datapro_search('002594 ROE 盈利水平'))"
```

**⚠️ 关键认知**：DataPro 是**日频**数据（非实时），只作日频财务指标/技术形态补充，
**不能作为实时行情主源**（早盘/盘中分析需分钟级实时数据，仍靠 mootdx/腾讯）。

### 3.2.2 DataPro 真实验证结果（2026-09-24，用真实 Agent Plan Key）✅✅

**验证方式**：从本地 arkcli profile（`agent-plan_cn-beijing_personal`）取明文 key
（`arkcli profile apikey get --profile agent-plan_cn-beijing_personal`），
设 `AGENT_PLAN_KEY` 后调用 `datapro_search_http()` 实测。

**实测通过的能力**：

| 查询 | 返回 | 说明 |
|------|------|------|
| `002594 ROE 盈利水平` | ✅ 20+ 字段 | 杜邦 ROE 4.86% / ROE(TTM) 12.27% / 盈利预测 FY1-3 / 文字评价 |
| `002594 股票 K 线形态分析` | ✅ 20 字段 | 连涨/连跌天数、MA、MACD、BOLL |
| `五粮液 ROE 盈利水平` | ✅ 20 字段 | 000858.SZ 全口径 ROE |
| `600519 最近30个交易日日K线...` | ✅ 13 字段 | 开高低收/量/额/换手率/涨跌幅/停牌/涨停/跌停，**滚动 ~3 周窗口** |
| `贵州茅台 最新股价` | ⚠️ 2 字段 | 仅状态判断（是否停牌/非交易日），**无实时价** |

**实测结论**：
1. **Agent Plan key 有效**（profile 显示 9/4 过期但 key 仍可调用，可能订阅已续费）
2. **HTTP 直连协议完全正确**（datapro_client 实现验证通过）
3. **能力边界确认**：
   - ✅ 财务指标（多口径 ROE + 盈利预测 + 评价文字）— 远超 a-stock-data 的简易财务
   - ✅ 技术形态指标（连涨天数/MA/MACD/BOLL）
   - ✅ **日频行情**（滚动 ~3 周日K：开高低收/量/额/换手率/涨跌幅）
   - ❌ 实时行情（无分钟级/最新价）→ 印证"日频非实时"，不能替代 mootdx/腾讯
   - ❌ 全量历史行情（只有滚动窗口，无长周期回溯）

**定位确定**：DataPro = **日频财务/技术形态补充源**（fallback + 深度财务），
a-stock-data（mootdx/腾讯实时）**保持主源不变**。两者互补。
