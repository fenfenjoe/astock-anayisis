## 1. 项目概览

ETF 量化策略回测系统是一个**A 股 ETF 多策略回测 + 信号生成 + Web Dashboard** 三位一体的量化投研工具。

```
etf-strategies/
├── backtest/                    # 回测核心层
│   ├── engine.py                #   向量化回测引擎（信号滞后1日、成本扣除）
│   ├── data.py                  #   数据层（东财API + parquet本地缓存）
│   ├── metrics.py               #   绩效指标（年化收益/Sharpe/MaxDD/Calmar/胜率）
│   ├── cost.py                  #   交易成本模型（佣金万2.5 + 滑点万1）
│   ├── reporting.py             #   报告输出（matplotlib图表 + Markdown表格）
│   ├── em_client.py             #   东财统一限流客户端
│   └── strategies/              #   策略库（19个策略）
│       ├── base.py              #     策略基类
│       ├── buy_hold.py          #     S1 买入持有
│       ├── momentum_rotation.py #     S4 动量轮动
│       ├── canary_defense.py    #     S16/S17 金丝雀防御
│       └── ...                  #     共19个策略
├── dashboard/                   # Web Dashboard (FastAPI + SQLite + ECharts)
│   ├── app.py                   #   FastAPI主应用
│   ├── auth.py                  #   认证（bcrypt + JWT）
│   ├── db.py                    #   数据库持久化（7张表）
│   ├── sync.py                  #   数据同步（K线/信号/回测NAV）
│   └── templates/               #   前端（单页HTML + ECharts）
├── automation/                  # 自动化迭代层
│   ├── prompts/                 #   巡检/修复/发现 Prompt
│   ├── config/                  #   正确性定义 + 发现源配置
│   ├── bugs/                    #   BUG跟踪（open/closed/archive + INDEX）
│   └── steering/                #   优化需求管理（open/in_progress/closed）
├── tests/                       # 测试（pytest）
├── run_backtest.py              # 全量回测入口
├── daily_signal.py              # 当日信号生成器
├── list_strategies.py           # 策略列表输出（rich表格）
├── cli.py                       # 交互式CLI菜单
├── strategy_kb.py               # 策略知识库（中文文档）
└── html_report.py               # 一年期HTML报告生成器
```

**数据流**：
```
东财API → data.get_kline() → parquet缓存
  → strategy.generate(prices) → 目标权重
    → engine.backtest(prices, weights) → NAV/收益/换手
      → metrics.compute_metrics() → 绩效指标
      → reporting → 图表/报告
      → dashboard/sync.py → SQLite → Web展示
```

## 2. 快速上手：如何使用

### 2.1 环境准备

```bash
cd etf-strategies
pip install -r requirements.txt  # pandas, numpy, matplotlib, scipy, fastapi, etc.
```

### 2.2 运行全量回测

```bash
# 对所有19个策略运行回测，输出绩效对比表
python run_backtest.py
```

输出：Markdown 格式的策略绩效对比表（年化收益、Sharpe、MaxDD、Calmar、胜率）。

### 2.3 查看策略列表

```bash
# 彩色表格（需要 rich 库）
python list_strategies.py

# 纯文本表格
python list_strategies.py --plain
```

### 2.4 生成当日信号

```bash
# 对所有策略生成当日交易信号
python daily_signal.py
```

输出每个策略的：当前持仓、目标权重、调仓方向、置信度。

### 2.5 交互式 CLI

```bash
python cli.py
```

菜单选项：运行回测、生成当日信号、查看策略列表、查看策略详情。

### 2.6 生成一年期 HTML 报告

```bash
# 生成单策略的完整一年期回测报告（含图表嵌入）
python html_report.py --sid S4
```

### 2.7 运行测试

```bash
# 全量测试
python -m pytest tests/ -v

# 仅策略测试
python -m pytest tests/ -v -k "test_strategies"

# 覆盖率报告
python -m pytest tests/ --cov=backtest --cov-report=term
```

## 3. 自动化迭代：如何让项目自动运转

项目配置了完整的自动化闭环，通过 Claude Code `/loop` + Python 调度器驱动。

### 3.1 当前定时任务一览

全部 13 条任务由 `.claude/scripts/task_schedule.json` 统一定义，一个 `/loop` 命令调度全部。

| task_id | 时间 | 星期 | Prompt |
|---------|------|------|--------|
| bug_auto_fix | 每小时:07 (9-18) | 一~五 | `bug_auto_fix.md` |
| bug_inspect_data | 12:07 | 一~五 | `bug_inspect_data.md` |
| bug_inspect_code | 12:17 | 一~五 | `bug_inspect_code.md` |
| bug_inspect_logic | 12:23 | 周一 | `bug_inspect_logic.md` |
| strategy_scan_weekly | 12:37 | 周二 | `strategy_scan_weekly.md` |

### 3.2 启动自动化循环

每次启动 Claude Code 后，输入：

```
/loop 7m /clear && 执行 .claude/prompts/loop_runner.md
```

`SessionStart` hook 会在启动时提醒此命令。详见 `.claude/prompts/setup_loop.md`。

**核心优势**：每次迭代先 `/clear` 清空上下文，Python 调度器判断是否有到期任务。**零上下文累积，每次任务从干净会话开始**。

### 3.3 管理调度

- **查看状态**：`python .claude/scripts/task_scheduler.py --status`
- **修改调度**：编辑 `.claude/scripts/task_schedule.json`（下次迭代即生效）
- **强制重跑**：删除 `.claude/scripts/scheduler_state.json` 中对应 key
- **停止循环**：`Ctrl+C` 或回复 `stop`

### 3.4 自动化工作流全景

```
┌─────────────────────────────────────────────────────────┐
│               /loop 7m /clear (每次清空上下文)            │
│              → Python scheduler --check                  │
│              → 匹配时间窗口 → 执行到期任务                  │
└──────────────────────┬──────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────┐
│                    巡检层                                │
│  数据质量(12:07) → 发现BUG → bugs/open/BUG-{NNN}.md     │
│  代码巡检(12:17) → 发现BUG → +auto_fix_eligible          │
│  逻辑巡检(周一12:23) → 发现BUG → +auto_fix_eligible      │
└──────────────────────┬──────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────┐
│            自动修复层 (工作日 9-18点 每小时 :07)          │
│  auto_fix_eligible=true  → 自动修复 → 测试 → FIXED       │
│  auto_fix_eligible=false → MANUAL_REVIEW → 待人工审核     │
│  生成 AUTO_FIX_REPORT_*.md → bugs/archive/               │
└──────────────────────┬──────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────┐
│              策略发现层 (每周二 12:37)                     │
│  多平台搜索 → 提取策略信息 → 交通灯评估                    │
│  绿灯 → 自动转化 → strategy_convert_backtest.md          │
│  黄灯 → candidate_queue.json 排队                        │
└─────────────────────────────────────────────────────────┘
```

### 3.5 查看自动化执行日志

```bash
# 自动修复日志
cat etf-strategies/automation/logs/auto_fix_*.log

# BUG 修复报告
ls etf-strategies/automation/bugs/archive/

# Loop 调度器状态
python .claude/scripts/task_scheduler.py --status
```

## 4. 需求与BUG：如何提

### 4.1 提优化需求（Steering 系统）

**适用场景**：你想给自动化迭代系统提优化建议，如"增加波动率过滤""优化东财限流""早盘增加新的数据源"等。

**步骤**：

1. 在 `etf-strategies/automation/steering/open/` 下创建需求文件：

```bash
# 复制模板
cp etf-strategies/automation/steering/REQ_TEMPLATE.md \
   etf-strategies/automation/steering/open/REQ-001.md
```

2. 填写需求内容（标题、优先级、描述、期望结果）

3. 在 `REQ_INDEX.md` 中登记新需求：

```markdown
| REQ-001 | 增加波动率过滤 | P1 | 策略发现 | OPEN | 2026-07-21 |
```

4. 下次自动化任务执行时，会自动读取并纳入工作范围

**状态流转**：
```
OPEN → IN_PROGRESS (自动化任务自动推进)
     → ADOPTED (你确认采纳)
     → REJECTED (你确认拒绝)
     → IMPLEMENTED (已实现并验证)
```

> 状态 ADOPTED/REJECTED/IMPLEMENTED 需要你手动设置（或让 Claude 代操作）。

### 4.2 报告 BUG

BUG 主要由自动化巡检自动发现。如果你想手动报告 BUG：

1. 在 `etf-strategies/automation/bugs/open/` 下参照格式创建 `BUG-{NNN}.md`
2. 在 `BUG_INDEX.md` 中登记
3. 下个小时的自动修复任务会尝试修复（如果 `auto_fix_eligible=true`）

### 4.3 查看待人工审核的 BUG

打开 `etf-strategies/automation/bugs/BUG_INDEX.md`，查看 "⚠️ 待人工审核" 区域。

这些 BUG 涉及计算逻辑/金融公式，自动修复不会处理，需要你人工审阅后决定如何修复。

## 5. 配置参考：如何查看自动化配置

### 5.1 正确性定义

**文件**：`etf-strategies/automation/config/correctness_definitions.yaml`

定义了 6 个组件、27 条"正确行为"规则，巡检时逐条验证：

| 组件 | 条目数 | 示例 |
|------|--------|------|
| engine | 4 | 信号滞后1日、NAV≥0、成本扣除公式、换手率计算 |
| data | 5 | K线排序、多资产对齐、API降级、东财限流、缓存路径 |
| metrics | 6 | 年化收益公式、Sharpe公式、MaxDD公式、Calmar、胜率、超额收益 |
| strategies | 5 | 权重行和≈1、全覆盖日期、无未来数据、warmup行为、diagnostics格式 |
| registration | 4 | run_backtest注册、daily_signal注册、list_strategies注册、strategy_kb注册 |
| dashboard | 3 | 登录API返回200、7张表存在、JWT流程完整 |

### 5.2 策略发现源配置

**文件**：`etf-strategies/automation/config/discovery_sources.yaml`

定义搜索平台、关键词、评估阈值：
- 绿灯：年化≥15%、Sharpe≥0.8、回测≥5年 → 自动转化
- 黄灯：接近阈值 → 进入候选队列
- 红灯：不达标 → 跳过

### 5.3 候选队列

**文件**：`etf-strategies/automation/config/candidate_queue.json`

黄灯策略排队，等待下次重新评估或人工确认。

### 5.4 定时任务配置

在 Claude Code 中查看：

```
列出所有 cron 任务
```

或查看注册脚本：`.claude/prompts/setup_automation_cron.md`

## 6. 策略开发：如何新增策略

### 6.1 创建策略文件

在 `backtest/strategies/` 下新建 `.py` 文件，继承 `Strategy` 基类：

```python
from .base import Strategy
import pandas as pd
import numpy as np

class MyStrategy(Strategy):
    name = "我的策略"
    assets = ["510300", "510500", "511880"]

    def generate(self, prices: pd.DataFrame) -> pd.DataFrame:
        """返回与 prices 等长的目标权重 DataFrame"""
        weights = pd.DataFrame(0.0, index=prices.index, columns=prices.columns)

        # 你的策略逻辑：填写 weights
        # ...

        return weights

    def get_diagnostics(self, prices: pd.DataFrame) -> dict:
        """可选：返回策略内部状态，供 Dashboard 展示"""
        return {
            "parameters": {"lookback": 20},
            "scores": {},
            "holdings": {}
        }
```

**关键约束**：
- `generate()` 返回的权重每行和 ≈ 1.0 或全零（空仓）
- 不能使用未来数据（只能用 `prices.iloc[:i]` 的数据计算第 i 行权重）
- 数据不足 warmup 期时返回全零权重

### 6.2 注册策略（5个位置）

新增策略必须在以下位置注册：

| # | 文件 | 注册方式 |
|---|------|---------|
| 1 | `daily_signal.py` | `STRAT_MAP` 字典中添加 `"S20": ("my_strategy", MyStrategy)` |
| 2 | `list_strategies.py` | `STRATEGIES` 列表中添加 `MyStrategy()` 实例 |
| 3 | `strategy_kb.py` | `KB` 字典中添加策略中文文档（参数、逻辑、适用场景） |
| 4 | `dashboard/sync.py` | `STRATEGY_DEFS` 列表中添加策略定义 |
| 5 | `backtest/strategies/` | 策略类文件本身 |

> 遗漏任何一处都会在代码巡检中被发现并自动修复（`auto_fix_eligible=true`）。

### 6.3 编写测试

在 `tests/test_strategies.py` 中添加测试函数：

```python
def test_my_strategy_basic(synth_prices):
    from backtest.strategies.my_strategy import MyStrategy
    s = MyStrategy()
    w = s.generate(synth_prices)

    # 输出形状与输入匹配
    assert w.shape == synth_prices.shape
    # 每行权重之和≈1.0 或全零
    row_sums = w.sum(axis=1)
    assert all((abs(row_sums - 1.0) < 0.01) | (row_sums == 0.0))
```

### 6.4 运行回测验证

```bash
python run_backtest.py  # 确认新策略出现在绩效表中
python -m pytest tests/ -v -k "my_strategy"  # 确认测试通过
```

## 7. Dashboard：如何启动和使用

### 7.1 启动 Dashboard

```bash
cd etf-strategies/dashboard
python app.py
```

首次启动会自动：
- 创建 SQLite 数据库（`data/cache.db`）
- 生成 JWT 密钥（`data/.secret_key`）
- 创建默认用户 `admin` / `admin123`
- 同步策略种子数据

访问 `http://localhost:8000`，使用 `admin` / `admin123` 登录。

### 7.2 API 端点

所有 `/api/*` 端点需要 JWT Bearer Token（登录后自动管理）。

| 端点 | 用途 |
|------|------|
| `/api/strategies` | 获取所有策略绩效指标 |
| `/api/strategies/{sid}` | 获取单策略详情（KB + 指标） |
| `/api/strategies/{sid}/source` | 获取策略源码 |
| `/api/strategies/{sid}/diagnostics` | 获取策略内部状态（动量得分等） |
| `/api/signals` | 获取所有策略当日信号 |
| `/api/backtest/run` | 触发全量回测 |
| `/api/refresh/signals` | 强制刷新信号 |
| `/api/refresh/klines` | 增量同步K线 |

### 7.3 数据同步

Dashboard 启动时自动执行种子数据填充和K线同步。后续可通过 API 手动触发：

```bash
# 强制刷新所有信号
curl -X POST http://localhost:8000/api/refresh/signals \
  -H "Authorization: Bearer <token>"

# 增量同步K线
curl -X POST http://localhost:8000/api/refresh/klines \
  -H "Authorization: Bearer <token>"
```
