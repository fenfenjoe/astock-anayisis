# A股（重点 ETF）免费/低成本实时行情数据源稳定性调研报告

> **数据时点**：2026-10-10（周五，休市后）｜**调研方式**：豆包搜索（byted-web-search）联网检索 + 项目 `a-stock-data` skill 端点实测记录 + 本项目现状（`em_client.py`/`data.py`/`daily_signal.py`）核对
> **背景**：本项目现用东财 `push2his` HTTP 拉日K（`em_get` 1s 限流），曾尝试 mootdx（通达信 TCP 7709）但海外/受限网络超时；东财对部分大陆住宅 IP 间歇风控（HTTP 000/空数据）。痛点＝盘中实时行情稳定性。
> **一句话结论**：2026 年免费行情源已发生结构性变化——**mootdx 通达信公开服务器 K线/盘口/逐笔命令自 2026-09 起失效**，**腾讯财经已成免费源事实首选**（不封IP、含分钟线/分时/当日逐笔）；东财仍是最丰富但风控最严的源。方案应从"东财单源"升级为"**腾讯为主 + 东财(限流)为备 + 新浪兜底 + 本地 parquet 缓存**"的多源容错架构，并预留 **miniQMT（10万门槛免费）** 作为推送式行情升级路径。

## 1. 免费实时行情源逐个评估

### 1.1 腾讯财经行情（qt.gtimg.cn / ifzq.gtimg.cn）—— ⭐ 首选主源

**端点与能力**
- 实时报价：`https://qt.gtimg.cn/q=sh510300,sz159915,...`（HTTP GET，GBK 编码，`~` 分隔 88 字段：现价/今开/最高/最低/昨收/PE/PB/市值/换手率/涨跌停价等）。支持**批量**（逗号分隔，实测一次数十只稳定）。
- 分钟K线：`https://ifzq.gtimg.cn/appstock/app/kline/mkline?param=sh510300,m1,320`（`m1/m5/m15/m30/m60` 分钟线；日线用 `/kline/get?param=sh600519,day,,,320,qfq`）。
- 当日逐笔成交：`tencent_ticks()`（V3.10 新增，替代 mootdx 逐笔，一次约 25s 拉全 A 当日逐笔）。
- 分时：`stock.gtimg.cn/data/index.php` 及行情页分时接口。

**稳定性 / 限流 / 封IP**
- **不封 IP**（实测），海外可直连（腾讯 CDN 全球加速）。
- ⚠️ 已知限制：**K线单入口约 600 次后触发限流**，需在多个腾讯 host 入口间轮换（a-stock-data V3.7+ 已内置三入口轮换）。
- 实时报价入口（`qt.gtimg.cn`）本身很稳，分钟K线/逐笔接口偶发慢。

**Python 调用方式**：裸 `requests`/`urllib` + `decode("gbk")` 即可，零依赖、零 key。项目 skill 已有 `tencent_quote()` 完整实现可直接抄用。

**历史数据能力**：日/周/月/分钟 K线（**前复权**，腾讯是少数免费提供前复权分钟/日K的源）；当日逐笔。历史深度不如东财 push2his，但覆盖本项目回测够用。

**ETF 专项**：510xxx/588xxx 等沪市 ETF、159xxx 深市 ETF 全覆盖，字段含 IOPV 附近指标（部分 ETF 字段），是 ETF 做 T 最合适的免费源。

> 来源：[a-stock-data（SkillsLLM 镜像，含腾讯三入口轮换）](https://skillsllm.com/skill/a-stock-data)｜[腾讯分钟K线接口（CSDN）](https://blog.csdn.net/afgasdg/article/details/86071921)｜[腾讯行情API（LobeHub allstock-data）](https://lobehub.com/skills/openclaw-skills-allstock-data)

### 1.2 新浪财经行情（hq.sinajs.cn）—— 稳定备源 / 期权专属

**端点与能力**
- 实时报价：`https://hq.sinajs.cn/list=sh510300,sz159915`（GBK，逗号分隔字段）。
- **硬性要求**：必须带 `Referer: https://finance.sina.com.cn/`，否则 **403 Forbidden**（2022 年起强制执行）；建议同时带浏览器 UA。
- 分钟K线：`money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData`。
- **ETF 期权 T 型报价 / 希腊字母 / 隐含波动率**：新浪独有免费能力（本项目 skill §9 已实现）。

**稳定性 / 限流 / 封IP**
- 稳定，A 股免费；**港股实时行情需付费"港股直通卡"**（新浪官方，受港交所授权限制），A 股/ETF 不受影响。
- 限流：无硬性公开阈值，但建议控制频率（无正式文档）。
- 偶发高峰慢，无封 IP 报告（带 Referer 前提下）。

**Python 调用方式**：裸 `requests` + headers + GBK 解码；字段无正式文档，需按索引解析（skill 已有实现）。

**历史数据能力**：历史K线较弱（主要当日/近期），偏实时。用于"第二实时报价源 + 期权数据"。

### 1.3 东方财富 push2 / push2his（HTTP）—— 数据最全但风控最严

**端点与能力**
- 实时报价：`push2.eastmoney.com/api/qt/stock/get`（单只）、`/api/qt/ulist.np/get`（**批量**，fields `f2/f3/f12/f14` 等）。
- 分时：`push2his.eastmoney.com/api/qt/stock/trends2/get`（含**均价线**与成交额，是 t0/做T 条件计算的现成接口）。
- 历史K线：`push2his.eastmoney.com/api/qt/stock/kline/get`（`klt=1/5/15/30/60/101`，`fqt=0/1/2`）——本项目 `em_client.py` 现用端点。
- 独有数据（不可替代）：资金流分钟/日级、龙虎榜、两融、大宗、股东户数、研报、新闻、板块排名、涨停池等。

**稳定性 / 限流 / 封IP（社区实测 2026-05 阈值）**
| 行为 | 触发阈值 | 风险 |
|---|---|---|
| 每秒请求 | >5 次/秒 | 高 |
| 单 IP 并发连接 | ≥10 | 高 |
| 1 分钟请求总数 | ≥200 | 中高 |
| 5 分钟请求总数 | ≥300 | **触发封禁** |
| User-Agent | 空 UA | 中 |

- 被封表现：`403` / `429` / 连接超时 / **返回空数据（HTTP 000）**；临时封禁几分钟到几小时。
- ⚠️ 实测封禁案例（2026-06-30，a-stock-data issue #36）：住宅 IP 批量循环拉取被间歇风控，表现为"连续正常→突然空数据→隔几分钟恢复"，非代码 Bug。
- ⚠️ 知名社区案例：akshare 用户批量拉全市场 K线 **800~1500 只后必断**、盘中实时行情 **每几分钟失效一次**（详见 1.7）。

**Python 调用方式**：必须走项目 `em_get()`（串行限流≥1s+随机抖动 + 会话复用 + 退避重试），禁止裸 requests 高频调用。

**历史数据能力**：**最强**。全 A/ETF 前复权日K可回溯十余年，分钟K线完整，资金流 120 日等独有。

> 来源：[东财风控阈值（a-stock-data / SkillsLLM）](https://skillsllm.com/skill/a-stock-data)｜[东财分时接口 trends2（CSDN）](https://blog.csdn.net/meiaoxue1234/article/details/122859168)｜[akshare 东财限流实测（掘金）](https://juejin.cn/post/7649206162342887474)

### 1.4 百度股市通（gushitong.baidu.com / finance.pae.baidu.com）—— 备用 K线

**端点与能力**
- K线（**带 MA5/10/20**）：`https://finance.pae.baidu.com/selfselect/getstockquotation?all=1&code=510300&isIndex=true&...&ktype=1&market_type=ab&group=quotation_index_kline&finClientType=pc`。
- 实时盘口：`gushitong.baidu.com/opendata?...`（需抓包定位，结构深）。

**稳定性 / 限流 / 封IP**
- **需带浏览器 UA + Cookie**，无 cookie 时返回 `ResultCode:403` 空数据；高频同 headers 易被判爬虫。
- 封 IP 风险低（零鉴权，但要求像浏览器），稳定性中等。
- 已知坑：`ResultCode` 返回类型不稳定（int 或 string），必须 `str(...)!="0"` 统一比较。

**Python 调用方式**：裸 `requests` + 预置 cookie/headers（skill 已有实现）。

**历史数据能力**：日K带均线，可用于备胎；分时/实时能力弱于腾讯/东财。

### 1.5 mootdx / pytdx（通达信 TCP 7709）—— ⚠️ 2026-09 起行情失效 + 海外不可用

**协议与能力**
- 通达信 TCP 7709 二进制协议，`pytdx`（底层）/ `mootdx`（封装）。
- 原能力：K线、五档盘口、逐笔成交、财务快照、F10。

**🔴 重大变化（2026-09）**：通达信**公开服务器的 K线/盘口/逐笔命令失效（返回空）**——a-stock-data V3.9.0（2026-09-20）/V3.10.0（2026-09-22）记录 issue #52，已将行情层从 mootdx 迁移到"腾讯 → 腾讯K线 → 通达信盘后包 → 腾讯逐笔"。**mootdx 现在只用于财务快照与 F10**（财务接口仍正常）。
> 这意味着：即使网络可达，mootdx 也拿不到 K线/盘口了。本项目"用 mootdx 补行情"的旧认知必须更新。

**服务器列表与替代端口**（skill 内置 10 个，全 7709）：
`119.97.185.59 / 124.70.133.119 / 116.205.183.150 / 123.60.73.44 / 116.205.163.254 / 121.36.225.169 / 123.60.70.228 / 124.71.9.153 / 110.41.147.114 / 124.71.187.122`
- 这些是**公共测试服务器**，时常被换/超时；`pytdx` 建议从通达信客户端"选项→通讯设置→行情主站"抓当前 IP（`netstat -ano | findstr 7709`）。
- 社区已验证：服务器 IP 会老化（如 124.71.187.122 曾失效），需 `socket` 探活 + 列表兜底（skill `tdx_client()` 已实现）。
- **海外/受限网络：TCP 7709 全部超时**——这是协议层限制，无法绕过，只能走 HTTP 源或国内代理。

**官方替代（HTTP）**：通达信官网提供**沪深京日线完整包 HTTP 下载**（`https://www.tdx.com.cn/article/vipdata.html`，zip 覆盖 vipdoc 目录，2026-10-09 仍更新）——这是官方、免风控的历史日K备份源。另：通达信量化平台支持本地客户端 HTTP 调用 `POST http://127.0.0.1:17709/`（TdxQuant）。

## 2. 专业行情源对比（升级路径）

### 2.1 QMT / miniQMT（迅投）—— ⭐ 最现实的免费升级路径

- **能力**：`xtquant`（`xtdata` 行情 + `xttrader` 交易）。**全市场实时推送行情**（订阅式，毫秒级，含 tick），替代轮询；本地 Python（VS Code/Jupyter）直连，不上云。
- **费用**：**免费**（券商免软件费），仅需开证券账户。
- **2026 门槛**：miniQMT **10 万**（20 交易日日均资产，股票/现金/基金都算）、C4 风测、6 个月交易记录；QMT 标准版 30~50 万。支持券商：**国金/华宝/中金/华西/银河/开源/国信**等（需客户经理渠道开白名单，APP 自助开户无权限）。
- **数据质量**：Level-1 全市场推送；**Level-2 部分券商支持**（十档+逐笔，QMT 内可直接订阅）。
- **⚠️ 对用户的重要限制**：
  - 需登录券商行情/交易服务器——**海外网络可能连接不稳，部分券商明确不支持云服务器/海外运行**；
  - **部分券商已不再维护 miniQMT**（功能阉割/废弃），申请前须问清是完整版还是阉割版；
  - 仍需 A 股证券账户（用户应有）。
- **结论**：若用户在海外但有可用的国内节点/代理跑 QMT，这是免费获得推送式行情的首选；否则回到 HTTP 多源方案。

## 3. 多源容错架构建议（主源 + 备源 + 本地缓存）

### 3.1 总体架构（三层降级）

```
请求入口
  ├─ 内存缓存（会话级）：同一天同一标的，秒级 TTL 内复用
  ├─ 主源（腾讯 qt.gtimg.cn / ifzq）        → 实时报价 / 分钟K / 分时
  ├─ 备源（东财 push2/push2his，走 em_get）  → 分时/分钟K/独有数据（资金流等）
  ├─ 兜底（新浪 hq.sinajs.cn）               → 实时报价 / 期权
  └─ 本地持久化（parquet/SQLite）
        ├─ 历史日K（东财→通达信盘后包→网易，多备胎）
        ├─ 盘中分钟快照（每轮拉取落盘，可回溯当日）
        └─ 交易日历 + 昨收基准（交叉验证用）
```

### 3.2 "主+备+缓存"分工设计

| 角色 | 源 | 职责 | 频率 |
|---|---|---|---|
| **主** | 腾讯 | 自选池批量实时报价（一次拉 30~60 只）+ 分钟K + 分时 | 报价 3~5s；分钟K 每分钟 |
| **备** | 东财（em_get） | 主源失败时顶替；**独有数据照常走 em_get**（资金流/龙虎榜等） | 独有数据 1~2s/次；作为备 15s 冷却 |
| **兜底** | 新浪 | 报价双源交叉验证 / 腾讯东财都挂时保底 | 低频 10s |
| **本地** | parquet | 历史K缓存（现 `data.py` 已有）+ 当日分钟快照落盘 | 增量写 |

**关键原则**：
1. **东财永远走 `em_get`**（≥1s 间隔 + 抖动 + 会话复用），即使作为备源也不突破限流；
2. **缓存是第一道防线**：`data.py` 已实现"缓存覆盖即零 API"，扩展到分钟级（当日分钟快照）可让盘中高频轮询绝大部分命中内存/磁盘缓存，显著降 API 调用量（社区经验：批量拉取+本地缓存+交易日历对齐可降调用量 50~80%）；
3. **腾讯做主力后，东财调用量自然下降**，间接降低被封概率。

### 3.3 健康探测与自动切换

- **每轮请求记录四元组**：`(源, 标的, 成功?, 延迟ms, 返回完整性)`，写滚动窗口（如最近 50 次）。
- **健康判定**：某源连续失败 ≥3 次 / 单次超时 >5s / 返回空或 `HTTP 000` / 字段缺失（现价/昨收为 None）→ 判"不健康"。
- **自动切换**：
  - 主源不健康 → 切备源（东财），主源进入**冷却**（如 60s 退避，退避时间指数增长）；
  - 冷却期结束做**一次探活**（单标的单请求），恢复即回切主源；
  - 备源也不健康 → 切新浪兜底；全挂 → 直接用本地缓存（标记"陈旧数据"，见 3.4/3.5）。
- **降级不静默**：每次降级写日志 + 触发通知（复用项目 `notify.py` / agent 通知）。

### 3.4 数据一致性校验（多源交叉验证）

- **双源价差校验**：盘中主+备各取一次（不必每轮，可每 10 轮抽样），同一标的 `(腾讯现价, 东财现价)` 差异 >0.5%（ETF 阈值，股票可放宽到 1%）→ 告警 + 标记该轮数据可疑，用第三源（新浪）裁决。
- **内部一致性**：`现价` vs `昨收×涨跌幅` 应吻合（涨跌幅=(现价/昨收-1)×100%）；分时尾点价 == 最新报价；分钟K最后一根 close == 当前价。任一不符 → 判数据异常。
- **基准锚定**：开盘后以"昨收 + 涨跌停价"校验 price 落在 [跌停, 涨停] 内（涨停/跌停附近 ask/bid 为空属正常，勿误报）。
- **历史完整性**：日K增量更新后核对"末根日期 == 最近交易日"（BUG-011 同款逻辑）；ETF 份额调整（合并/拆分）导致价格跳变 >15% 时做检测，不做跨除权日直接比较（skill 已有 `detect_etf_corp_action`）。

### 3.5 告警

| 级别 | 场景 | 动作 |
|---|---|---|
| INFO | 单源单次失败（已重试成功） | 日志 |
| WARN | 主源连续失败切换备源 / 双源价差超阈 | 通知（app 推送/agent） |
| ERROR | 全部源不可用 / 单标的连续空数据 | 通知 + 停用该标的信号（**禁止用陈旧数据触发做T信号**） |
| 每日 | 收盘后完整性检查（缓存缺口、源健康度汇总） | 写入日志/看板 |

> 设计要点来源：[腾讯云"免费数据源限频三步法"（批量拉取/本地缓存/交易日历对齐）](https://cloud.tencent.cn/developer/article/2740727?policyId=1003)｜[行情接入验证检查卡（状态码/字段/告警）](https://cloud.tencent.com/developer/article/2675735?frompage=seopage)｜[pyqauto 多源路由+审计参考实现](https://pypi.org/project/pyqauto/)

## 4. 盘中实时监控的数据需求（盘中信号 / 做T）

### 4.1 场景需求拆解（结合本项目"做T信号规则/ETF做T信号规则"）

| **分钟K线**（1/5/15min） | 日内结构、MACD/均线信号 | 每根收线后 | 腾讯 `ifzq mkline`（主）；东财 `kline/get klt=1/5`（备） |

### 4.2 推荐数据获取方案（结合现有 em_get 限流客户端）

**A. 最小改造（推荐，1~2 天内落地）——腾讯接管行情，东财退居备胎**
1. 新增 `tencent_client.py`：`tencent_quote(codes)`（批量报价）+ `tencent_mkline(code, period)`（1/5/15分钟）+ `tencent_trends(code)`（分时）。
2. 盘中信号主循环：**报价走腾讯（3~5s 批量）**，分时/分钟K 走腾讯；`em_get` 只保留——分时均价（若腾讯分时不含均价则用东财 trends2）、独有数据（资金流/龙虎榜）。
3. `data.py` 扩展：新增 `当日分钟快照 parquet`（每轮增量写，跨重启可回溯当日）；历史日K 增加"腾讯→东财→通达信盘后包"三级降级。
4. 健康探测 + 自动切换 + 价差交叉校验（第 3 节四件套）挂到 `daily_signal.py` 的主循环。

**B. 免费推送升级（推荐长期，消除轮询）——miniQMT / 东财掘金**
- 若用户可申请到 **miniQMT（10 万门槛）**：`xtdata` 订阅自选池，秒级推送，彻底告别 HTTP 轮询与限流；本项目策略层接口不变（行情入口换成 xtdata 适配器即可）。
- 若已有东财账户：申请**东财掘金 EMT**，`subscribe(frequency='60s'/'300s')` 订阅，与 push2 同源但走官方通道，比 HTTP 抓包稳定得多。
- 注意：两者均需国内网络/券商服务器可达；海外跑就退回方案 A。

**C. 做T场景注意**：分时均价线是 T0 关键（成本锚点），东财 `trends2` 是免费源里最现成的（`fields2=f51~f58` 含均价）；用腾讯做实时价、东财做均价线、交叉校验后计算"价差偏离"，是当前免费约束下性价比最高的做T数据组合。

### 5.2 多源容错设计要点（落地清单）

1. **主备兜三层**：腾讯（主）→ 东财 em_get（备）→ 新浪（兜底）→ 本地缓存（陈旧兜底），逐级降级不中断。
2. **东财永不裸调**：所有 eastmoney 请求走 `em_get()`（串行 ≥1s + 抖动 + 会话复用 + 退避重试），独有数据也限流——这是防封铁律，也是全方案能成立的前提。
3. **缓存三件套**：内存 TTL 缓存（秒级）+ 当日分钟快照 parquet（盘中）+ 历史日K parquet（现有 `data.py`），缓存覆盖即零 API，调用量降 50~80%。
4. **健康探测**：滚动窗口统计（成功率/延迟/空数据），连续失败 3 次即切换 + 指数退避冷却 + 探活回切。
5. **交叉校验**：双源价差（ETF 0.5%）抽样比对 + 内部一致性（现价≈昨收×涨跌幅、分时尾点≈最新价）+ 涨跌停边界锚定 + ETF 份额调整检测。
6. **降级不静默 + 陈旧数据禁触发信号**：每次降级写日志 + 通知（复用 notify/agent）；全部源不可用时**停用做T信号**，绝不用缓存价下信号。
7. **海外网络专项**：mootdx/JQData 直接排除；QMT 先确认券商是否支持海外/云服务器；HTTP 三源（腾讯/东财/新浪）海外实测均可直连，优先腾讯（CDN 加速）。
8. **长期升级**：行情入口抽象成 `QuoteSource` 接口（`realtime(codes)` / `mkline(code, period)` / `trends(code)` / `history(code, start, end)`），HTTP 实现与 `xtdata`（miniQMT）实现可无缝切换——先落地 HTTP 多源，条件具备再插 miniQMT，策略层零改动。
