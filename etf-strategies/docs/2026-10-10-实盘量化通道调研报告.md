# 个人投资者 A股量化实盘方案调研报告（2025–2026）

> **数据时点：2026-10-10**（本报告基于截至 2026-10-10 的公开联网检索整理）
> **定位**：为本地 Python ETF 量化系统（`etf-strategies` / `daily_signal.py` 信号 → 实盘）做方案选型。
> **一句话结论（先看这里）**：2026 年监管已剧变——**miniQMT 新申请已停发、存量在清退，大QMT 的外部 Python 直连也在收紧**。当前对散户最稳、最合规的「信号→实盘」路径是：**迁移到标准版 QMT（大QMT）内置 Python 沙箱**，通过官方合规通道（文件/Redis/HTTP 桥接）接收你本地 `daily_signal.py` 生成的信号；次选是 **PTrade 云端**（券商合规管控内，但三方库受限、迁移成本高）。**不推荐新开 easytrader UI 自动化**（停止维护 + 2026 外接新规下风险高）。

**要点解读**：
- **MiniQMT 停用原因**：MiniQMT 允许本地原生 Python 通过 xtquant 直连券商接口，易被认定为「外接系统」，触碰 2026 外接新规红线。目前**无迅投/证监会统一红头文件**，是券商集体收紧（多家中型券商已发内部通知，国金 2026-08-21 明确关闭存量）。
- **外接新规核心**（中证协发〔2026〕181 号，共 5 章 33 条）：券商对外接实行**备案制+全程管理+主体兜底**；对客户身份/账户/资金/交易行为**全程穿透**；**明文取消「通道特权」**（专属高速通道、独立服务器托管、优先报盘、低延迟机柜等差异化安排一律违规）。量化成交已占两市约 20%–25%，监管明确「非禁止量化，而是阳光化」。
- **对散户的实质影响**：标准版 QMT 客户端（策略跑在券商提供的终端内置 Python 沙箱内）和 PTrade 云端，**全流程在券商合规管控体系内，不属于「外部接入」**，仍可承接个人量化需求（财联社解读）——这正是券商 2026 年加大推广 QMT/PTrade 的原因。

## 1. QMT / miniQMT（迅投 ThinkTrader）

### 1.1 是什么
- **QMT**（Quantitative Market Trading）= 迅投（睿智融科）研发的券商端智能交易终端，本地运行，覆盖主观+量化全谱系。支持**股票、ETF、LOF、可转债、两融、期权、期货、北交所、港股通**。
- **miniQMT（极简模式）**= QMT 的轻量版，核心卖点是**支持外部原生 Python 环境 + xtquant API**：任意 IDE（VS Code/PyCharm/Jupyter）、`pip` 任意装三方库、外部爬数据，实盘链路=「本地 Python 直连 miniQMT 客户端 → 券商」。
- 迅投官方定位 QMT 面向「量化私募、职业交易员、高频团队」，本地部署、数据不出内网、实盘延迟 <1ms。
- 来源：迅投官网 [thinktrader.net/about#/products/qmt](https://www.thinktrader.net/about#/products/qmt)；miniqmt.com QA [miniqmt.com/pages/qa/knowledge-qa.html](https://www.miniqmt.com/pages/qa/knowledge-qa.html)

### 1.2 开通门槛（2025→2026 变化）
- **资金门槛**：2025 年已大幅下降，主流从 50 万降到 **10 万**起；部分券商可谈更低。**2026 年最新分层**（搜狐「方略说财经」2026-09-21）：
  - 基础版/极速接口：**约 10 万**（国金、银河、中金财富、国泰海通、方正等）
  - 完整版 QMT：多为 **10–50 万**（中信、华泰、国金、国泰海通、中信建投等）
  - 极速高频柜台 API：**100–300 万**（广发极速量化柜台要求 300 万日均）
  - 来源：[news.sohu.com/a/1078962777_121751844](https://news.sohu.com/a/1078962777_121751844)
- **资质**：18–65 岁、风险测评 **C4/C5**（部分券商 C3 即可）、部分要求 6 个月以上交易经验；账户无休眠/冻结/违规记录；**必须通过客户经理专属链接开户或老户补录「量化白名单」**（自助开户一般无量化入口，90% 新手的坑）。
- **审核**：1–3 个工作日，全程线上，通过后券商邮件发软件下载链接。
- **费用**：QMT/miniQMT **本身免费**（无年费/开通费），只收正常交易佣金（可协商低佣，ETF 常见万 0.5–万 1 免五）。**凡是收费代开的基本是套路**。
- 来源：[m.sohu.com/a/919110340_121751016](https://m.sohu.com/a/919110340_121751016)；[m.sohu.com/a/1024059280_121752051](https://m.sohu.com/a/1024059280_121752051)

### 1.3 Python API 能力（xtquant）
- 模块：**`xtdata`**（行情/数据）+ **`xttrader`**（交易）。
- **xtdata**：`get_market_data`（K线）、`subscribe_quote`（实时订阅）、`get_full_tick`、`get_l2_quote/order/transaction`（L2 逐笔，需权限）、`download_history_data`、`get_financial_data`（财务）、`get_instrument_detail`、`get_stock_list_in_sector`（板块成分）等。来源：[zsrl.github.io/xtquant-doc/xtquant/xtdata.html](https://zsrl.github.io/xtquant-doc/xtquant/xtdata.html)
- **xttrader 下单**：`order_stock`（同步）、`order_stock_async`（异步）、`cancel_order_stock`（撤单）、查询账户/持仓/委托/成交；**委托类型含 ETF 申赎**。典型代码：
  ```python
  from xtquant.xttrader import XtQuantTrader
  xt_trader = XtQuantTrader('D:\\迅投极速交易终端 睿智融科版\\userdata_mini', 123456)
  xt_trader.start(); xt_trader.connect()
  order_id = xt_trader.order_stock(acc, '510300.SH', xtconstant.STOCK_BUY, 1000, xtconstant.FIX_PRICE, 4.10, 'strategy', 'remark')
  ```
  来源：迅投知识库 [dict.thinktrader.net/nativeApi/xttrader.html](https://dict.thinktrader.net/nativeApi/xttrader.html)
- **ETF 交易**：完全支持（股票/ETF/可转债买卖 opType=23/24），代码后缀沪 `.SH`、深 `.SZ`。
- **QMT 内置 Python 环境**：基于 Python 3.6，自带 numpy/pandas/scipy 等，其余三方库**需券商开白名单**（券商版默认白名单受限）；miniQMT 则是本地任意 pip。来源：迅投知识库 [dict.thinktrader.net/innerApi/question_answer.html](https://dict.thinktrader.net/innerApi/question_answer.html)
- **注意**：QMT 交易接口是异步的，委托/成交/持仓来自**客户端本地缓存**（主推柜台 50ms 刷新，非主推 1–6s），实盘策略需自己维护委托状态（"待报→已报→成交"），避免重复下单。

### 1.4 支持券商（2026 年参考清单）
| 门槛档 | 券商 | 备注 |
|---|---|---|
| 低（~10 万） | 国金、国信、华西、大同、德邦、开源、银河（基础版） | 国金同时支持 QMT/miniQMT/PTrade 且都免费，社区口碑最好 |
| 中（30–50 万） | 华泰、中金财富、国泰君安、银河（全功能）、广发、招商、国海（30 万） | 头部券商，系统稳定 |
| 高（100–300 万） | 华泰、国泰君安等（极速柜台/LDP） | 面向高频 |
来源：次方量化 2026 清单 [blog.cifangquant.com/post/111.html](https://blog.cifangquant.com/post/111.html)；叩富 [licai.cofool.com/user/guide_view_3488601.html](https://licai.cofool.com/user/guide_view_3488601.html)

### 1.5 miniQMT 是否适合个人、能否 Python 直接下单
- **历史结论（2025 及以前）**：是——门槛低（10 万）、免费、本地 Python 直连下单（xtquant `order_stock`/`passorder`），是散户最主流方案。
- **2026 现状（关键！）**：**不再适合新开**。2026-07-06 起新申请基本停发，存量预计 1–2 个月内逐步清退（国金 2026-08-21 已确认）。若你已有存量 miniQMT，可短期过渡但**务必规划迁移**。
- **应对路径**（WTSolutions 建议）：
  1. **迁移到标准版 QMT（大QMT）内置 Python**——API 名基本一致，环境改为客户端沙箱，适合中低频（你的日频/盘中调仓完全够）；
  2. 简单定时选股+手动确认下单，可先用大 QMT 内置；
  3. 依赖复杂三方库/外部数据源的重度策略 → 考虑 PTrade（但库受限，需评估）或「大 QMT + 外部信号桥接」。
  - 来源：[invest.wtsolutions.cn/posts/miniqmt-termination/](https://invest.wtsolutions.cn/posts/miniqmt-termination/)；[developer.cloud.tencent.com.cn/article/2704635](https://developer.cloud.tencent.com.cn/article/2704635)

## 2. Ptrade（恒生电子）

### 2.1 是什么 / 与 QMT 差异
- **Ptrade** = 恒生电子研发的**云端托管**量化终端，策略运行在**券商服务器**上（非本地），关机断网不影响自动执行，对上班族友好。
- 核心差异（搜狐 2026 对比文章）：
  | 维度 | QMT（迅投） | PTrade（恒生） |
  |---|---|---|
  | 运行位置 | 本地客户端 | 券商云端 |
  | 编程 | Python+VBA（内置白名单库） | 仅 Python（云端白名单库） |
  | 上手 | 硬核、全代码 | 零代码模板多（网格/ETF轮动/条件单/篮子），新手友好 |
  | 回测 | 内置 tick→年线引擎 | 仅分钟/日线 |
  | 高频/极速 | 支持（需高门槛极速柜台） | 不强（中低频够用） |
  | 数据 | 自带 L2+，可接三方库 | 自带 L2+ |
  | 代码后缀 | 沪 `.SH`/深 `.SZ` | **沪 `.SS`/深 `.SZ`**（迁移大坑） |
  | 下单函数 | `passorder`（参数多） | `order`（3 参数） |
  - 来源：[m.sohu.com/a/1064886130_121752051](https://m.sohu.com/a/1064886130_121752051)；[m.sohu.com/a/1075716177_121752051](https://m.sohu.com/a/1075716177_121752051)
- **品种**：股票、ETF、LOF 买卖、**ETF 申赎**、可转债、两融、股指期货、国债逆回购（恒生官方模拟版说明）。来源：[hs.net/openplat-front/service/serviceDetail/365](https://www.hs.net/openplat-front/service/serviceDetail/365)

### 2.2 开通门槛
- 与 QMT 基本一致：个人 **10 万**起（国金 10 万线上开通），申万宏源要求 50 万+T-1 资产+1 年经验；部分券商要求 300 万+；有券商一直未对个人开放 PTrade 通道。来源：[m.toutiao.com/group/7690807397509497385](http://m.toutiao.com/group/7690807397509497385/)
- 支持券商：国金、国盛、东莞、湘财、长江、国泰君安-海通等（ptradeapi.com 列示）。来源：[ptradeapi.com](http://ptradeapi.com/)
- 费用：软件免费，收交易佣金；恒生官方**模拟环境** AI 版 ¥559/90 天（仅供学习，不支持实盘）。

### 2.3 优缺点小结
- **优点**：云端托管省心、稳定性高、券商合规管控内（2026 外接新规下地位稳固）、零代码模板适合快速上手。
- **缺点**：三方库白名单受限（Pandas/NumPy/机器学习库通常可以，但冷门库大概率装不了）→ **从你本地 daily_signal.py 重度依赖自研/外部库的策略迁移成本高**；API 与 QMT 完全不同（函数名/后缀/下单方式都要重写）；回测仅分钟/日线。

## 3. easytrader（开源，券商客户端 UI 自动化）

### 3.1 项目状态
- GitHub `shidenggui/easytrader`（Gitee 镜像同为 `shidenggui`），**最后一次版本发布 0.20.4 约在 2019–2020 年（距今约 6 年），基本停止维护**。Gitee 镜像 commit 记录：`Bump version: 0.20.3 → 0.20.4` 为 6 年前最后提交。来源：[gitee.com/sunnyu/easytrader](https://gitee.com/sunnyu/easytrader)
- 官方文档：easytrader.readthedocs.io（master 分支仍在）[easytrader.readthedocs.io/zh-cn/master/](https://easytrader.readthedocs.io/zh-cn/master/)

### 3.2 支持券商客户端
- 海通客户端（独立委托）、**华泰**（网上交易专业版Ⅱ）、**国金**（全能行 PC 版）、**通用同花顺客户端**、其他券商专用同花顺版（银河双子星/国金核新等，需手动登录）。
- 现版本也支持对接券商 **miniqmt 官方量化接口** 与雪球组合调仓。

### 3.3 原理与依赖
- 原理：用 pywin32 模拟操作客户端 UI（xiadan.exe）自动下单。前置要求苛刻：客户端需设置「界面不操作超时=0」「默认买卖价格/数量置空」，**客户端不能最小化/精简模式**；验证码需装 tesseract（银河可自动登录，其他券商常需手动登录后接管）；云部署需 TightVNC。来源：[easytrader.readthedocs.io/zh-cn/master/install/](https://easytrader.readthedocs.io/zh-cn/master/install/)

### 3.4 风险与是否适合个人（2026 判断）
- **维护风险**：作者停更多年，券商客户端 UI 一变（如华泰/同花顺改版、加强风控滑块/短信验证）即失效，社区依赖个人 patch，无保障。
- **合规风险（重点）**：UI 自动化属「客户端模拟操作」，在 2026-08-28 外接新规「穿透管理、备案制、主体兜底」语境下处于**灰色地带**——它实质是用脚本驱动券商交易终端，券商/交易所难以穿透核验，监管方向明确收紧此类行为；一旦券商端做 UI 风控升级或要求程序化报告，easytrader 路线首当其冲。
- **结论**：**不再适合作为新的实盘通道**。仅可保留用于「研究/模拟、手动确认」等低风险场景；不推荐接真金白银自动下单。若坚持用，务必：仅日频低频、履行程序化交易报告义务、设人工确认与熔断。

## 4. vn.py（vnpy，开源量化框架）

### 4.1 现状
- 活跃开源框架，当前社区版 4.5.0、Elite 2.0，MIT 协议，事件驱动引擎，官方文档齐全。来源：[vnpy.com](https://www.vnpy.com/)；[vnpy.com/docs/cn/community/info/gateway.html](https://www.vnpy.com/docs/cn/community/info/gateway.html)

### 4.2 对接券商通道现状（A股现货）
| 通道 | 品种 | 个人能否用 |
|---|---|---|
| CTP | 期货、期货期权 | ✅ 可（期货公司开户） |
| 中泰 XTP | A股、两融、ETF期权（现货账户含股票/ETF/债券/回购） | ⚠️ 需专业投资者认证 |
| 国泰君安统一交易网关 | A股、两融 | ⚠️ 需专业投资者认证 |
| 华鑫奇点股票 | A股 | ⚠️ 需专业投资者认证 |
| 顶点飞创 / 恒生 UFT / CTP期权 | ETF期权 | ⚠️ 需专业投资者认证 |

**关键障碍**：A股现货早已**关闭类似期货的开放式 API 接入**。vn.py 官方教程明确：现阶段 A 股可行的主要是「三方采购」模式——**专业投资者认证（自然人 ≥300 万金融资产 + 1 年投资经历）→ 券商三方系统采购 → 券商内网托管运行（盘中禁止外发行情/交易数据）**。来源：[vnpy.com/forum/topic/1947-vn-pykuai-su-ru-men-5-agu-zheng-quan-xtp](https://www.vnpy.com/forum/topic/1947-vn-pykuai-su-ru-men-5-agu-zheng-quan-xtp)

### 4.3 个人使用门槛（ETF 现货）
- **不友好**：对个人散户的 A股/ETF 现货实盘，直连 XTP/国泰君安/华鑫奇点基本不可行（300 万专业投资者门槛）。
- 社区有 `vnpy_x`（gitee.com/good-man-z/vnpy_x）可对接券商 **QMT/miniQMT 客户端**跑实盘——但这恰好**命中了 2026 年被清退的 miniQMT 外部直连路线**，且需要改源码、自行维护，现在更是踩在监管收紧点上。来源：[vnpy.com/forum/topic/33667](https://www.vnpy.com/forum/topic/33667-quan-shang-qmt-clientlian-jie-ji-shi-pan-wen-ti)
- **适合场景**：期货 CTA（CTP 直连成熟）、学习事件驱动框架、私募/机构自建报盘通道。对你的 ETF 日频信号 → 实盘，**不建议作为首选**。

## 6. 合规与风险（个人必读）

### 6.1 个人自用程序化交易是合法的，但要履行义务
- **程序化交易定义**：通过计算机程序自动生成或下达交易指令。你的 `daily_signal.py` 自动生成买卖信号并自动下单，**就属于程序化交易**，受监管规范。
- **必须履行的义务**（沪深北《实施细则》2025-07-07 施行）：
  1. **首次开展前向券商报告**：账户/资金（含杠杆）/交易策略类型/交易软件信息/最高申报速率等；券商核查确认后 5 个工作日内向交易所报告。
  2. **重大变更变更报告**（换策略、换软件、资金规模明显变化等）。
  3. **高频交易**（单账户每秒申报/撤单 ≥300 笔，或单日 ≥20000 笔）需额外报告服务器所在地/系统测试报告/应急方案，并面临**差异化收费**。
  4. 不得触发四类异常交易：瞬时申报速率异常、频繁瞬时撤单、频繁拉抬打压、短时间大额成交。
  - 你的**日频/盘中低频 ETF 调仓远够不到高频线**，正常合规即可，无需过度担忧。
  - 来源：[sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml)；上交所报告通知 [big5.sse.com.cn/site/cht/www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781705.shtml](http://big5.sse.com.cn/site/cht/www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781705.shtml)

### 6.2 2026「外接新规」对你的含义
- 《证券公司交易信息系统接入管理规范（试行）》2026-08-28 施行：券商对外接备案制+穿透管理；**取消通道特权**。
- **QMT/PTrade 在券商合规管控内，不算外部接入**——这是它们目前最安全的合规身份，也是券商加大推广的原因。
- **easytrader 类 UI 自动化、以及 miniQMT 本地 Python 直连，正是本轮被收紧的对象**。结论：**别把信号接到 UI 自动化通道上实盘**。

### 6.3 常见坑与提示
1. **必须走客户经理白名单**：自助开户一般没有量化入口，先联系客户经理确认门槛/佣金/能否开 QMT/PTrade。
2. **免费是主流**：QMT/PTrade 软件免费，收佣金即可；「付费代开」基本是骗局。
3. **程序化报告别漏**：开权限时券商一般会让你签《程序化交易承诺书》《风险揭示书》《软件使用协议》并报备——这是报告义务的一部分，务必配合完成，别用「手动下单」心态逃避。
4. **刑事/合规边界（与个人自用无关，但要知悉）**：上海「迅动量化」案（2025-05-19 二审维持）——无牌照卖「炒股机器人」软件被判**非法经营罪+侵犯著作权罪**，数罪并罚 7 年 9 个月、罚金 500 万。**红线是"对外销售/经营量化软件"**，你自己写策略自用完全合法；但**不要开发软件卖给别人**（哪怕 DIY 参数化）。
   - 来源：[mankunlaw.com/insights/ai-agent-stock-trading-legal-risks/](https://www.mankunlaw.com/insights/ai-agent-stock-trading-legal-risks/)
5. **技术风控**：自动交易必须带——资金/持仓校验、单日下单次数与金额上限、熔断开关（行情异常/连续亏损暂停）、委托状态机防重复下单、异常人工确认。

## 7. 与本项目集成的建议（信号 → 实盘）

你的现状：`etf-strategies/daily_signal.py` 本地生成 ETF 买卖信号（510300/513100/511880 等，日频或盘中调仓），已有一套成熟的本地 Python 回测/信号体系（a-stock-data 取数、pytest 测试、automation 调度）。目标是最轻量地打通「信号 → 实盘」。

### 前置条件（无论选哪条路径都成立）
1. 选定一家**支持 QMT 或 PTrade 且门槛可接受**的券商（低门槛推荐国金/华西/国信等 ~10 万），走客户经理专属通道开户/补录白名单，**确认支持标准版 QMT（大QMT）**。
2. 完成风险测评（C4/C5）、签署协议并**完成程序化交易报备**。
3. 先模拟盘跑通「信号→下单」全链路 1–2 周，再小资金实盘。

### 推荐路径（二选一，均可保留现有 daily_signal.py 与回测体系）

#### 路径 A（首选）：标准版 QMT 大QMT + 外部信号桥接（保留本地信号代码）
- **思路**：`daily_signal.py` 照旧在本地跑（数据/回测/信号逻辑完全不动），把**信号结果**通过合规桥接喂给大 QMT 客户端内置的下单脚本执行。
- **三种桥接方式**（社区已验证，按复杂度递增）：
  1. **文件监控**（最简）：本地策略把信号写入文本文件（如 `signals/20261010.json`），大 QMT 内置脚本轮询读取 → `passorder` 下单。**日频调仓首选，零新增依赖**。
  2. **HTTP API**：本地起 tornado/FastAPI 小服务，大 QMT 脚本 `requests` 定时拉取信号。
  3. **Redis**：信号写入 Redis，QMT 端实时订阅（适合盘中 T+0 高频场景）。
  - 来源：[developer.cloud.tencent.com.cn/article/2704635](https://developer.cloud.tencent.com.cn/article/2704635)
- **优点**：**信号逻辑/回测/取数零迁移**；策略最终在券商 QMT 客户端沙箱内执行，**合规身份好**；日频完全够用；成本=一个券商佣金户。
- **注意**：大 QMT 内置 Python 三方库白名单受限 → **把"计算"留在本地，QMT 只做"读信号+下单+回报"**，QMT 内只依赖 json/requests 这类基础库即可。
- **若你已有 miniQMT 存量**：短期可沿用 xtquant 外部直连，但按 2026 政策尽快迁移到上述大 QMT 模式。

#### 路径 B（次选）：PTrade 云端
- **思路**：把策略移植到 PTrade（`initialize/run_daily` + `order` 3 参数 + 沪市 `.SS` 后缀），跑券商云端。
- **优点**：云端托管不用挂机；券商合规管控内，地位稳固。
- **代价**：三方库白名单受限、API 全重写、回测仅分钟/日线 → 迁移成本高；**只在你不想要本地常驻、或所在券商 PTrade 更好开时才选**。
- 若未来监管进一步收紧本地 QMT 沙箱，PTrade 可作为 B 计划；两套可并行小仓试验。

#### 不推荐
- **easytrader UI 自动化**：停止维护 + 外接新规收紧，仅适合研究/手动确认场景。
- **vn.py 直连 XTP 等**：300 万专业投资者门槛，个人不现实。
- **掘金券商版**：多一层第三方终端依赖，不如直接券商自有 QMT/PTrade。

---

## 8. 推荐方案（最终结论）

> **首推：路径 A —— 标准版 QMT（大QMT）+ 文件/HTTP 信号桥接，保留本地 daily_signal.py 与回测体系。**
> 理由：① 合规身份最稳（策略在券商 QMT 沙箱内，2026 外接新规明确其不属于外部接入）；② 信号/回测/数据代码零迁移，改动量最小；③ 日频/盘中调仓完全够用，成本仅交易佣金；④ 与监管趋势（引导用券商自有终端）同向，长期可维护。

**实施路线图**：
1. 选券商（低门槛：国金/华西/国信，~10 万）→ 客户经理专属通道开户 → 确认标准版 QMT 权限 → 签署协议 + 程序化交易报备。
2. `daily_signal.py` 增加「信号落盘」模块：把当日信号（代码、方向、目标仓位、参考价、生成时间）写 `signals/*.json`，附带信号 ID 防重复。
3. 大 QMT 内置 Python 写一个「信号消费」脚本：轮询读取 → 资金/持仓校验 → `passorder` 下单 → 回报写日志 → 状态机防重。
4. 先模拟盘跑 1–2 周，再小资金（如每笔 ≤2 万）实盘过渡，逐步放大。
5. 持续配合券商完成程序化交易信息报备与重大变更报告；保留人工熔断开关。

**如果你已有 miniQMT 存量账号**：先沿用 xtquant 过渡，同时按第 7 节路径 A 迁移，赶在券商清退前完成。
