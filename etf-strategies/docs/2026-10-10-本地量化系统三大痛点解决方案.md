# 本地量化系统三大痛点解决方案

> **数据时点：2026-10-10**
> **定位**：针对 `etf-strategies` 本地量化系统的三个痛点（分钟级策略、实盘交易、实时K线稳定性）给出解决路径与落地路线图。
> **配套调研报告**：
> - 实盘通道：`docs/2026-10-10-实盘量化通道调研报告.md`
> - 实时行情：`docs/2026-10-10-免费实时行情数据源稳定性调研.md`
> - 分钟级：`docs/2026-10-10-分钟级数据源与本地回测方案调研.md`

---

## 痛点总览与优先级

| # | 痛点 | 现状 | 解决难度 | 优先级 |
|---|------|------|---------|--------|
| 1 | 不支持分钟级策略 | S21 聚宽分钟级回测年化 101.52%/夏普4.20，本地日频仅 40.00%/1.53（收益差2.5倍） | 中 | ⭐⭐⭐（价值最高） |
| 2 | 不支持实盘交易 | 仅 daily_signal.py 输出信号，无下单能力 | 中（券商门槛） | ⭐⭐ |
| 3 | 实时K线接口不稳定 | 东财 push2his 频繁风控（BUG-016~058 大量记录）；mootdx 2026-09 起行情失效 | 低（立即可做） | ⭐⭐⭐（基础，先做） |

**关键洞察**：痛点 3（实时行情）是痛点 1（分钟级）和痛点 2（实盘）的**基础设施前提**——分钟级需要稳定分钟价，实盘需要实时盘口/委托。因此建议**先解决痛点3，再解决痛点1，最后打通痛点2**。

## 痛点3：实时K线数据源不稳定 → 多源容错架构（先做）

**现状问题**：
- 东财 push2his 对部分大陆住宅 IP 间歇风控（HTTP 000/空数据/RemoteDisconnected），实测 2026-10-10 仍不可达
- mootdx（通达信 TCP 7709）**2026-09 起行情命令整体失效**（a-stock-data #52），且海外超时
- 单源依赖 → 任何单源波动都会中断

**解决方案**：升级为「腾讯主源 + 东财备源 + 新浪兜底 + 本地缓存」多源容错架构

| 优先级 | 数据源 | 角色 | 用途 |
|---|---|---|---|
| **1** | **腾讯**（qt.gtimg.cn / ifzq.gtimg.cn） | 主源 | 批量实时报价 + 分钟K（前复权）+ 分时 + 当日逐笔；不封IP、海外可直连 |
| **2** | **东财**（push2/push2his，走 em_get） | 备源+独有 | 分时(含均价 trends2)/分钟K/历史K最深；资金流·龙虎榜·两融等独有数据 |
| **3** | **新浪**（hq.sinajs.cn） | 兜底+期权 | 报价双源交叉验证；ETF 期权 T型/希腊字母/IV |
| **4** | 通达信盘后包 / 网易 | 历史备份 | 历史日K官方包 / 财务 |
| 升级 | **miniQMT**（10万免费）/ 东财掘金 EMT | 推送式行情 | 秒级/tick 订阅替代轮询（长期） |

**落地清单**：
1. 新增 `tencent_client.py`（批量报价 + 分钟K + 分时），复用 a-stock-data 的 `tencent_quote()` 实现
2. 东财永不裸调（继续走 `em_get` 1s+限流）
3. 缓存三件套：内存TTL + 当日分钟快照parquet + 历史日K parquet
4. 健康探测 + 自动切换 + 交叉价差校验（ETF 0.5%阈值）
5. 降级不静默 + 陈旧数据禁触发信号
6. 行情入口抽象 `QuoteSource` 接口（为 miniQMT 预留无痛切换位）

**预计工作量**：1~2 天内落地（腾讯封装 + 容错 + 校验）。

## 痛点2：不支持实盘交易 → 标准版 QMT + 信号桥接

**2026 监管剧变**（详见实盘调研报告）：
- miniQMT 新申请停发、存量清退（国金 2026-08-21 已确认）
- 2026-08-28 外接新规：备案制 + 穿透管理，easytrader UI 自动化不推荐

**推荐方案**：**标准版 QMT（大QMT）+ 外部信号桥接**，保留本地 `daily_signal.py` 与回测体系

```
daily_signal.py (本地)         大QMT 客户端 (券商沙箱)
  ├─ 信号计算                    ├─ 内置 Python 轮询脚本
  └─ 写 signals/*.json ────────→ └─ 读信号 → passorder 下单 → 回报日志
```

- 桥接方式：文件监控（日频首选）/ HTTP API / Redis（盘中高频）
- 前置：客户经理白名单开户（国金/华西/国信 ~10万）→ 程序化交易报备 → 模拟盘1-2周 → 小资金过渡
- 技术风控：资金/持仓校验、单日次数/金额上限、熔断开关、委托状态机防重

## 痛点1：不支持分钟级策略 → 分层方案

**为什么值得做**：S21 聚宽分钟级回测年化 **101.52%**（夏普4.20）vs 本地日频仅 **40.00%**（夏普1.53）——收益差 2.5 倍、夏普差 2.7 倍，差异全部来自平台分钟级盘中止损/七星覆盖/日内择时（本地日频未移植）。分钟级不是锦上添花，而是策略收益的关键来源。

**关键事实（2026-10-10 实测）**：
| 数据源 | 分钟线历史深度 | 状态 |
|---|---|---|
| 腾讯 ifzq mkline | m1≈3天 / m5≈1月 / m15≈2.5月 / m60≈4月（上限800根） | ✅ 可用（免费、不封IP、HTTP） |
| 东财 push2his klt=5 | 最深 | ❌ 当前被风控（连接关闭） |
| mootdx TCP | — | ❌ 2026-09 起行情命令失效 + 海外超时 |
| 聚宽平台回测 | 全周期 | ⚠️ 通道已有（joinquant_backtest.py --frequency minute）但**需聚宽 Cookie（当前缺失）** |

**核心判断**：S21 的分钟级需求 = **「当日盘中执行时刻的分钟价」（13:10 调仓 + 日内 ATR/择时风控）**，而非长周期分钟回测。据此分层：

### 层1（推荐，近期做）：盘中实时信号层
- 新增 `tencent_client.py`（含 `tencent_mkline()` 已实测可用）
- 新增 `minute_signal.py`：盘中定时（13:10）拉取 S21 池分钟价 → 用「截至当前」价格重算 25日动量信号 + 日内 ATR 止损/趋势择时
- 与痛点2实盘桥接联动：盘中信号 → 大QMT 执行
- 收益：复现聚宽分钟级优势（盘中调仓 + 日内风控），腾讯分钟线历史深度完全够用
- 前置：痛点3的多源容错落地（稳定分钟价）

### 层2（长期）：分钟级回测验证层
- **路径A（推荐）**：聚宽平台分钟级回测（已有 `joinquant_backtest.py --frequency minute`）——用户在 Dashboard 登录聚宽后可用；受平台并行配额限制（2个）
- **路径B**：自建分钟数据积累——每日盘后从腾讯/东财拉全池分钟线落盘 parquet，长期积累后支持本地分钟回测（成本低，但需数月积累才有长周期样本）
- **路径C（不推荐）**：付费分钟源（tushare 历史分钟 2000元/年；JQData 2026-08-01 起禁海外 IP）——单策略不值得付费
- **本地引擎分钟级改造**：当前不推荐——免费源历史不够 + 引擎改造（t+0约束/成本模型/性能240倍数据量）成本高收益低；除非后续引入 QMT 行情（自带历史分钟）

### S21 分钟级逻辑还原映射
| 聚宽原逻辑 | 本地落地 |
|---|---|
| `run_daily(13:10 调仓)` | `minute_signal.py` 盘中 13:10 触发 |
| 分钟级 ATR 止损 | `minute_signal.py` 日内风控模块（腾讯分钟价） |
| 日内趋势择时 | `minute_signal.py` 日内结构判断 |
| 25日动量打分（日线） | 沿用日频 `wufu_momentum_rotation.py`（不变） |
| 长周期分钟回测 | 聚宽平台通道 / 自建分钟积累 |

## 落地路线图（建议）

> 每个 Phase 走 REQ + dev-workflow（brainstorming → TDD → code-review），涉 A 股数据走 `a-stock-data`。

| Phase | 内容 | 前置 | 工作量 | 收益 |
|---|---|---|---|---|
| **P0** | 实时行情多源容错（腾讯主+东财备+新浪兜底+缓存） | 无 | 1~2 天 | 根治单源不稳定，为 P1/P2 打底 |
| **P1** | 分钟级盘中信号（tencent_client + minute_signal + S21 分钟级还原） | P0 | 2~3 天 | 复现 S21 分钟级收益（101% vs 40%） |
| **P2** | 实盘通道（大 QMT 开通 + 信号桥接 + 风控） | P0（P1 可选） | 券商开通 ~1周 + 桥接 2~3 天 | 信号→实盘闭环 |
| P3（可选） | 分钟数据自积累 + 本地分钟回测引擎 | P0/P1 | 长期 | 摆脱平台依赖 |

**关键依赖**：
- P1 需要用户在 Dashboard 登录聚宽（层2路径A），或接受层2路径B/C 的取舍
- P2 需要用户开通券商 QMT 权限（客户经理白名单，~10万门槛）

**风险与缓解**：
| 风险 | 缓解 |
|---|---|
| 腾讯分钟线限流（单入口~600次） | 多 host 轮换（a-stock-data V3.7+ 已内置三入口） |
| 东财独有数据仍不稳 | 独有数据降级为"有就更好，没有不阻塞" |
| 分钟级盘中信号依赖盘中稳定行情 | P0 多源容错先行 |
| 实盘合规（2026 外接新规） | 走大 QMT 内置沙箱 + 报备，不碰 easytrader |
| 海外网络（JQData 禁海外、mootdx 失效） | 腾讯 HTTP 为主，不依赖 TCP/平台数据 |
