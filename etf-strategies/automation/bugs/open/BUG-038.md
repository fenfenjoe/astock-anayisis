# BUG-038: agent/__main__._ensure_cloud() 在 import agent.db 之后执行 — USE_CLOUD 已在导入时固化，「强制 AGENT_DB_BACKEND=cloud」永远无效

- **组件**: agent（agent/__main__.py 启动入口 + agent/db.py 后端选择）
- **严重程度**: MEDIUM
- **违反的正确性定义**: 不适用（导入时序/配置生效性；与 BUG-025 同类 — 模块级常量在导入时固化）
- **状态**: MANUAL_REVIEW
- **auto_fix_eligible**: false
  - 判定理由：根因是「模块级常量 `USE_CLOUD` 在 import 时固化」+ `_ensure_cloud()` 调用时机晚于 import。修复需设计决策（把 `_ensure_cloud()` 提到 import 之前 / 改为动态 `use_cloud()` 函数 / 在 db.py 内做缺省 fallback），与 BUG-025（cloud_db._ENABLED 导入时序，判 false）同类；按「不确定时默认 false（安全原则）」标记人工
- **发现时间**: 2026-09-10T12:30+08:00
- **发现方式**: 每日代码巡检 (bug_inspect_code) 第二步静态分析 — agent 启动链路导入顺序核对
- **预期行为**: 未显式配置 `AGENT_DB_BACKEND` 时，Agent 进程应如 `_ensure_cloud()` 注释与日志所述**强制走云库**（`USE_CLOUD=True`），保证与小满 Dashboard/云权威库一致
- **实际行为**: `agent/db.py:32` 的 `USE_CLOUD = os.environ.get("AGENT_DB_BACKEND", "").lower() == "cloud"` 是**模块导入时求值的常量**；而 `agent/__main__.py` 的执行顺序是：
  ```
  L15-17  load_env_file()                    # 载入 .env（若存在）
  L21     from agent import db as agent_db    # ← 此刻 db.py 已求值 USE_CLOUD
  L33-35  main() → _ensure_cloud()            # ← 此刻才 os.environ["AGENT_DB_BACKEND"]="cloud"
  ```
  `_ensure_cloud()` 在 `main()` 内、即 import 之后才写入环境变量 → 对已固化的 `USE_CLOUD` **没有任何影响**。实测：清空 `AGENT_DB_BACKEND` 后导入 `agent.db` → `USE_CLOUD=False`，随后即使按 `_ensure_cloud()` 逻辑置 env="cloud"，`USE_CLOUD` 仍为 False。
  - 当前生产之所以正常，仅因仓库 `.env` 显式写了 `AGENT_DB_BACKEND=cloud`（`load_env_file()` 在 import 前载入）；
  - 一旦 `.env` 缺失该键（新环境/CI/换机），日志会打印「强制 AGENT_DB_BACKEND=cloud（Agent 独立运行不再支持 file 模式）」，但进程实际仍跑 **file 后端**，静默写入本地 `agent.db`，而 Dashboard 读云库 → 数据分叉（agent 的活动/会话/提示用户看不到）。
- **复现步骤**:
  1. `cd etf-strategies && python -c "import os; os.environ.pop('AGENT_DB_BACKEND', None); from agent import db; print('USE_CLOUD =', db.USE_CLOUD); print('env =', repr(os.environ.get('AGENT_DB_BACKEND')))"` → `USE_CLOUD = False` / `env = None`
  2. `grep -n "AGENT_DB_BACKEND" agent/__main__.py agent/db.py` → `__main__.py:26-27`（设置）晚于 `__main__.py:21`（导入）；`db.py:32`（固化）
  3. 对照：`grep -n "AGENT_DB_BACKEND" .env` → `AGENT_DB_BACKEND=cloud`（生产靠 .env 兜住，故未暴露）
- **受影响文件**:
  - `etf-strategies/agent/__main__.py:14-35`（load_env → import db → main/_ensure_cloud 顺序）
  - `etf-strategies/agent/db.py:32-49`（`USE_CLOUD` 模块级常量 + 导入 cloud_db 分支）
  - 相关：`etf-strategies/.env`（AGENT_DB_BACKEND=cloud，掩盖了该缺陷）
- **潜在影响**: `.env` 缺键的环境下，Agent 进程静默降级为本地 file 后端，与 Dashboard/云权威库数据分叉；日志却声称已强制 cloud，误导排查。对回测/信号无影响。属「配置项生效性」缺陷，与 BUG-025 同族（导入时序固化）。
- **建议修复**: 三选一：
  (a) 把后端兜底逻辑提到 import 之前（`agent/__main__.py` 顶层、`from agent import db` 之前完成 `os.environ.setdefault("AGENT_DB_BACKEND", "cloud")`），并同步调整 `_ensure_cloud()`；
  (b) 将 `agent/db.py` 的 `USE_CLOUD` 改为动态函数（`def use_cloud(): return os.environ.get(...) == "cloud"`）或惰性求值，消除导入时序依赖；
  (c) 在 `agent/db.py` 内直接做缺省兜底（未配置即视为 cloud），并去掉 `__main__._ensure_cloud()` 的误导日志。
  修复后建议加一条测试：清空 `AGENT_DB_BACKEND` 导入 `agent` 后断言后端为 cloud（防复发）。
