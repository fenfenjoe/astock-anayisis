- **组件**: agent（agent/db.py — 工单表 DDL 缺失）
- **严重程度**: MEDIUM
- **违反的正确性定义**: 不适用（schema 完整性；agent 层不在 correctness_definitions.yaml 覆盖范围）
- **状态**: FIXED
- **auto_fix_eligible**: true
  - 判定理由：`agent/db.py` 的本地 `SCHEMA`（11 张表）漏建 `tickets` 表，而 `ticket_upsert/ticket_list/ticket_count/ticket_get` 的 file 分支直写 `tickets`。修复是从 `scripts/cloud_schema.sql:154-168` 机械移植等价 DDL 到本地 `SCHEMA`（TEXT 主键 + 12 列 + status 索引），属确定性配置/建表修复，不涉及金融计算/策略逻辑
- **发现时间**: 2026-09-10T12:30+08:00
- **发现方式**: 每日代码巡检 (bug_inspect_code) 第二步静态分析 + 运行时验证（新增未提交模块 `agent/core/scheduler_agent.py` / `dashboard/api_tickets.py` 依赖 `ticket_*`）
- **预期行为**: file 后端（`AGENT_DB_BACKEND != cloud`，含**全部 pytest 测试进程**——`tests/conftest.py:24` 强制 `AGENT_DB_BACKEND=file`）下，`init_db()` 应建出 `tickets` 表，`ticket_upsert/ticket_list/ticket_count/ticket_get` 可正常读写
- **实际行为**: 本地 `SCHEMA` 只建 11 张表（`agent_sessions / agent_messages / agent_articles / agent_opinions / agent_knowledge / agent_metadata / agent_sources / agent_activities / platform_cookies / platform_reachability / agent_notices`），**无 `tickets`**；四个 ticket 函数的 file 分支全部 `sqlite3.OperationalError: no such table: tickets`：
  - `agent/db.py:1357` `INSERT OR REPLACE INTO tickets ...`（`ticket_upsert`）
  - `agent/db.py:1404` `SELECT {_TICKET_COLS} FROM tickets`（`ticket_list`）
  - `agent/db.py:1428` `SELECT COUNT(*) FROM tickets`（`ticket_count`）
  - `agent/db.py:1440` `SELECT ... FROM tickets WHERE id=?`（`ticket_get`）
  - 云表 DDL 已存在于 `scripts/cloud_schema.sql:154-168`，但未同步回本地 `SCHEMA`
- **复现步骤**:
  1. 运行 `_verify_tickets.py`（临时脚本，已删）：
     ```python
     import os, sqlite3, tempfile, pathlib
     os.environ['AGENT_DB_BACKEND'] = 'file'
     from agent import db
     p = pathlib.Path(tempfile.mkdtemp()) / 'agent.db'
     db.init_db(p)
     con = sqlite3.connect(str(p))
     print([r[0] for r in con.execute("SELECT name FROM sqlite_master WHERE type='table'")])
     db.ticket_count()
     ```
  2. 输出：表清单无 `tickets`；`ticket_count` → `OperationalError no such table: tickets`（`ticket_list/ticket_get/ticket_upsert` 同）
- **受影响文件**:
  - `etf-strategies/agent/db.py:66-176`（本地 `SCHEMA`，缺 `tickets`）
  - `etf-strategies/agent/db.py:1349-1442`（四个 ticket 函数 file 分支）
  - `etf-strategies/scripts/cloud_schema.sql:154-168`（云表 DDL，可作移植来源）
  - 消费方：`etf-strategies/dashboard/api_tickets.py:37-64`（`/api/tickets` 列表/详情 → 500）、`etf-strategies/agent/core/scheduler_agent.py:374-378`（建工单，被 `except: pass` 静默吞掉）
- **潜在影响**:
  1. 全部 pytest 进程（conftest 强制 file 后端）中，工单功能不可用；因**无任何 ticket 测试**，该缺陷不会被测试门禁发现；
  2. 本地/无 `.env` 环境启动 Dashboard 后打开"工单"页 → `/api/tickets` 500（`ticket_count` 抛异常，无兜底）；
  3. `scheduler_agent._upsert_ticket` 的 `except: pass` 使失败静默 → 调度失败工单既建不出也无日志（与 BUG-036 叠加，失败感知链路整体失效）。
  4. 生产 cloud 后端不受影响（云表已建）。
- **建议修复**: 在 `agent/db.py` 的 `SCHEMA` 末尾补建本地 `tickets` 表（字段与 `cloud_schema.sql` 对齐，SQLite 方言）：
  ```sql
  CREATE TABLE IF NOT EXISTS tickets (
      id          TEXT PRIMARY KEY,
      kind        TEXT NOT NULL,
      title       TEXT NOT NULL,
      description TEXT,
      severity    TEXT NOT NULL DEFAULT 'p2',
      status      TEXT NOT NULL DEFAULT 'open',
      source_task TEXT,
      assignee    TEXT DEFAULT 'xiaoman',
      created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
      updated_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
      result      TEXT,
      log_entries TEXT
  );
  CREATE INDEX IF NOT EXISTS idx_tickets_status ON tickets(status);
  ```
  并补 `tests/test_agent_db.py` 的 ticket CRUD 测试（file 后端）以防复发。
