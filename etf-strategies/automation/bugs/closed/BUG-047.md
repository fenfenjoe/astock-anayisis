# BUG-047: test_cloud_db.py 单元测试未适配 pgdirect 后端迁移 — `_mock_cloud` fixture 只 mock PostgREST 路径，pgdirect 下误连真实云库（10 项 FAILED + 触发云端认证限流）

- **组件**: tests（tests/test_cloud_db.py fixture 隔离缺陷；根因在 cloud_db.py 双后端路由）
- **严重程度**: HIGH
- **违反的正确性定义**: 不适用（测试隔离缺陷；与 BUG-025/BUG-035/BUG-042 同族 — 测试未适配后端迁移/重构）
- **状态**: FIXED
- **auto_fix_eligible**: true
  - 判定理由：属"测试缺失/隔离缺陷"类机械性确定性修复 —— 在 `_mock_cloud` fixture 中强制 `cloud_db._BACKEND = "postgrest"`（或等价地强制 `_PG_ENABLED = False`）即可让单元测试稳定走 mocked `_req` 路径，修复方向唯一且不改变被测代码行为
- **发现时间**: 2026-09-22T12:26+08:00
- **发现方式**: 每日代码巡检 (bug_inspect_code) 第四步全量测试 — tests/test_cloud_db.py 10 项 FAILED（覆盖率+verbose 两次全量运行均复现）
- **预期行为**: `tests/test_cloud_db.py` 的单元测试（`test_select_passes_filters` 等 10 项，标记为 PostgREST 语义测试）应通过 `_mock_cloud` autouse fixture 隔离网络，**永不连接真实云库**；`test_cloud_db_pg.py`（pgdirect 专项测试）负责 pgdirect 路径并 mock `_pg_connect`。全量测试套件在配置了 `CLOUD_DB_BACKEND=pgdirect` 的仓库环境下应保持 660/660 通过
- **实际行为**: 2026-09-17 云数据库迁移到 AIDAP PostgreSQL 引擎后，`.env` 配置 `CLOUD_DB_BACKEND=pgdirect` + 真实 PG 凭据（PGHOST/PGUSER 等）；`tests/conftest.py` 只清空 `SUPABASE_URL`/`SUPABASE_SERVICE_KEY`（PostgREST 凭据），**未处理 `CLOUD_DB_BACKEND`/`PG*`**。于是测试进程导入 `cloud_db` 时 `_BACKEND="pgdirect"`、`_PG_ENABLED=True`：
  - `test_cloud_db.py::_mock_cloud` fixture（L17-24）只 mock `cloud_db._ENABLED=True` 和 `cloud_db._req`（PostgREST 路径），**未 mock `_BACKEND`/`_PG_ENABLED`/`_pg_connect`**；
  - `cloud_db.select()/insert()/update()/delete()/upsert()` 在 `_BACKEND=="pgdirect"` 时（L541-545 等）路由到 `_pg_select`/`_pg_run` → `_pg_connect()` → **真实 pg8000 连接公网 AIDAP Postgres**；
  - 结果：10 项单元测试全部尝试真实连接并抛 `pg8000.dbapi.ProgrammingError: password authentication failed for user 'user_admin'`（密码过期/工作区变更），最后一例甚至报 `Too many authentication failures. Please try again in 57s` —— 测试套件对真实云端反复认证失败，**触发云端防爆破限流**（运维污染 + 测试时长/稳定性恶化）。
  - 对比：`test_cloud_db_pg.py` 的 `_pg_backend` fixture（L66-80）正确 mock 了 `_pg_connect` 与 `_BACKEND`，全部 33 项通过；`test_agent_db_cloud.py`/`test_dashboard_db_cloud.py` 用 skipif 正确跳过（各 8/6 项）。唯独 `test_cloud_db.py` 的 fixture 停留在 PostgREST 时代的 mock 面。
- **复现步骤**:
  1. `cd etf-strategies && python -m pytest tests/test_cloud_db.py::test_select_passes_filters -v --tb=short` → FAILED，`CloudDBError: pg select agent_sessions: password authentication failed for user 'user_admin'`
  2. `python -m pytest tests/ -q --cov=backtest --cov-report=term` → 10 failed, 660 passed, 17 skipped（全部失败在 test_cloud_db.py）
  3. 模拟验证：`python -c "import cloud_db; print(cloud_db._BACKEND, cloud_db._PG_ENABLED)"`（conftest 未覆盖时）→ `pgdirect True`
- **受影响文件**:
  - `etf-strategies/tests/test_cloud_db.py:17-24`（`_mock_cloud` fixture 未强制 `_BACKEND="postgrest"`/未 mock pgdirect 路径）

  - 相关：`etf-strategies/cloud_db.py:39,50-55,541-545`（`_BACKEND` 模块级常量 + pgdirect 路由，行为正确，非缺陷源）
- **潜在影响**: 全量测试套件在当前仓库环境 10 项稳定 FAILED，CI/巡检红色；更严重的是**测试进程反复对真实云端数据库发起认证连接**，可触发云库防爆破限流（实测 `Too many authentication failures`），有影响生产服务连接的风险（同 IP 被临时封锁 57s+）；`test_select_disabled_returns_empty` 等语义被破坏（期望空结果却抛异常）。对回测/策略逻辑无影响。
- **建议修复**: 二选一（推荐 a）：
  (a) `tests/test_cloud_db.py::_mock_cloud` fixture 增加 `monkeypatch.setattr(cloud_db, "_BACKEND", "postgrest")`（并可选 `monkeypatch.setattr(cloud_db, "_PG_ENABLED", False)`），使 PostgREST 单元测试始终走 mocked `_req` 路径；已实测该修复后 `test_select_passes_filters` 通过（走 `_req` 返回 mock 行）；
  (b) 或 `tests/conftest.py` 在测试隔离区补 `os.environ["CLOUD_DB_BACKEND"] = "postgrest"`（与清空 SUPABASE 凭据同理，早于 .env 生效），全局兜底。
  修复后全量重跑 `python -m pytest tests/ -q` 应 660/660（或 670/670 含 skipped 计数不变）通过；建议补一条回归断言（测试进程内 `cloud_db._BACKEND == "postgrest"` 且无真实连接尝试）。
