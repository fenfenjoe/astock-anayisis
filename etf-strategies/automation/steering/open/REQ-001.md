## 需求描述

**背景**：`backtest/data.py get_kline(refresh=True)` 在**交易时段**执行时会把当日 partial bar（盘中快照）写入 parquet 缓存作为"最后日K"；收盘后（15:00+）与次日盘中前**无兜底刷新任务**把该 partial bar 补全为完整收盘 bar。该缺陷已连续 3 次引发 BUG：

- BUG-016（2026-09-01）：18 个缓存 08-31 日K 为盘中快照，跨源价差最大 -3.59%
- BUG-019（2026-09-03）：11/13 活跃 ETF 缓存 09-02 日K 为盘中快照（BUG-016 根因复发）
- BUG-020（2026-09-03）：5 个非活跃标的缓存过期（BUG-004→BUG-008→第三次复发）— 非活跃/持仓标的缺少固定刷新入口

**已知的触发路径**（巡检证据）：
1. 交易时段任意 `refresh=True` / `refresh=False`（缓存覆盖不足触发 API）调用 → 写入当日 partial bar
2. 收盘后无任务补全 → partial bar 永久成为"最后日K"
3. 次日信号/回测 `refresh=False` 读缓存：缓存覆盖范围内（end=今日≤缓存最后 bar）→ **零 API 调用**，直接用 stale partial 快照计算 → 信号失真且无任何报错

**附加缺陷**（BUG-016 修复记录指出）：`get_kline` 在 API 异常时**静默回退读缓存**（无 WARN、无报错），掩盖了长区间重拉失败（RemoteDisconnected），使缓存停留在错误状态而不易察觉。

## 期望结果

1. **收盘后强制补全**：新增/调整数据刷新调度或 `get_kline` 逻辑——在非交易时段（15:00 后、次日 09:30 前）的刷新把当日 bar 补全为完整收盘 bar（`eastmoney_kline(code, start=当日, end=当日)` 覆盖 partial）；交易时段内不再把"最后一根 bar"视为完整日K 写死
2. **非活跃/持仓标的定期刷新**：持仓/打新底仓等非活跃标的进入固定刷新范围（与活跃 ETF 同一 freshness 巡检/刷新节奏），杜绝 BUG-020 式反复过期（复发 3 次）
3. **显式失败提示**：`get_kline` API 异常回退缓存时输出 WARN（当前静默回退掩盖重拉失败）
4. **可验证**：新增测试覆盖「盘中 partial bar 不被当作完整日K 持久化」「收盘后刷新补全当日 bar」「API 失败回退时打印 WARN」三条路径
